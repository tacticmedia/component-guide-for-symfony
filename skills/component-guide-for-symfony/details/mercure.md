# Mercure (`symfony/mercure`, `symfony/mercure-bundle`): details

**Applies to:** symfony/mercure 0.9, MercureBundle 0.6, Symfony UX 3.5

## Key features and concepts

- **Hub and topics:** The hub is a separate server that holds the SSE connections of the subscribers. The application publishes an update to one or more topics, and the hub sends it to each subscriber of a matching topic. A topic is an IRI, for example `https://example.com/books/1`, and this URL does not have to exist. Entry point: `Symfony\Component\Mercure\Update`.
- **Publish an update:** Autowire `HubInterface` and call `$hub->publish(new Update($topic, $data))`. The call returns the ID of the update. The data can have any format; the docs recommend JSON-LD, Atom, HTML or XML. The other `Update` arguments are `$private`, `$id`, `$type` and `$retry`. If the request to the hub fails, `Hub::publish()` throws a `RuntimeException`. Each entry under `mercure.hubs` is the service `mercure.hub.<name>`. `HubInterface` gets the hub in `mercure.default_hub`, or else the first hub. For another hub, add `#[Target('<name>')]` to the `HubInterface` argument, or call `HubRegistry::getHub('<name>')`. Symfony 8.1 deprecates a match on the argument name alone (`HubInterface $<name>Hub`), except in controller actions. Entry point: `Symfony\Component\Mercure\HubInterface`.
- **Subscribe in the browser:** The Twig function `mercure(topics)` returns the public URL of the hub with one query parameter for each topic. Give this URL to `new EventSource(...)`, with `|escape('js')` in a `<script>` block. Under protocol 1.0, the parameter is `match`, and a matcher map such as `{urlpattern: ['https://example.com/books/:id']}` gives `match_urlpattern`. Under protocol 0.x, the parameter is `topic`. The option `hub` selects a hub, and `lastEventId` asks for the updates after this event ID. `EventSource` does not tell which topic sent a message. If you need the topic, put it in the data. Entry point: Twig function `mercure()`.
- **Private updates:** `new Update($topic, $data, true)` makes a private update. The hub sends it only to subscribers with a JWT that grants a matching topic. For a browser, send this JWT in a cookie. For other clients, send an `Authorization: Bearer` header. In Twig, `mercure(topic, {subscribe: topic})` also sets the cookie; then create the `EventSource` with `{withCredentials: true}`. The other options are `publish`, `grants`, `payload` (only with `subscribe`) and `additionalClaims`. Entry point: Twig function `mercure()`.
- **Authorization cookie:** `Authorization::setCookie($request, $grants)` sets the cookie from PHP code, and `clearCookie($request)` removes it. `SetCookieSubscriber` adds the cookie to the main response. For each hub, set the cookie only once in a request. A second call, or `mercure()` with options plus `setCookie()`, throws a `RuntimeException`. The application and the hub must use the same second-level domain. The cookie is `HttpOnly` and `SameSite=Strict`, and it is `Secure` for an HTTPS hub URL. The default name is `__Secure-mercure_access_token` for protocol 1.0, `mercure_access_token` for 1.0 in debug mode, and `mercureAuthorization` for 0.x. A `__Secure-` name with an `http://` hub URL throws an `InvalidArgumentException`; set `cookie_name` for plain HTTP. The cookie lifetime is `mercure.default_cookie_lifetime`, or else the session cookie lifetime. If the cookie is a session cookie, its JWT expires after one hour. Entry point: `Symfony\Component\Mercure\Authorization`.
- **JWT to publish:** The hub accepts an update only with a JWT that it can verify. `jwt.secret` makes the bundle sign the JWTs with `LcobucciFactory` and the algorithm `hmac.sha256` (default). Use a key of 256 bits or more, and give the hub the same key (`MERCURE_JWT_SECRET` in the Flex recipe). `jwt.publish` and `jwt.subscribe` list the topics in the publisher JWT. As alternatives, `jwt.value` is a fixed JWT, `jwt.provider` is a `TokenProviderInterface` service, and `jwt.factory` is a `TokenFactoryInterface` service. Do not set `jwt.value` and `jwt.provider` together. If the publisher and subscriber JWTs need different keys, use `publisher` and `subscriber` instead of `jwt`. `jwt.jwks_uri` with `jwt.key_id` gets the key from a JWK Set through `WebTokenFactory`; this needs `web-token/jwt-library` and protocol 1.0. Entry point: `mercure.hubs.<name>.jwt`.
- **Protocol 1.0 by default:** MercureBundle 0.6.0 sets `protocol_version: '1.0'`. Protocol 1.0 uses RFC 9068 access tokens, and the component requires the claims `iss`, `aud`, `sub` and `client_id`. If you use `jwt.secret` or `jwt.jwks_uri`, set `iss`, `sub` and `client_id` in `jwt.claims`. Without them, the container does not compile. The `aud` claim defaults to `public_url`, or else `url`. The `iss` value must match a trusted issuer of the hub. In the official image, this is `MERCURE_TRUSTED_ISSUERS`, with the default `https://localhost`. Since 0.6.1, the publisher token that the bundle signs also lists `url` in `aud`. So a hub that the application reaches through an internal `url` accepts the publications without `resource_identifier`. For a 0.x hub, set `protocol_version: '0.x'`. Entry point: `mercure.hubs.<name>.protocol_version`.
- **Grants and topic matchers:** A `Grant` holds actions (`Grant::ACTION_SUBSCRIBE`, `Grant::ACTION_PUBLISH`), topics and an optional subscriber `payload`. `Authorization::setCookie()`, the `grants` option of `mercure()`, `FactoryTokenProvider` and `TokenFactoryInterface::create($grants, $additionalClaims)` take grants. Topics are a flat list of exact topics or a map from a matcher type to patterns, for example `['urlpattern' => ['https://example.com/books/:id']]`. Protocol 1.0 uses URL Patterns (`:id`), not URI Templates (`{id}`). Matcher types other than `exact` need protocol 1.0. Entry point: `Symfony\Component\Mercure\Jwt\Grant`.
- **Discovery:** `Discovery::addLink($request)` adds the public URL of the hub as a link with `rel="mercure"`. The WebLink listener writes it to the response header, for example `Link: <https://hub.example.com/.well-known/mercure>; rel="mercure"`. A client reads this header and subscribes to the hub. `addLink()` does nothing for a CORS preflight request. Entry point: `Symfony\Component\Mercure\Discovery`.
- **Hub server:** In production, install a hub yourself. The docs name the official open-source hub (AGPL, based on Caddy). It comes as a static binary from Mercure.rocks, a `dunglas/mercure` Docker image, a Helm chart and a managed service. For development, the Flex recipe can add a `mercure` service to `compose.yaml` (or to an existing `docker-compose.yml`). For a `dunglas/mercure` container, the Symfony CLI sets `MERCURE_URL` and `MERCURE_PUBLIC_URL`. Start the local web server with `--no-tls`, or with `--proxy-mercure` to serve the hub on the origin of the application. Symfony Docker and the API Platform distribution set the variables for you. Entry point: `MERCURE_URL`, `MERCURE_PUBLIC_URL`, `MERCURE_JWT_SECRET`.
- **FrankenPHP built-in hub:** If `url` is empty, the hub service is a `FrankenPhpHub`, which publishes with the FrankenPHP function `mercure_publish()`. Then you must set `public_url`. Outside a FrankenPHP request, for example in a console command or a Messenger worker, this function does not exist. The hub creation then throws a `LogicException`. Entry point: `Symfony\Component\Mercure\FrankenPhpHub`.
- **Testing:** In a unit test, create `new MockHub($url, new StaticTokenProvider('token'), $publisher)`. `MockHub::publish()` calls the `$publisher` callable with the `Update` and returns its result. Import `Symfony\Component\Mercure\Jwt\StaticTokenProvider`; the docs write `JWT`, which is wrong. In a functional test, replace the service `mercure.hub.<name>` with a class that implements the five methods of `HubInterface`. To test real-time pages with several browsers, use Panther `createAdditionalPantherClient()`. Entry point: `Symfony\Component\Mercure\MockHub`.
- **Messenger:** The bundle registers an `UpdateHandler` for each hub. Dispatch an `Update` on the message bus to publish it, synchronously or through a transport. The hub option `bus` selects the bus; without it, Messenger registers the handler on all buses. If several hubs share a bus, the dispatched `Update` goes to each of these hubs. The docs discourage async dispatch, because most hubs already handle publications asynchronously. Entry point: `Symfony\Component\Mercure\Messenger\UpdateHandler`.
- **Profiler panel:** In debug mode with Stopwatch installed, `TraceableHub` decorates each hub. The "Mercure" panel of the profiler shows the time, memory, topics, data, private flag, ID, type and retry of each update. To get the profiler, install `symfony/debug-pack`. Entry point: `data_collector.mercure`.
- **Turbo Streams (UX Turbo):** If `symfony/ux-turbo` is installed, each hub is a Turbo transport with the name of the hub. `#[Broadcast]` on a Doctrine entity publishes Turbo Stream HTML when the entity changes. `turbo_stream_from()` and `<twig:Turbo:Stream:From>` subscribe the page through `mercure()`. You can also publish `new Update('tasks', $this->renderView('task/stream/new.html.twig', ['task' => $task]))`, as in the UX Turbo docs. UX Turbo 3.5 targets protocol 0.x (see "Status"). Entry point: `Symfony\UX\Turbo\Attribute\Broadcast`.

## Entry points

- Installation: `composer require mercure` (Flex alias of `symfony/mercure-bundle`). The recipe adds `config/packages/mercure.yaml` and the variables `MERCURE_URL`, `MERCURE_PUBLIC_URL` and `MERCURE_JWT_SECRET`.
- Autowire: `Symfony\Component\Mercure\HubInterface` (another hub: `#[Target('<name>')] HubInterface $hub`, with `Symfony\Component\DependencyInjection\Attribute\Target`), `Symfony\Component\Mercure\RemoteHubInterface` (only hubs with `url`; adds `getUrl()`), `Symfony\Component\Mercure\HubRegistry`, `Symfony\Component\Mercure\Authorization`, `Symfony\Component\Mercure\Discovery`.
- Autowire the JWT services of a hub: `#[Target('<name>')] Symfony\Component\Mercure\Jwt\TokenFactoryInterface $factory` and `#[Target('<name>')] Symfony\Component\Mercure\Jwt\TokenProviderInterface $provider`.
- Value objects: `Symfony\Component\Mercure\Update`, `Symfony\Component\Mercure\Jwt\Grant`, `Symfony\Component\Mercure\ProtocolVersion` (`V1` = `'1.0'`, `Legacy` = `'0.x'`).
- JWT classes: `Symfony\Component\Mercure\Jwt\StaticTokenProvider`, `FactoryTokenProvider`, `CallableTokenProvider`, `LcobucciFactory`, `WebTokenFactory` (`fromSecret()`, `fromJwksUri()`), `DefaultClaimsTokenFactory`.
- Without FrameworkBundle: the hub classes `Symfony\Component\Mercure\Hub`, `FrankenPhpHub`, `MockHub`.
- Config of each hub (`mercure.hubs.<name>`): `url`, `public_url`, `jwt` (`secret`, `passphrase`, `algorithm`, `jwks_uri`, `key_id`, `claims`, `publish`, `subscribe`, `value`, `provider`, `factory`), `publisher` (the same signing keys, `value`, `provider`, `factory`, `topics`), `subscriber` (the signing keys, `factory`), `protocol_version`, `cookie_name`, `bus`, `http_client`.
- Global config: `mercure.default_hub`, `mercure.default_cookie_lifetime`. Deprecated since 0.3: `mercure.hubs.<name>.jwt_provider` and `mercure.enable_profiler`.
- Service IDs and tags: `mercure.hub.<name>` (tag `mercure.hub`), `mercure.hub.<name>.message_handler`, `data_collector.mercure`.
- Twig: `mercure(topics = null, options = {})`. Without topics, it returns the URL of the hub, for example to publish from JavaScript. Options: `hub`, `subscribe`, `publish`, `grants`, `payload`, `additionalClaims`, `lastEventId`.
- Messenger: dispatch an `Update` with `Symfony\Component\Messenger\MessageBusInterface`.
- Tests: `Symfony\Component\Mercure\MockHub`; Panther `PantherTestCase::createAdditionalPantherClient()`.
- Symfony CLI: `symfony server:start --proxy-mercure` (or `proxy_mercure: true` under `http` in `.symfony.local.yaml`) and `--no-tls`.
- The two packages have no console commands and no PHP attributes.

## Symbiotic packages

- [Symfony UX Turbo](../packages/ux-turbo.md): Each Mercure hub is a Turbo transport, `#[Broadcast]` publishes Turbo Stream HTML, and `turbo_stream_from()` subscribes through `mercure()`. UX Turbo 3.5 targets protocol 0.x, so set `protocol_version: '0.x'` on the hub.
- [Symfony UX Notify](../packages/ux-notify.md): It shows Notifier chat messages from a Mercure hub as native browser notifications. UX Notify requires MercureBundle `^0.3.4|^0.4.1`, so it does not install with MercureBundle 0.5 or 0.6.
- [Notifier](../packages/notifier.md): The `symfony/mercure-notifier` chat transport (DSN `mercure://HUB_ID?topic=TOPIC`) publishes chat messages to a MercureBundle hub. Its version 8.1 allows `symfony/mercure` only up to `^0.8`, so with MercureBundle 0.6, Composer installs `symfony/mercure` 0.8, not 0.9.
- [Messenger](../packages/messenger.md): MercureBundle registers a handler that publishes each `Update` that you dispatch on the bus; the docs discourage async dispatch.
- [HttpFoundation](../packages/http-foundation.md): `EventStreamResponse` sends SSE directly from a controller. Use it for a few connections, and use Mercure for many clients, authorization or the retrieval of lost updates.
- [WebLink](../packages/web-link.md): `Discovery::addLink()` adds a `rel="mercure"` link, and the WebLink listener writes the `Link` header.
- [HttpClient](../packages/http-client.md): `Hub` posts each update with HttpClient. The hub option `http_client` selects another client, for example a scoped client with a short timeout.
- [TwigBundle](../packages/twig-bundle.md): If Twig is installed, MercureBundle registers the `mercure()` Twig function.
- [WebProfilerBundle](../packages/web-profiler-bundle.md): In debug mode, the profiler shows the "Mercure" panel with the published updates.
- [Stopwatch](../packages/stopwatch.md): MercureBundle adds the profiler panel and `TraceableHub` only if Stopwatch is installed.
- [Panther](../packages/panther.md): `createAdditionalPantherClient()` opens isolated browsers to test pages that receive Mercure updates.
- [Abandoned Symfony UX packages](../packages/ux-abandoned.md): `symfony/ux-turbo-mercure` (last version 2.6.0) is abandoned; UX Turbo 2.6.1 took over its code.
- [StimulusBundle](../packages/stimulus-bundle.md): give the hub URL from `mercure()` to a Stimulus controller as a value with `stimulus_controller()`.

## Changed in symfony/mercure 0.8 to 0.9 and MercureBundle 0.5 to 0.6

- Protocol 1.0 is the default (symfony/mercure 0.9, MercureBundle 0.6). `mercure()` writes `match=`, not `topic=`. The JWT has `authorization_details`, not the `mercure` claim, and the cookie is `__Secure-mercure_access_token`, not `mercureAuthorization`. For a 0.x hub, set `protocol_version: '0.x'` or pass `ProtocolVersion::Legacy`.
- A protocol 1.0 hub with `jwt.secret` or `jwt.jwks_uri` needs `jwt.claims` with `iss`, `sub` and `client_id` (MercureBundle 0.5 added `jwt.claims`). Without them, the container does not compile.
- `TokenFactoryInterface::create($subscribe, $publish, $additionalClaims)` -> `create($grants, $additionalClaims)` with `Grant` objects (0.8). With the old arguments, the factories throw an `InvalidArgumentException`.
- `new FactoryTokenProvider($factory, publish: ['*'])` -> `new FactoryTokenProvider($factory, [new Grant([Grant::ACTION_PUBLISH], ['*'])])` (0.8). The component README shows the old call.
- `Authorization::setCookie($request, $subscribe, $publish)` -> `setCookie($request, $grants)` (0.8). The `$publish` argument and `null` for `$grants` are deprecated.
- MercureBundle 0.6 removed the `Publisher`, `PublisherInterface`, `TraceablePublisher` and `StaticJwtProvider` services. Use `HubInterface`, `TraceableHub` and `StaticTokenProvider`. The docs text names a "Publisher service".
- MercureBundle 0.6: an empty `url` selects the FrankenPHP built-in hub at runtime. New hub options: `http_client`, `publisher` and `subscriber`. `RemoteHubInterface` is autowirable.
- MercureBundle 0.5 added the hub options `protocol_version`, `cookie_name`, `jwt.jwks_uri` and `jwt.key_id`. The `jwt.algorithm` default is now `hmac.sha256` with `jwt.secret` and `HS256` with `jwt.jwks_uri`.

## Status

- Both packages are 0.x: symfony/mercure 0.9 and MercureBundle 0.6. Minor versions break backward compatibility, for example symfony/mercure 0.8.0 and MercureBundle 0.6.0. `HubInterface`, `Hub`, `Update` and the JWT interfaces have the `@experimental` tag.
- The docs page, the component README, the Flex recipe (0.4, the latest) and the UX Turbo 3.5 docs show protocol 0.x examples. With the MercureBundle 0.6 defaults, the recipe config (`jwt.secret` without `jwt.claims`) does not compile. Add `jwt.claims` with `iss`, `sub` and `client_id`, or set `protocol_version: '0.x'`.
- The recipe Docker service uses `dunglas/mercure` without a tag, which is the latest 1.x hub. The service runs `/etc/caddy/dev.Caddyfile` and checks `/healthz`, but hub 1.x removed both. For a 0.x hub, use the image `dunglas/mercure:v0` (0.24.2, the last 0.x release). For a 1.x development hub, remove `command` and `healthcheck`, and add `playground` to `MERCURE_EXTRA_DIRECTIVES`. Never enable `playground` in production. In hub 1.x, the `debugger` directive replaces `ui`, and the debug UI moved from `/.well-known/mercure/ui/` (the path in the docs) to `/.well-known/mercure/debug/`.
- UX Turbo 3.5 targets protocol 0.x. A subscription to all entities of a class uses a URI Template (`{id}`), and `turbo_stream_listen()` sends `topic=`. Under protocol 1.0, `mercure()` sends this template as an exact `match` parameter, so the subscription gets no updates. With UX Turbo 3.5, set `protocol_version: '0.x'` on each hub. Then use a 0.x hub, or add `protocol_version_compatibility 8` to a 1.x hub. The official 1.x binaries and images have the build tags that this mode needs.
- UX Notify does not install with MercureBundle 0.5 or 0.6. `symfony/mercure-notifier` 8.1 keeps `symfony/mercure` at 0.8 or lower. With the notifier bridge and MercureBundle 0.6, Composer installs `symfony/mercure` 0.8, not 0.9.
