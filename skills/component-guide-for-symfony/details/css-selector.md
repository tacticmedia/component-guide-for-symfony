# CssSelector (`symfony/css-selector`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **Converter:** `toXPath()` returns the XPath expression for a CSS selector as a string. It does not load or query a document. Give the expression to `DOMXPath::query()`, `SimpleXMLElement::xpath()` or `Crawler::filterXPath()`. The second argument sets the prefix of each expression, by default `descendant-or-self::`. A selector list such as `h1, h2` becomes an XPath union with `|`. A static LRU cache for each mode keeps up to 1024 results by default, and all instances share these caches. Entry point: `(new CssSelectorConverter())->toXPath('div.item > h4 > a')`, `CssSelectorConverter::$maxCachedItems`.
- **HTML mode and XML mode:** `new CssSelectorConverter()` uses HTML mode. HTML mode changes element names and attribute names to lowercase and adds the HTML pseudo-classes, but attribute values keep their case. `new CssSelectorConverter(false)` uses XML mode, in which names are case-sensitive. In XML mode, an HTML pseudo-class such as `:checked` throws an `ExpressionErrorException`. If the document is XML, use XML mode. `:lang(en)` in HTML mode reads the `lang` attribute of the element or of its nearest ancestor with that attribute, and it ignores case. In XML mode, `:lang()` becomes the XPath function `lang()`. Entry point: `new CssSelectorConverter(false)`.
- **Basic selectors:** the converter supports type, universal, class, ID and attribute selectors. It also supports the combinators `>`, `+` and `~`, and the space for descendants. The attribute operators are `=`, `~=`, `|=`, `^=`, `$=` and `*=`. A class selector matches only a complete word in the `class` attribute, so `.btn` does not match `btn-primary`. Entry point: `toXPath('ul#menu > li.active a[href^="https"]')`.
- **Namespaces:** `ns|element` becomes `ns:element`, and `[ns|attribute]` becomes `@ns:attribute`. `Crawler::filter()` finds the namespace of each prefix in the document, and the prefix `default` selects the default namespace. `Crawler::registerNamespace()` adds a prefix of your choice. If the document has no prefixed namespace, `addXmlContent()` removes the default namespace. Then select the elements without a prefix. Entry point: `$crawler->filter('default|entry media|group yt|aspectRatio')`.
- **Structural pseudo-classes:** `:root`, `:empty`, `:first-child`, `:last-child`, `:only-child`, `:first-of-type`, `:last-of-type` and `:only-of-type` work. The functions `:nth-child()`, `:nth-last-child()`, `:nth-of-type()` and `:nth-last-of-type()` accept `an+b`, `odd` and `even`. `:scope` is valid only at the start of a selector, as in `:scope > li`. Entry point: `toXPath('li:nth-child(2n+1)')`.
- **Logical pseudo-classes:** `:not()` accepts one compound selector without a combinator, for example `:not(a.ext)` or `:not([href])`. If `:not()` must exclude a selector list, use `:not(:is(.a, .b))`. `:is()` and `:where()` accept a selector list. A `:not()` directly inside a `:not()`, such as `:not(:not(a))`, throws a `SyntaxErrorException`. Entry point: `toXPath('a:not(:is(.ext, .mail))')`.
- **`:has()`:** since 8.1, `:has()` matches an element when the argument matches a descendant of the element. With a leading `>`, `+` or `~`, the argument must match a child, the next sibling or a later sibling instead. `:has()` accepts a selector list, but not a pseudo-element. Without a leading combinator, the argument can also match the element itself, so `div:has(div)` matches every `div`. A `:has()` with one argument inside `:not()`, `:is()` or `:where()` gives wrong results without an error. For example, `li:not(:has(a))` matches every `li`. A structural pseudo-class, such as `:first-child` or `:nth-child()`, in the same compound selector as `:has()` can give an invalid XPath expression or wrong results. In these cases, use `Crawler::filterXPath()`, for example `filterXPath('//li[not(.//a)]')`. Entry point: `toXPath('div:has(> img)')`, which returns `descendant-or-self::div[./img]`.
- **HTML pseudo-classes:** in HTML mode, `:checked`, `:selected` and `:link` select form controls and links by their attributes. `:checked` matches a checkbox or radio `input` with a `checked` attribute, but not an `option`. For a selected `option`, use `:selected`. `:link` matches an `a`, `link` or `area` element with an `href` attribute. `:hover`, `:visited` and `:invalid` are valid, but they never match. Entry point: `toXPath('input[name="terms"]:checked')`.
- **Disabled and enabled controls:** in HTML mode, `:disabled` matches a control with a `disabled` attribute. It also matches the controls in a disabled `fieldset`, except the controls in its first `legend`. `:enabled` also matches an `a`, `link` or `area` element with an `href` attribute. `:disabled` and `:enabled` match an `input` only when the `input` has a `type` attribute other than `hidden`. If an `input` has no `type` attribute, select it with `input[disabled]` instead of `input:disabled`. Entry point: `toXPath('button:disabled')`.
- **Extensions to CSS:** `:contains()` and the attribute operator `!=` are not standard CSS. `:contains("text")` matches an element whose text contains the string, and the comparison is case-sensitive. Without an element name, `:contains()` also matches every ancestor, such as `html` and `body`. `[attr!=value]` matches an element without the attribute or with a different value. Entry point: `toXPath('td:contains("Total")')`.
- **Unsupported selectors:** pseudo-elements such as `::before`, `:after` and `::first-line` throw an `ExpressionErrorException`. The pseudo-classes `:target`, `:focus`, `:active`, `:indeterminate` and `:unchecked` also throw it. The jQuery forms `:visible`, `:first` and `:eq()` throw it too. If you need `:first` or `:eq(1)`, use `Crawler::first()` or `Crawler::eq(1)`. If a test must check visibility, use the Panther assertion `assertSelectorIsVisible()`. Entry point: `Symfony\Component\CssSelector\Exception\ExpressionErrorException`.
- **The universal selector with `-of-type`:** `*:first-of-type`, `*:last-of-type` and `*:nth-last-of-type()` throw an `ExpressionErrorException`. `*:nth-of-type(2)` and `*:only-of-type` do not throw, but they work like `*:nth-child(2)` and `*:only-child`. `*:scope` throws a `SyntaxErrorException`. Always write an element name before an `-of-type` pseudo-class. Entry point: `toXPath('li:nth-of-type(2)')`.
- **Errors:** `ParseException` is the base class of the other exceptions of the component, and it implements `ExceptionInterface`. Invalid syntax, such as `h1:` or `//div`, throws a `SyntaxErrorException`. An unsupported pseudo-class, function or pseudo-element throws an `ExpressionErrorException`. An invalid argument of `:nth-child()`, `:contains()` or `:lang()` also throws it. `Crawler::filter()` does not catch these exceptions. Entry point: `catch (ParseException $e)`.
- **Use in DomCrawler:** `Crawler::filter()`, `children($selector)`, `matches()` and `closest()` convert the selector with `CssSelectorConverter`. `matches()`, `closest()` and `children()` search the whole document, so combinators and position pseudo-classes work. The crawler uses XML mode only after `addXmlContent()`. The constructor and `addContent()` call `addXmlContent()` for a string that starts with `<?xml`. `addContent()` also calls it for an XML content type, and BrowserKit gives it the `Content-Type` of the response. A `DOMDocument` that you give to the constructor or to `addDocument()` stays in HTML mode. If you have an XML `DOMDocument`, use `$crawler->addXmlContent($dom->saveXML())`. Entry point: `$crawler->filter('body > p')`, `Crawler::addXmlContent()`.
- **Test assertions:** the crawler assertions of `WebTestCase` come from `DomCrawlerAssertionsTrait`. Each assertion calls `Crawler::filter()`, so its selector follows the rules of this component. For example, `assertCheckboxChecked('terms')` uses the selector `input[name="terms"]:checked`. Entry point: `$this->assertSelectorTextContains('h1', 'Hello World')`.

## Entry points

- Class `Symfony\Component\CssSelector\CssSelectorConverter`: create it with `new CssSelectorConverter()` for HTML or `new CssSelectorConverter(false)` for XML. Then call `toXPath(string $cssExpr, string $prefix = 'descendant-or-self::'): string`.
- Without FrameworkBundle: call `(new CssSelectorConverter())->toXPath($selector)`, then give the expression to `DOMXPath::query()`, `SimpleXMLElement::xpath()` or `Crawler::filterXPath()`.
- Static property `CssSelectorConverter::$maxCachedItems` (default `1024`) for the size of each cache.
- Exceptions in `Symfony\Component\CssSelector\Exception`: `ParseException`, `SyntaxErrorException`, `ExpressionErrorException`, `InternalErrorException` and `ExceptionInterface`.
- DomCrawler methods that use this package: `Crawler::filter()`, `Crawler::children($selector)`, `Crawler::matches()` and `Crawler::closest()`. `Crawler::addXmlContent()` selects XML mode. `Crawler::registerNamespace()` and `Crawler::setDefaultNamespacePrefix()` control the namespace prefixes.
- Test assertions in `Symfony\Bundle\FrameworkBundle\Test\DomCrawlerAssertionsTrait`, which `WebTestCase` uses: `assertSelectorExists()`, `assertSelectorNotExists()`, `assertSelectorCount()`, `assertSelectorTextContains()`, `assertSelectorTextNotContains()`, `assertSelectorTextSame()`, `assertAnySelectorTextContains()`, `assertAnySelectorTextNotContains()`, `assertAnySelectorTextSame()`, `assertPageTitleSame()`, `assertPageTitleContains()`, `assertInputValueSame()`, `assertInputValueNotSame()`, `assertCheckboxChecked()`, `assertCheckboxNotChecked()`, `assertFormValue()` and `assertNoFormValue()`.
- Installation: `composer require symfony/css-selector`. In a Symfony application, `composer require --dev symfony/test-pack` also installs it. DomCrawler and BrowserKit list it only as a dev requirement, so they do not install it.
- The component has no service, configuration key, console command, Twig function or attribute. Its other classes (parser, translator, nodes and extensions) are `@internal`.
- The static `CssSelector` class does not exist. Use `CssSelectorConverter`.

## Symbiotic packages

- [DomCrawler](../packages/dom-crawler.md): `Crawler::filter()`, `children($selector)`, `matches()` and `closest()` convert their selector with this package, and they throw a `LogicException` when it is missing.
- [FrameworkBundle test tools](../packages/framework-bundle-testing.md): the crawler assertions of `WebTestCase`, such as `assertSelectorTextContains()`, call `Crawler::filter()` and need this package, which `symfony/test-pack` installs.
- [BrowserKit](../packages/browser-kit.md): `HttpBrowser` and the test client return a `Crawler` for each HTML or XML response, and the `followMetaRefresh()` mode needs this package.
- [UX Twig Component](../packages/ux-twig-component.md): `renderTwigComponent()` returns a `RenderedComponent`, and its `crawler()` method gives a `Crawler` for CSS selectors such as `filter('ul li')`.
- [UX Live Component](../packages/ux-live-component.md): the `TestLiveComponent` methods `call()`, `set()`, `emit()`, `refresh()`, `submitForm()` and `component()`, and the `assertComponent*()` event assertions, use `Crawler::filter()`, so they need DomCrawler and this package.
- [Panther](../packages/panther.md): Panther runs a real browser and sends `filter()` selectors to it, but its `matches()`, `closest()` and `children($selector)` still use this package.
- [JsonPath](../packages/json-path.md): for JSON, use `JsonCrawler::find()` with a JSONPath expression, because CssSelector and DomCrawler work only on HTML and XML.
- [Tui](../packages/tui.md): the Tui `StyleSheet` rules use their own CSS-like selectors for terminal widgets and do not use this package.

## Changed in 8.0/8.1

- **8.1, `:has()`:** the converter supports `:has()`. A hand-written XPath such as `//div[img]`, or a `reduce()` closure with a nested `filter()`, becomes `filter('div:has(> img)')`.
