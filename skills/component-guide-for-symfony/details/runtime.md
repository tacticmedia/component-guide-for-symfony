# Runtime (`symfony/runtime`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **Front-controller closure:** the front controller requires `vendor/autoload_runtime.php` and returns a closure. The runtime resolves the closure arguments, calls the closure and runs the object that the closure returns. The runtime includes the front controller a second time, so the code above the `require_once` line runs twice. Keep that code free of side effects. Entry point: `require_once dirname(__DIR__).'/vendor/autoload_runtime.php';` and `return function (array $context) { ... };`.
- **The `autoload_runtime.php` file:** the Composer plugin of the package writes `vendor/autoload_runtime.php` after each autoload dump. The file loads `vendor/autoload.php`, includes the front controller, creates the runtime and exits with the exit code of the runner. If `vendor/autoload.php` is already loaded, the file does not start the runtime. With `composer --no-plugins`, Composer does not create the file. Composer runs only the plugins that `config.allow-plugins` in `composer.json` allows, for example `"symfony/runtime": true`. Entry point: `composer dump-autoload`.
- **Runtime classes:** `SymfonyRuntime` is the default runtime. `GenericRuntime` gives the closure plain arrays from the PHP superglobals. To use another class, set the `APP_RUNTIME` env var or `extra.runtime.class` in `composer.json`. Entry point: `Symfony\Component\Runtime\SymfonyRuntime`, `Symfony\Component\Runtime\GenericRuntime`.
- **Closure arguments:** both runtimes resolve `array $context` (server vars and env vars), `array $argv` and `array $request` (keys `query`, `body`, `files` and `session`). For these three arguments, the type and the name must match. `SymfonyRuntime` also resolves `Request`, `InputInterface`, `OutputInterface`, the console `Application` and `Command`. A `RuntimeInterface` argument gets the runtime itself. Entry point: `return function (Request $request, array $context) { ... };`.
- **Application objects and runners:** `SymfonyRuntime` runs a returned `HttpKernelInterface` with `HttpKernelRunner`, a `Response` with `ResponseRunner`, and a console `Application` or `Command` with `ConsoleApplicationRunner`. Both runtimes also run a `RunnerInterface` object or a callable. A callable returns an `int` exit code, a `string` to print, or `null`. If the closure returns nothing, the exit code is 0. Entry point: `Symfony\Component\Runtime\RunnerInterface::run(): int`.
- **HTTP kernel runner:** `HttpKernelRunner` handles the `Request` object that the closure arguments also receive, and sends the response. If debug mode is off and `fastcgi_finish_request()` or `litespeed_finish_request()` exists, the runner calls that function before it calls `terminate()` on a `TerminableInterface` kernel. With PHP-FPM, the client then gets the response before the `kernel.terminate` listeners run. Entry point: `Symfony\Component\Runtime\Runner\Symfony\HttpKernelRunner`.
- **Console scripts:** for a returned console `Application`, `ConsoleApplicationRunner` adds the `--env` (`-e`) and `--no-debug` options, unless the `env` runtime option is set. `SymfonyRuntime` reads these options before it loads the `.env` files, and it removes the PHP time limit. If the closure returns a `Command`, the runtime puts the command in a single-command `Application`. Entry point: `Symfony\Component\Runtime\Runner\Symfony\ConsoleApplicationRunner`.
- **Where to set runtime options:** before the `require_once` line, set `$_SERVER['APP_RUNTIME_OPTIONS']` to an array. Alternatively, set the `APP_RUNTIME_OPTIONS` env var to a JSON string, or put the options under `extra.runtime` in `composer.json` and run `composer dump-autoload`. The `APP_RUNTIME_OPTIONS` values have priority over the `composer.json` values. The runtime reads `APP_RUNTIME` and `APP_RUNTIME_OPTIONS` before it loads `.env`, so do not define them in `.env`. Entry point: `$_SERVER['APP_RUNTIME_OPTIONS']`, `extra.runtime`.
- **Environment and debug mode:** in `SymfonyRuntime`, the `env` option has priority over the `--env` console option, and `--env` has priority over the `APP_ENV` env var. The default environment is `dev`. The `debug` option, `--no-debug` and `APP_DEBUG` set debug mode. If none of them is set, debug mode is on, except for the environments in the `prod_envs` option (default `["prod"]`). In `GenericRuntime`, debug mode is on unless `APP_DEBUG` or the `debug` option turns it off. The options `env_var_name` and `debug_var_name` change the names `APP_ENV` and `APP_DEBUG`. Entry point: `$context['APP_ENV']`, `$context['APP_DEBUG']`.
- **`.env` loading:** if `symfony/dotenv` is installed, `SymfonyRuntime` calls `Dotenv::bootEnv()` for the `dotenv_path` file (default `.env`) in the `project_dir` directory. The generated `autoload_runtime.php` sets `project_dir` to the directory of `composer.json`, or to `extra.runtime.project_dir` relative to it. To let the `.env` files override real env vars, set `dotenv_overload` to `true`. The Runtime docs page says that this option makes `.env.local` override `.env`. That is not correct: `.env.local` overrides `.env` without this option. The `dotenv_extra_paths` option (in the source, not in the docs) loads more files after the `.env` files, relative to `project_dir`. Each of these files must exist, and `dotenv_overload` also applies to them. The `disable_dotenv: true` option skips all `.env` files. Before it loads the `.env` files, the runtime sets `APP_PROJECT_DIR`, so these files can use `${APP_PROJECT_DIR}`. The `project_dir_var` option changes this name. Entry point: `extra.runtime.dotenv_path`.
- **Error handler:** `SymfonyRuntime` registers the `ErrorHandler` of `symfony/error-handler`, and the `DebugClassLoader` in debug mode. Without that package, and in `GenericRuntime`, a basic handler throws an `ErrorException` for PHP warnings and notices. In debug mode, both runtimes also call `umask(0o000)`. To keep your own error handler, set the `error_handler` option to `false`. Entry point: `error_handler` option.
- **FrankenPHP worker mode:** FrankenPHP sets `$_SERVER['FRANKENPHP_WORKER']` to `1` for a worker script, for example `worker ./public/index.php` in the `Caddyfile`. If this value is true and the closure returns an `HttpKernelInterface` or a `Response`, `SymfonyRuntime` uses `FrankenPhpWorkerRunner`. The runner handles the requests in a `frankenphp_handle_request()` loop. After each request, it calls `terminate()` on a terminable kernel and runs `gc_collect_cycles()`. The worker restarts after `worker_loop_max` requests. If this option is not set, the runtime reads the `FRANKENPHP_LOOP_MAX` env var, and the default is 500. A value of 0 or less removes the limit. The runner sets `APP_RUNTIME_MODE` to `web=1&worker=1`. Entry point: `Symfony\Component\Runtime\Runner\FrankenPhpWorkerRunner`.
- **Kernel reset in worker mode:** by default, one kernel serves all requests of a worker, so state in services can leak into the next request. To prevent this, implement `ResetInterface` in these services. If that is not possible, set `FRANKENPHP_RESET_KERNEL=1`. The runner then clones the kernel after each request and sets `APP_RUNTIME_MODE` to `web=1&worker=2`. This option costs performance. Entry point: `FRANKENPHP_RESET_KERNEL`.
- **Custom runtimes:** to support a new application type, extend `GenericRuntime` and override `getRunner()` to return your own `RunnerInterface`. To supply your own object for a closure argument type, extend `SymfonyRuntime` and override `resolveType()`. The `runtimes` option, or a class named `Symfony\Runtime\<FQCN>Runtime`, adds a runtime for one type. The `extra.runtime.autoload_template` key sets your own template for the generated file. Entry point: `GenericRuntime::getRunner()`, `SymfonyRuntime::resolveType()`.
- **Third-party runtimes in the docs:** the docs name PHP-PM, ReactPHP, Swoole, FrankenPHP and AWS Lambda. Only FrankenPHP worker mode has a built-in runner. For the other servers, use a custom runtime class. As an example, the docs show a ReactPHP runner for PSR-15 request handlers. Entry point: `APP_RUNTIME` or `extra.runtime.class`.

## Entry points

- Front controllers `public/index.php` and `bin/console`: `require_once dirname(__DIR__).'/vendor/autoload_runtime.php';`, then `return function (array $context) { ... };`.
- Generated file `vendor/autoload_runtime.php`: the Composer plugin (`Symfony\Component\Runtime\Internal\ComposerPlugin`, internal) writes it at each autoload dump, for example `composer dump-autoload`.
- `composer.json` keys: `extra.runtime.class`, `extra.runtime.autoload_template`, `extra.runtime.project_dir` and each runtime option under `extra.runtime` (for example `extra.runtime.dotenv_path`). The value `"extra": {"runtime": false}` stops the file generation.
- Env vars that the runtime reads: `APP_RUNTIME`, `APP_RUNTIME_OPTIONS` (array in `$_SERVER`, or JSON string), `APP_ENV`, `APP_DEBUG`, `FRANKENPHP_WORKER`, `FRANKENPHP_LOOP_MAX` and `FRANKENPHP_RESET_KERNEL`.
- Env vars that the runtime sets: `APP_ENV` and `APP_PROJECT_DIR` (`SymfonyRuntime` only), `APP_DEBUG` (as `'1'` or `'0'`), `APP_RUNTIME_MODE` (worker mode only), `$_SERVER['APP_RUNTIME']` and `$_SERVER['APP_RUNTIME_OPTIONS']` (the class and the options in use).
- Runtime options of `SymfonyRuntime`: `env`, `debug`, `disable_dotenv`, `dotenv_path`, `dotenv_overload`, `dotenv_extra_paths`, `prod_envs`, `test_envs`, `use_putenv`, `project_dir`, `project_dir_var`, `worker_loop_max`, `runtimes`, `error_handler`, `env_var_name` and `debug_var_name`.
- Runtime options of `GenericRuntime`: `debug`, `runtimes`, `error_handler`, `env_var_name` and `debug_var_name`.
- Runtime classes: `Symfony\Component\Runtime\SymfonyRuntime` (default) and `Symfony\Component\Runtime\GenericRuntime`.
- Without FrameworkBundle: return a callable, a `RunnerInterface` object, a console `Application` or a `Command` from the closure. For plain arrays from the PHP superglobals, select `GenericRuntime` with `APP_RUNTIME` or `extra.runtime.class`.
- Interfaces: `Symfony\Component\Runtime\RuntimeInterface`, `Symfony\Component\Runtime\ResolverInterface` and `Symfony\Component\Runtime\RunnerInterface`.
- Runners: `Symfony\Component\Runtime\Runner\Symfony\HttpKernelRunner`, `Symfony\Component\Runtime\Runner\Symfony\ResponseRunner`, `Symfony\Component\Runtime\Runner\Symfony\ConsoleApplicationRunner`, `Symfony\Component\Runtime\Runner\ClosureRunner` and `Symfony\Component\Runtime\Runner\FrankenPhpWorkerRunner`.
- Protected extension point: `SymfonyRuntime::resolveType(string $type): mixed`.
- Console options that the runtime adds: `--env` (`-e`) and `--no-debug`.
- The package has no bundle configuration key, service, console command, Twig function or attribute. It runs before the kernel builds the container.

## Symbiotic packages

- [HttpKernel](../packages/http-kernel.md): `HttpKernelRunner` and `FrankenPhpWorkerRunner` run a returned `HttpKernelInterface` such as `App\Kernel`, and call `terminate()` after the response.
- [HttpFoundation](../packages/http-foundation.md): `SymfonyRuntime` creates the `Request` argument with `Request::createFromGlobals()`, and `ResponseRunner` sends a returned `Response`.
- [Console](../packages/console.md): the runtime resolves `InputInterface`, `OutputInterface`, `Application` and `Command` arguments and runs a returned `Application` or `Command`; since 8.1, a `ConsoleBundle` script returns `new Application('my-cli', '1.0', $kernel->getContainer())`.
- [FrameworkBundle](../packages/framework-bundle.md): `bin/console` returns its `Symfony\Bundle\FrameworkBundle\Console\Application`, and FrameworkBundle reuses the error handler of the runtime and preloads `SymfonyRuntime` and its HTTP runners.
- [Dotenv](../packages/dotenv.md): `SymfonyRuntime` loads the `.env` files with `Dotenv::bootEnv()`, and `debug:dotenv` and `dotenv:dump` read `dotenv_path` from the runtime options.
- [ErrorHandler](../packages/error-handler.md): `SymfonyRuntime` registers its `ErrorHandler`, and its `DebugClassLoader` in debug mode; `symfony/runtime` conflicts with `symfony/error-handler` versions below 7.4.
- [DependencyInjection](../packages/dependency-injection.md): its `KernelTrait` reads `APP_RUNTIME_MODE` into `kernel.runtime_mode` and `kernel.runtime_mode.worker` (the integer `1` or `2` in worker mode, else `0`); `APP_RUNTIME_ENV` (`kernel.runtime_environment`) is a kernel setting, not a runtime option.
- [Symfony Contracts](../packages/contracts.md): in FrankenPHP worker mode, services that keep state between requests implement `ResetInterface`, unless `FRANKENPHP_RESET_KERNEL` clones the kernel.
- [WebProfilerBundle](../packages/web-profiler-bundle.md): the toolbar and the Configuration panel of the profiler show the runner class, for example `HttpKernelRunner` or `FrankenPhpWorkerRunner`.
- [Symfony Flex](../packages/flex.md): the FrameworkBundle and Console recipes create `public/index.php` and `bin/console` as runtime front controllers. Flex also reads `extra.runtime`: it writes recipe env vars to the `dotenv_path` file, and `composer dump-env` uses these options.

## Changed in 8.0/8.1

- **8.1, `Response` in worker mode:** if the closure returns a `Response`, for example a maintenance page, `FrankenPhpWorkerRunner` serves it in the worker loop. Before 8.1, only an `HttpKernelInterface` used the worker runner.
- **8.1, `FRANKENPHP_RESET_KERNEL`:** set it to `1` to clone the kernel after each worker request. Use it when you cannot add `ResetInterface` to every service that keeps state.
- **8.1, `SymfonyRuntime::resolveType()`:** override this protected method in a runtime subclass to supply your own object for a closure argument type. For all other types, return `parent::resolveType($type)`. A `null` return delegates to `GenericRuntime`, which does not resolve `Request` or the console types.
- **8.0 (also 7.4), FrankenPHP worker mode:** `SymfonyRuntime` detects worker mode and uses `FrankenPhpWorkerRunner`. You do not need the `runtime/frankenphp-symfony` package or its `APP_RUNTIME` class for this.
- **8.0 (also 7.4), options as JSON:** a real `APP_RUNTIME_OPTIONS` env var can hold a JSON string, for example `{"dotenv_path":"config/.env"}`. The runtime exposes the class and the options in `$_SERVER['APP_RUNTIME']` and `$_SERVER['APP_RUNTIME_OPTIONS']`.
- **8.0 (also 7.4), project directory:** if the project root is not the directory of `composer.json`, set `extra.runtime.project_dir`. The runtime exposes the project directory as the `APP_PROJECT_DIR` env var.
- **8.0, Console code in front controllers:** `Application::add()` no longer exists, so call `addCommand()`. A `setCode()` closure must return an `int`. Otherwise, the command throws a `TypeError`. The Runtime docs examples show `add()` and `: void`.
