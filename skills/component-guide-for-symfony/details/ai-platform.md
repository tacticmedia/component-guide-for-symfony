# AI Platform (`symfony/ai-platform`): details

**Applies to:** Symfony AI 0.14

## Key features and concepts

- **Platform and deferred result:** `invoke($model, $input, $options)` returns a `DeferredResult`. The result is converted when you read it with `asText()`, `asObject()`, `asVectors()`, `asBinary()`, `asFile()`, `asToolCalls()`, `asStream()` or `asJob()`. Several `invoke()` calls before the first read run in parallel. The main bridges convert HTTP errors to typed exceptions, for example `AuthenticationException` (401) and `RateLimitExceededException` (429, `getRetryAfter()`). Entry point: `Symfony\AI\Platform\PlatformInterface`.
- **Provider bridges:** each provider has its own Composer package `symfony/ai-<name>-platform`. The `Factory` class of each provider bridge (for Azure: `Azure\OpenAi\Factory` and `Azure\Meta\Factory`) has `createPlatform()` for a ready `Platform` and `createProvider()` for a multi-provider `Platform`. `new Platform([$providerA, $providerB])` sends each model to the first provider whose catalog has the model (`CatalogBasedModelRouter`). For an OpenAI-compatible API, use the `Generic` bridge with a base URL. Entry point: `Symfony\AI\Platform\Bridge\OpenAi\Factory`.
  - The README of the package lists 43 bridge packages, and the source tree has the same 43 names. The name is the bridge name in kebab-case, for example `symfony/ai-open-ai-platform` for OpenAI. Six packages do not serve one specific AI provider. `cache` and `failover` are decorators, and `generic` and `open-responses` serve any compatible API. `models-dev` gives only a model catalog and provider data. `meta` holds the Llama model classes that the Azure, Bedrock and Replicate bridges use. All names: `symfony/ai-ai-ml-api-platform`, `symfony/ai-albert-platform`, `symfony/ai-amazee-ai-platform`, `symfony/ai-anthropic-platform`, `symfony/ai-azure-platform`, `symfony/ai-bedrock-platform`, `symfony/ai-cache-platform`, `symfony/ai-cartesia-platform`, `symfony/ai-cerebras-platform`, `symfony/ai-claude-code-platform`, `symfony/ai-codex-platform`, `symfony/ai-cohere-platform`, `symfony/ai-decart-platform`, `symfony/ai-deep-seek-platform`, `symfony/ai-deepgram-platform`, `symfony/ai-docker-model-runner-platform`, `symfony/ai-eden-ai-platform`, `symfony/ai-eleven-labs-platform`, `symfony/ai-failover-platform`, `symfony/ai-fireworks-platform`, `symfony/ai-gemini-platform`, `symfony/ai-generic-platform`, `symfony/ai-higgsfield-platform`, `symfony/ai-hugging-face-platform`, `symfony/ai-lm-studio-platform`, `symfony/ai-meta-platform`, `symfony/ai-mini-max-platform`, `symfony/ai-mistral-platform`, `symfony/ai-models-dev-platform`, `symfony/ai-ollama-platform`, `symfony/ai-open-ai-platform`, `symfony/ai-open-responses-platform`, `symfony/ai-open-router-platform`, `symfony/ai-ovh-platform`, `symfony/ai-perplexity-platform`, `symfony/ai-replicate-platform`, `symfony/ai-scaleway-platform`, `symfony/ai-together-platform`, `symfony/ai-transformers-php-platform`, `symfony/ai-type-safe-platform`, `symfony/ai-venice-platform`, `symfony/ai-vertex-ai-platform`, `symfony/ai-voyage-platform`.
- **Models and capabilities:** a `Model` has a name, `Capability` cases (for example `INPUT_IMAGE`, `INPUT_PDF`, `OUTPUT_STRUCTURED`, `EMBEDDINGS`) and default options. A model name can carry options as a query string, for example `gpt-4o-mini?temperature=0.5`. Each provider bridge has a model catalog. `FallbackModelCatalog` accepts each model name and gives it all capabilities. Entry point: `Symfony\AI\Platform\ModelCatalog\ModelCatalogInterface`.
- **models.dev data:** `Symfony\AI\Platform\Bridge\ModelsDev\ModelCatalog` (package `symfony/ai-models-dev-platform`) builds the models and their capabilities from the `symfony/models-dev` data package. Install both packages. Give the catalog to a bridge factory, for example `modelCatalog: new ModelCatalog('deepseek')`. For an OpenAI-compatible provider, `ProviderRegistry::getApiBaseUrl()` gives the base URL for the `Generic` bridge. `symfony/models-dev` is a daily snapshot: a minor version adds models, and a major version removes models.
- **Messages and templates:** a `MessageBag` holds the messages from `Message::forSystem()`, `Message::ofUser()`, `Message::ofAssistant()` and `Message::ofToolCall()`. `Template::string('You are a {role} assistant.')` adds variables. Give the values in the `template_vars` option. Without the AI Bundle, add `TemplateRendererListener` to the event dispatcher. Entry point: `Symfony\AI\Platform\Message\MessageBag`.
- **Multimodal input:** give content objects to `Message::ofUser()`: `Image::fromFile()`, `Image::fromDataUrl()`, `ImageUrl`, `Document::fromFile()` (PDF), `DocumentUrl`, `Audio::fromFile()` and `Video::fromFile()`. The model must support the input type, for example `Capability::INPUT_PDF`. Entry point: `Symfony\AI\Platform\Message\Content\Image`.
- **Streams:** set the `stream` option to `true`. `asTextStream()` yields `TextDelta` objects that you can `echo`. `asStream()` yields the typed deltas, for example `TextDelta`, `ThinkingDelta`, `ToolCallStart`, `ToolCallComplete` and `BinaryDelta`. Entry point: `Symfony\AI\Platform\Result\Stream\Delta\DeltaInterface`.
- **Thinking:** for a reasoning model, set the `thinking` option, for example `['type' => 'enabled', 'budget_tokens' => 10000]` for Anthropic. `Capability::THINKING` marks the models that support it. A stream yields `ThinkingDelta` and `ThinkingComplete` (`getSignature()`), and a buffered result contains a `ThinkingResult`; `asText()` still returns only the text. `Message::ofAssistant($result)` keeps the text, the thinking blocks with their signatures and the tool calls for the next request. Entry points: `Symfony\AI\Platform\Result\Stream\Delta\ThinkingDelta` and `Symfony\AI\Platform\Result\ThinkingResult`.
- **Structured output:** give a class name, an object to fill, or a JSON schema array in the `response_format` option. `asObject()` returns the object, or an array for a JSON schema array. `PlatformSubscriber` must listen on the event dispatcher of the platform; the AI Bundle registers it. The JSON schema comes from the PHP types, the `#[Schema]` attribute and, if symfony/validator is installed, the constraints. For a class name or an object, the model must have `Capability::OUTPUT_STRUCTURED`, or `MissingModelSupportException` occurs. `ValidatorSubscriber` validates the object and throws `ValidationException`. With the `stream` option, `asStreamedObject()` yields partial objects. Entry point: `Symfony\AI\Platform\StructuredOutput\PlatformSubscriber`.
- **Embeddings, reranking and classification:** `asVectors()` returns `Vector` objects, and `getData()` gives the list of floats. `asReranking()` returns `RerankingEntry` objects with `getIndex()` and `getScore()`. The TypeSafe bridge (`symfony/ai-type-safe-platform`) sends an `Evaluation` (a state and `NoulQuestion`, `ChoiceQuestion` or `ScoreQuestion` objects) to the Jev model, for example `jev-latest`. `asObject()` then returns `Answers` with calibrated probabilities, for example `getNoul('is_urgent')->isTrue()`. Jev fits classification, routing, scoring and guardrails, but it cannot be the model of an agent. Entry points: `Symfony\AI\Platform\Vector\Vector` and `Symfony\AI\Platform\Bridge\TypeSafe\Evaluation`.
- **Server tools:** for OpenAI, Azure OpenAI and Scaleway, add raw entries to the `tools` option, for example `['type' => 'web_search']`. For Anthropic, Gemini and Vertex AI, use the `server_tools` option, for example `['web_search' => true]` or `['google_search' => true]`. The Anthropic bridge maps only `web_search` and `code_execution`; other names throw `InvalidArgumentException`. Entry point: the `tools` and `server_tools` options of `invoke()`.
- **Result metadata:** read the result first, because the metadata stays empty until then. For a stream, read all deltas first. Then `getMetadata()->get('token_usage')` returns a `TokenUsageInterface` with the prompt, completion, thinking and cached tokens. `getMetadata()->get('finish_reason')` returns a `FinishReason`; `is(FinishReasonCase::LENGTH)` finds a truncated answer. If the provider does not report a value, `get()` returns `null`. Entry point: `Symfony\AI\Platform\TokenUsage\TokenUsageInterface`.
- **Asynchronous jobs and batches:** the MiniMax, Replicate, Higgsfield, Venice and Eden AI bridges can return a `JobResult`. `asJob()` returns a serializable `JobHandle`, and `JobRunner::wait()` polls the job client from `Factory::createJobClient()`. For OpenAI, the `'batch' => true` option with an array of `MessageBag` inputs sends one batch job. The job client then returns a `BatchResult` of `BatchItem` objects. Entry point: `Symfony\AI\Platform\Job\JobRunner`.
- **Decorators:** `CachePlatform` (`symfony/ai-cache-platform`) keeps results in a tag-aware cache pool, but only for calls with the `prompt_cache_key` option. `FailoverPlatform` (`symfony/ai-failover-platform`) calls the next platform when `invoke()` throws an exception, for example for a model that is not in the catalog. The main bridges check the HTTP status only when you read the result, so a 429 or 5xx error does not start the fallback. In debug mode, the AI Bundle wraps each platform in `TraceablePlatform` for the profiler. Entry point: `Symfony\AI\Platform\Bridge\Cache\CachePlatform`.
- **Test doubles:** `InMemoryPlatform` returns a fixed text, or the result of a closure that gets the model, the input and the options. `MockPlatformFactory` returns scripted responses for each model. `RecordingProvider` with a `Cassette` records real results one time and then replays them. `CassetteHttpClient` with an `HttpCassette` records and replays the HTTP traffic of a bridge. Entry point: `Symfony\AI\Platform\Test\InMemoryPlatform`.

## Entry points

- `Symfony\AI\Platform\PlatformInterface`: autowire it. The AI Bundle creates this alias only when exactly one platform service exists. A `cache` or `failover` entry is also a platform service. With more platforms, inject a platform service, for example `ai.platform.openai`, or `ai.platform.generic.<name>` for a named type such as `generic`.
- Without FrameworkBundle: `Symfony\AI\Platform\Bridge\<Bridge>\Factory::createPlatform()` and `::createProvider()` create a platform without the AI Bundle. For structured output, add `PlatformSubscriber` to the event dispatcher of the platform. For message templates, add `TemplateRendererListener`.
- `Symfony\AI\Platform\Platform` and `Symfony\AI\Platform\ModelRouterInterface`: put several providers in one platform.
- `Symfony\AI\Platform\Message\Message`, `Symfony\AI\Platform\Message\MessageBag`, `Symfony\AI\Platform\Message\Template`.
- `Symfony\AI\Platform\Message\Content\Image`, `ImageUrl`, `Document`, `DocumentUrl`, `Audio`, `Video`, `Collection` (same namespace).
- `Symfony\AI\Platform\Result\DeferredResult`: the return type of `invoke()`.
- `Symfony\AI\Platform\Contract\JsonSchema\Attribute\Schema`: attribute for properties and parameters (`description`, `enum`, `pattern`, `minimum`, `maximum` and more).
- `Symfony\AI\Platform\Contract\JsonSchema\Provider\SchemaProviderInterface`: adds schema fragments at run time. The AI Bundle autoconfigures it with the tag `ai.platform.json_schema.provider`.
- `Symfony\AI\Platform\StructuredOutput\PlatformSubscriber` (service `ai.platform.structured_output_subscriber`) and `Symfony\AI\Platform\StructuredOutput\Validator\ValidatorSubscriber`.
- `Symfony\AI\Platform\Job\JobRunner` (service `ai.platform.job_runner`) and `Symfony\AI\Platform\Job\JobClientInterface` (services `ai.platform.job_client.<type>`, for example `ai.platform.job_client.openai`).
- `Symfony\AI\Platform\Bridge\ModelsDev\ModelCatalog` and `Symfony\AI\Platform\Bridge\ModelsDev\ProviderRegistry`.
- `Symfony\AI\Platform\Bridge\TypeSafe\Evaluation` and `Symfony\AI\Platform\Bridge\TypeSafe\Answer\Answers`.
- Config keys (AI Bundle): `ai.platform.<bridge>` (for example `ai.platform.openai.api_key`), `ai.platform.generic.<name>.base_url`, `ai.platform.cache.<name>.platform`, `ai.platform.failover.<name>.platforms` and `ai.platform.failover.<name>.rate_limiter`, `ai.model.<platform>.<model>.class` and `ai.model.<platform>.<model>.capabilities`.
- Console command (AI Bundle): `ai:platform:invoke [platform] [model] [message]`. All three arguments are optional, and the command asks for missing values.
- Test helpers: `Symfony\AI\Platform\Test\InMemoryPlatform`, `Symfony\AI\Platform\Test\MockPlatformFactory`, `Symfony\AI\Platform\Test\Recording\RecordingProvider`, `Symfony\AI\Platform\Test\Replay\CassetteHttpClient`, `Symfony\AI\Platform\Test\Replay\AbstractBridgeReplayTestCase`. In the AI Bundle: `Symfony\AI\AiBundle\Test\AiAssertionsTrait` (`assertPlatformCallCount()`, `assertModelCalled()`).

## Symbiotic packages

- [AI Bundle](../packages/ai-bundle.md): configures platforms under `ai.platform`, registers the `ai.platform.<type>` and `ai.platform.<type>.<name>` services and the structured output subscriber, and adds `ai:platform:invoke`.
- [AI Agent](../packages/ai-agent.md): runs tool calls, memory and processors on top of a `PlatformInterface`; for single model calls, AI Platform alone is enough.
- [AI Store](../packages/ai-store.md): its `Vectorizer` uses a platform and an embeddings model to turn documents into vectors for vector search and RAG.
- [AI Chat](../packages/ai-chat.md): keeps the `MessageBag` of a conversation in a message store, so that the chat history persists between requests.
- [Serializer](../packages/serializer.md): structured output maps the JSON answer to PHP objects with the Serializer, and the schema follows serializer groups and discriminator maps.
- [Validator](../packages/validator.md): `ValidatorSubscriber` validates structured output objects, and the schema factory turns constraints such as `Length` and `Range` into JSON schema keywords.
- [EventDispatcher](../packages/event-dispatcher.md): each call dispatches `InvocationEvent` and `ResultEvent`, and structured output and templates work only through these listeners.
- [HttpClient](../packages/http-client.md): the bridges send their requests through `HttpClientInterface`, and `CassetteHttpClient` replays recorded HTTP traffic in tests.
- [Cache](../packages/cache.md): `CachePlatform` keeps results in a tag-aware cache pool (`TagAwareAdapterInterface`).
- [RateLimiter](../packages/rate-limiter.md): `FailoverPlatform` requires a `RateLimiterFactoryInterface` and creates one limiter for each platform class, but it calls a platform even when its limit is reached.
- [ExpressionLanguage](../packages/expression-language.md): `Template::expression()` renders message templates with expressions.
- [Uid](../packages/uid.md): each message and each `MessageBag` gets a UUID v7 from `getId()`.
- [Clock](../packages/clock.md): `JobRunner`, `CachePlatform` and `FailoverPlatform` read the time through `ClockInterface`.
- [Stopwatch](../packages/stopwatch.md): in debug mode, `TraceablePlatform` starts the stopwatch event `ai.platform.invoke "<model>"` for each call.
- [HttpFoundation](../packages/http-foundation.md): put an `asTextStream()` loop in a `StreamedResponse` to stream the answer to the browser.
- [Messenger](../packages/messenger.md): a `JobHandle` is serializable, so a Messenger message can carry it to a worker that waits for the job.
- [TypeInfo](../packages/type-info.md): the JSON schema factory reads the property types through TypeInfo.
- [PropertyInfo](../packages/property-info.md): the JSON schema factory reads the properties and their descriptions through PropertyInfo.

## Changed in 0.3 to 0.14

- 0.3: `Symfony\AI\Platform\CachedPlatform` -> `Symfony\AI\Platform\Bridge\Cache\CachePlatform` in `symfony/ai-cache-platform`.
- 0.7: `ChunkEvent` and `onChunk()` -> `DeltaEvent` and `onDelta()`. Streams yield typed deltas, not strings: replace `is_string($chunk)` with `$chunk instanceof TextDelta`.
- 0.8: `PlatformFactory::create()` -> `Factory::createPlatform()`, or `Factory::createProvider()` for a multi-provider `Platform`, in each bridge.
- 0.8: `#[With]` -> `#[Schema]` (`Symfony\AI\Platform\Contract\JsonSchema\Attribute\Schema`).
- 0.9: `new AssistantMessage(content: ..., toolCalls: ...)` -> `new AssistantMessage(new Text(...), new ToolCall(...))`. `getContent()` returns content parts; `asText()` returns the text.
- 0.10: models.dev `Factory`, `BridgeResolver` and `ModelResolver` are removed -> the `Factory` of a bridge with `modelCatalog: new ModelsDev\ModelCatalog('<provider>')`, plus `ProviderRegistry` for base URLs.
- 0.11: OpenAI `DallE` -> `Image` for the `gpt-image-*` models. The `dall-e-2` and `dall-e-3` catalog entries are removed.
- 0.14: MiniMax and Replicate return a `JobResult` -> call `asJob()`, then `JobRunner::wait()` with `Factory::createJobClient()`. A direct `asText()` or `asFile()` throws `UnexpectedResultTypeException`.

## Status

The component is experimental (README: "This Component is experimental"). Experimental code has no Symfony backward compatibility promise. All versions are 0.x, and minor versions contain breaking changes, for example 0.14 for the MiniMax and Replicate bridges. Before an update, read `UPGRADE.md` of symfony/ai. Packagist has v0.14.1 only for `symfony/ai-platform`; the 43 bridge packages stay at v0.14.0, with the same code as the v0.14.1 tag. The package requires PHP 8.2 or later and the `fileinfo` extension.
