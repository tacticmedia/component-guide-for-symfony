# Webhook (`symfony/webhook`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **One endpoint for all webhooks.** The Flex recipe creates `config/routes/webhook.yaml`. This file imports `@FrameworkBundle/Resources/config/routing/webhook.php` with the prefix `/webhook`. The imported route `_webhook_controller` has the path `/{type}` and calls `WebhookController::handle()`. If no parser is configured for `{type}`, the controller returns a 404 response. Entry point: `config/routes/webhook.yaml`.
- **Routing names.** Each key under `framework.webhook.routing` is a routing name, for example `mailer_mailgun`. The webhook URL is `/webhook/<routing name>`. The `service` option (required) is the ID of the parser service. The `secret` option (default `''`) is the value that the parser uses to authenticate the request. The same routing name connects the parser to its consumer. Entry point: `framework.webhook.routing`.
- **Parser contract.** A parser implements `RequestParserInterface`. Its `parse($request, $secret)` method returns a `RemoteEvent`, a list of `RemoteEvent` objects or `null`. To reject a request, it throws `RejectWebhookException`, an HTTP exception with the status code 406 by default. For each event, the controller dispatches a `ConsumeRemoteEventMessage`, then returns `createSuccessfulResponse()`. In `AbstractRequestParser`, this response is a 202 with an empty body. For `null` or an empty list, the controller returns `createRejectedResponse()`, a 406 in `AbstractRequestParser`. The interface docblock says that `null` means "ignore the webhook", but the provider gets this 406 response. If a provider expects another status code or body, override `createSuccessfulResponse()` or `createRejectedResponse()`. Entry point: `Symfony\Component\Webhook\Client\RequestParserInterface`.
- **Custom parsers.** Extend `AbstractRequestParser` and implement `getRequestMatcher()` and `doParse()`. Return a request matcher from `getRequestMatcher()`, for example a `ChainRequestMatcher` with `MethodRequestMatcher('POST')` and `IsJsonRequestMatcher`. If the request does not match, the parser rejects it with a 406. In `doParse()`, verify the signature with `hash_equals()`. If the provider sends a timestamp, reject old requests. Throw `RejectWebhookException` for each failure. A malformed JSON body also gives a 406 response. The `make:webhook` command generates a parser, a consumer and the routing entry. Entry point: `Symfony\Component\Webhook\Client\AbstractRequestParser`.
- **Payload converters.** Put the mapping from the provider payload to a `RemoteEvent` in a class that implements `PayloadConverterInterface`. Inject the converter into the parser. Convert a `ParseException` from the converter into a `RejectWebhookException`. Each mailer bridge uses this pattern, with the service `mailer.payload_converter.<provider>`. Entry point: `Symfony\Component\RemoteEvent\PayloadConverterInterface`.
- **Built-in parser for Symfony senders.** `RequestParser` accepts a POST request with a valid JSON body and the `Webhook-Signature`, `Webhook-Event` and `Webhook-Id` headers. With the default algorithm, it compares `Webhook-Signature` with `sha256=` and the HMAC-SHA256 of the event name, event ID and raw body, concatenated. It creates a `RemoteEvent` from the two other headers and the decoded body. An empty secret causes an `InvalidArgumentException`. Entry point: `service: Symfony\Component\Webhook\Client\RequestParser` (an alias of `webhook.request_parser`).
- **Consumers.** A consumer class implements `ConsumerInterface::consume(RemoteEvent $event)` and has the attribute `#[AsRemoteEventConsumer('<routing name>')]`. FrameworkBundle autoconfigures this attribute as the `remote_event.consumer` tag. If no consumer has the routing name, `ConsumeRemoteEventHandler` throws a `LogicException`. Type the parameter as `RemoteEvent`. Check the event class with `instanceof`. These types come from `symfony/remote-event`. Entry point: `Symfony\Component\RemoteEvent\Attribute\AsRemoteEventConsumer`.
- **Asynchronous consumption.** The controller dispatches each event as a `ConsumeRemoteEventMessage` on the bus in `framework.webhook.message_bus` (default `messenger.default_bus`). Without a Messenger route, the consumer runs during the webhook request. To run the consumer in a worker, route `ConsumeRemoteEventMessage` to an async transport in `framework.messenger.routing`. Entry point: `Symfony\Component\RemoteEvent\Messenger\ConsumeRemoteEventMessage`.
- **Email webhooks.** For twelve mailer bridges, FrameworkBundle registers a parser service with the ID `mailer.webhook.request_parser.<provider>`. The parsers create `MailerDeliveryEvent` objects (`received`, `dropped`, `delivered`, `deferred`, `bounce`) and `MailerEngagementEvent` objects (`open`, `click`, `spam`, `unsubscribe`). The service exists only when Mailer and Webhook are enabled and the bridge is installed. The bridges do not require `symfony/webhook`. Install it with `composer require symfony/webhook`. Entry point: `mailer.webhook.request_parser.mailgun` (the full list is under "Entry points").
- **SMS webhooks.** For five notifier bridges, FrameworkBundle registers a parser service with the ID `notifier.webhook.request_parser.<provider>`. The parsers create `SmsEvent` objects with the name `delivered` or `failed`. All parsers except the LOX24 parser set the recipient phone number. For an intermediate status, such as `sent`, the Twilio, Vonage and LOX24 parsers return `null`, and the controller answers with a 406. The Smsbox parser throws a `TypeError` for the codes `-1`, `9` and `10`. The LOX24 parser also creates a plain `RemoteEvent` for other LOX24 event types. For Twilio, set the status callback URL of a message with `TwilioOptions::webhookUrl()`. Entry point: `notifier.webhook.request_parser.twilio`.
- **The secret.** The meaning of `secret` depends on the provider. It can be an HMAC signing key, the `user:password` pair of HTTP Basic authentication (Brevo, Mailjet, Postmark), a token (LOX24) or a public key (SendGrid). With an empty secret, 11 of the 17 bridge parsers throw an `InvalidArgumentException`, and the provider gets a 500 response by default. The Brevo, Mailjet, Postmark, SendGrid and LOX24 parsers skip the secret check. Mailjet, SendGrid and LOX24 then accept requests from any sender. Brevo and Postmark still accept only requests from the provider IP addresses. The Smsbox parser does not use the secret. Always set the secret in production. Store it in the secrets vault or in an environment variable. Entry point: `framework.webhook.routing.<name>.secret`.
- **Replay and source checks.** The AhaSend, Mailgun, Resend, SendGrid (with a secret), Sweego and Vonage parsers reject a timestamp more than 300 seconds from the server time. The Mailomat parser uses a 12-hour limit. The Brevo, Postmark and Smsbox parsers accept requests only from the provider IP addresses in their `PROVIDER_IPS` constant. In debug mode, FrameworkBundle also allows `127.0.0.1` for Brevo and Postmark. The IP check reads `Request::getClientIp()`, and the Mandrill and Twilio signatures include the full request URL. Behind a reverse proxy, set `framework.trusted_proxies` and `framework.trusted_headers`. If you do not, these checks can see the proxy IP address or a wrong URL and reject valid requests. Entry point: the `$allowedIPs` constructor argument of these three parsers.
- **Sending webhooks.** Dispatch `new SendWebhookMessage(new Subscriber($url, $secret), new RemoteEvent($name, $id, $payload))` on the message bus. `SendWebhookHandler` calls the `webhook.transport` service, which sends a POST request with HttpClient. The request has a JSON body and the `Webhook-Event`, `Webhook-Id` and `Webhook-Signature` headers. By default, the signature is `sha256=` and the HMAC-SHA256 of the event name, event ID and body, with the subscriber secret. The transport waits for the response and throws an exception for a status code from 300 to 599. `Subscriber` refuses an empty secret. HttpClient is necessary. The Serializer is optional: without it, `json_encode()` creates the body. Entry point: `Symfony\Component\Webhook\Messenger\SendWebhookMessage`.
- **Header names, algorithm and custom transports.** The options `event_header_name`, `id_header_name`, `signature_header_name` and `signing_algorithm` (new in 8.1) change the headers and the HMAC algorithm, for example to `sha512`. The values apply to outgoing webhooks and to the built-in `RequestParser`. For another request format, implement `TransportInterface`, `RequestConfiguratorInterface` or `PayloadSerializerInterface`. The default transport has the service ID `webhook.transport` and no autowiring alias. Entry point: `framework.webhook.signing_algorithm`.
- **Parser tests.** Extend `AbstractRequestParserTestCase` and implement `createRequestParser()`. Its `testParse()` method runs once for each `Fixtures/*.json` file next to the test class. It compares the parser result with the object that the `.php` file of the same name returns. If the parser checks a signature, override `getSecret()` and `createRequest()`. For fixtures that are not JSON, override `getFixtureExtension()`. Entry point: `Symfony\Component\Webhook\Test\AbstractRequestParserTestCase`.

## Entry points

- Route import: `config/routes/webhook.yaml` with `resource: '@FrameworkBundle/Resources/config/routing/webhook.php'` and `prefix: /webhook`. The Flex recipe creates it. The route name is `_webhook_controller`, and the path is `/{type}`.
- `Symfony\Component\Webhook\Controller\WebhookController` (service `webhook.controller`): the class is `@internal`. Do not extend or call it. Configure it with `framework.webhook`.
- Configuration:
  - `framework.webhook.enabled`: enabled by default when `symfony/webhook` is installed.
  - `framework.webhook.message_bus`: default `messenger.default_bus`.
  - `framework.webhook.routing.<name>.service`: required.
  - `framework.webhook.routing.<name>.secret`: default `''`.
  - `framework.webhook.event_header_name` (default `Webhook-Event`), `framework.webhook.id_header_name` (default `Webhook-Id`) and `framework.webhook.signature_header_name` (default `Webhook-Signature`).
  - `framework.webhook.signing_algorithm`: default `sha256`.
  - `framework.remote_event.enabled`: enabled by default when `symfony/remote-event` is installed.
- Parser types: `Symfony\Component\Webhook\Client\RequestParserInterface`, `Symfony\Component\Webhook\Client\AbstractRequestParser` and `Symfony\Component\Webhook\Client\RequestParser` (service `webhook.request_parser`).
- `Symfony\Component\Webhook\Exception\RejectWebhookException`: throw it to reject a request. It extends `Symfony\Component\HttpKernel\Exception\HttpException`.
- Request matchers from HttpFoundation: `Symfony\Component\HttpFoundation\ChainRequestMatcher`, `Symfony\Component\HttpFoundation\RequestMatcherInterface`, `Symfony\Component\HttpFoundation\RequestMatcher\MethodRequestMatcher`, `Symfony\Component\HttpFoundation\RequestMatcher\IsJsonRequestMatcher`, `Symfony\Component\HttpFoundation\RequestMatcher\HeaderRequestMatcher` and `Symfony\Component\HttpFoundation\RequestMatcher\IpsRequestMatcher`. The parser examples in webhook.rst import `ChainRequestMatcher`, `RequestMatcherInterface` and `Autowire` from wrong namespaces and use `ParseException` without an import. Use the FQCNs in this list and `Symfony\Component\DependencyInjection\Attribute\Autowire`.
- Consumer side: `Symfony\Component\RemoteEvent\Consumer\ConsumerInterface`, `Symfony\Component\RemoteEvent\Attribute\AsRemoteEventConsumer` (tag `remote_event.consumer`), `Symfony\Component\RemoteEvent\RemoteEvent` (with `getName()`, `getId()` and `getPayload()`), `Symfony\Component\RemoteEvent\Messenger\ConsumeRemoteEventMessage`, `Symfony\Component\RemoteEvent\PayloadConverterInterface` and `Symfony\Component\RemoteEvent\Exception\ParseException`.
- Event classes: `Symfony\Component\RemoteEvent\Event\Mailer\MailerDeliveryEvent` (with `getReason()`), `Symfony\Component\RemoteEvent\Event\Mailer\MailerEngagementEvent` (both extend `AbstractMailerEvent` with `getDate()`, `getRecipientEmail()`, `getMetadata()` and `getTags()`) and `Symfony\Component\RemoteEvent\Event\Sms\SmsEvent` (with `getRecipientPhone()`).
- Sending: `Symfony\Component\Webhook\Messenger\SendWebhookMessage`, `Symfony\Component\Webhook\Subscriber`, `Symfony\Component\Webhook\Messenger\SendWebhookHandler` (service `webhook.messenger.send_handler`), `Symfony\Component\Webhook\Server\TransportInterface` (service `webhook.transport`), `Symfony\Component\Webhook\Server\RequestConfiguratorInterface` and `Symfony\Component\Webhook\Server\PayloadSerializerInterface` (services `webhook.payload_serializer.json` and `webhook.payload_serializer.serializer`).
- Console command: `make:webhook [name]` from MakerBundle. It writes `App\Webhook\<Name>RequestParser`, `App\RemoteEvent\<Name>WebhookConsumer` and an entry in `config/packages/webhook.yaml` with the placeholder secret `your_secret_here`.
- Test helper: `Symfony\Component\Webhook\Test\AbstractRequestParserTestCase`.
- Email parser services. Install the bridge package and `symfony/webhook`:
  - `mailer.webhook.request_parser.ahasend` (`symfony/aha-send-mailer`): HMAC-SHA256 signing key; 300-second timestamp limit.
  - `mailer.webhook.request_parser.brevo` (`symfony/brevo-mailer`): optional HTTP Basic `user:password`; Brevo IP addresses only.
  - `mailer.webhook.request_parser.mailchimp` (`symfony/mailchimp-mailer`, Mandrill): webhook key for the `X-Mandrill-Signature` HMAC-SHA1; form-encoded `mandrill_events`; one event for each item.
  - `mailer.webhook.request_parser.mailersend` (`symfony/mailer-send-mailer`): HMAC-SHA256 signing secret for the `Signature` header.
  - `mailer.webhook.request_parser.mailgun` (`symfony/mailgun-mailer`): HTTP webhook signing key; 300-second timestamp limit.
  - `mailer.webhook.request_parser.mailjet` (`symfony/mailjet-mailer`): optional HTTP Basic `user:password`. Do not group events in the Mailjet webhook settings.
  - `mailer.webhook.request_parser.mailomat` (`symfony/mailomat-mailer`): HMAC-SHA256 webhook secret; 12-hour timestamp limit.
  - `mailer.webhook.request_parser.mailtrap` (`symfony/mailtrap-mailer`): HMAC-SHA256 signing secret for the `Mailtrap-Signature` header; one event for each item.
  - `mailer.webhook.request_parser.postmark` (`symfony/postmark-mailer`): optional HTTP Basic `user:password`; Postmark IP addresses only.
  - `mailer.webhook.request_parser.resend` (`symfony/resend-mailer`): `whsec_` signing secret for the `svix-*` headers; 300-second timestamp limit.
  - `mailer.webhook.request_parser.sendgrid` (`symfony/sendgrid-mailer`): optional base64 public verification key, checked with OpenSSL; one event for each item.
  - `mailer.webhook.request_parser.sweego` (`symfony/sweego-mailer`): base64 signing secret for the `webhook-*` headers; 300-second timestamp limit.
- SMS parser services. Install the bridge package and `symfony/webhook`:
  - `notifier.webhook.request_parser.lox24` (`symfony/lox24-notifier`): optional token for the `X-LOX24-Token` header.
  - `notifier.webhook.request_parser.smsbox` (`symfony/smsbox-notifier`): GET requests from the Smsbox IP addresses; no secret.
  - `notifier.webhook.request_parser.sweego` (`symfony/sweego-notifier`): base64 signing secret for the `webhook-*` headers; 300-second timestamp limit.
  - `notifier.webhook.request_parser.twilio` (`symfony/twilio-notifier`): auth token for the `X-Twilio-Signature` HMAC-SHA1; form-encoded body.
  - `notifier.webhook.request_parser.vonage` (`symfony/vonage-notifier`): signature secret for the signed JWT in the `Authorization` header; 300-second limit.
- Class ownership, for `use` statements and `composer require`:
  - `symfony/webhook`: everything in `Symfony\Component\Webhook\`: `WebhookController`, `Client\RequestParserInterface`, `Client\AbstractRequestParser`, `Client\RequestParser`, `Exception\RejectWebhookException`, `Subscriber`, `Messenger\SendWebhookMessage`, `Messenger\SendWebhookHandler`, `Server\TransportInterface`, `Server\Transport`, the `Server\*Configurator` classes, `Server\PayloadSerializerInterface` and `Test\AbstractRequestParserTestCase`.
  - `symfony/remote-event` (a dependency of `symfony/webhook`): everything in `Symfony\Component\RemoteEvent\`: `RemoteEvent`, `Consumer\ConsumerInterface`, `Attribute\AsRemoteEventConsumer`, `PayloadConverterInterface`, `Messenger\ConsumeRemoteEventMessage`, `Messenger\ConsumeRemoteEventHandler`, the `Event\Mailer\*` and `Event\Sms\SmsEvent` classes and `Exception\ParseException`.
  - `symfony/framework-bundle`: the route file `webhook.php`, the `framework.webhook` and `framework.remote_event` options, all service IDs above and the `#[AsRemoteEventConsumer]` autoconfiguration.
  - Each mailer bridge: `Symfony\Component\Mailer\Bridge\<Provider>\Webhook\<Provider>RequestParser` and `Symfony\Component\Mailer\Bridge\<Provider>\RemoteEvent\<Provider>PayloadConverter`. Each notifier bridge: `Symfony\Component\Notifier\Bridge\<Provider>\Webhook\<Provider>RequestParser`.
  - `symfony/http-client`: `Symfony\Component\HttpClient\Messenger\PingWebhookMessage`. This class is not part of the Webhook package.

## Symbiotic packages

- [RemoteEvent](../packages/remote-event.md): RemoteEvent owns `RemoteEvent`, the consumer interface and attribute, the event classes and `ConsumeRemoteEventMessage`; Webhook requires it and turns each verified request into its events.
- [Messenger](../packages/messenger.md): The webhook controller dispatches `ConsumeRemoteEventMessage`, and `SendWebhookMessage` is a Messenger message. Route either one to an async transport to do the work in a worker.
- [HttpClient](../packages/http-client.md): The `webhook.transport` service sends outgoing webhooks with HttpClient. Do not confuse `SendWebhookMessage` with HttpClient `PingWebhookMessage`, which sends an unsigned request to check a URL.
- [Mailer](../packages/mailer.md): Twelve Mailer bridge packages provide the `mailer.webhook.request_parser.<provider>` parsers for delivery and engagement events.
- [Notifier](../packages/notifier.md): Five Notifier SMS bridge packages provide the `notifier.webhook.request_parser.<provider>` parsers for `SmsEvent`.
- [HttpFoundation](../packages/http-foundation.md): A parser gets the `Request` and uses the HttpFoundation request matchers to accept or reject it.
- [HttpKernel](../packages/http-kernel.md): `RejectWebhookException` extends the HttpKernel `HttpException`, so a rejected webhook gets an HTTP error status (406 by default).
- [Serializer](../packages/serializer.md): If the Serializer is enabled, it encodes the outgoing payload; else the transport uses `json_encode()`.
- [FrameworkBundle](../packages/framework-bundle.md): FrameworkBundle provides the `webhook.php` route file, the `framework.webhook` options, the services and the `#[AsRemoteEventConsumer]` autoconfiguration.
- [Routing](../packages/routing.md): The application imports the `webhook.php` route file with a prefix, and the `{type}` route parameter selects the parser.
- [MakerBundle](../packages/maker-bundle.md): `make:webhook` generates a parser, a consumer and the routing entry in `config/packages/webhook.yaml`.
- [Symfony Flex](../packages/flex.md): The `symfony/webhook` recipe creates `config/routes/webhook.yaml` with the `/webhook` prefix.

## Changed in 8.0/8.1

- `resource: '@FrameworkBundle/Resources/config/routing/webhook.xml'` -> `resource: '@FrameworkBundle/Resources/config/routing/webhook.php'`. Symfony 8.0 removed the XML route file.
- `public function createSuccessfulResponse(): Response` in a custom parser -> `public function createSuccessfulResponse(?Request $request = null): Response`. Also add `?Request $request = null` to `createRejectedResponse(string $reason)`. Symfony 8.0 added this argument to `RequestParserInterface`.
- `$config->webhook()->routing('acme')->service(...)->secret(...)` with `Symfony\Config\FrameworkConfig` -> YAML, or `App::config(['framework' => ['webhook' => ['routing' => ['acme' => ['service' => ..., 'secret' => env('ACME_SECRET')]]]]])`. Symfony 8.0 removed the fluent PHP configuration format. Three PHP examples in the webhook docs use it.
- `->routing(ConsumeRemoteEventMessage::class)->senders(['async'])` -> `'routing' => [ConsumeRemoteEventMessage::class => 'async']`. Symfony 8.1 deprecated the `senders` level in `framework.messenger.routing`.
- A redefined `webhook.signer` or `webhook.request_parser` service for other header names -> `framework.webhook.event_header_name`, `id_header_name`, `signature_header_name` and `signing_algorithm` (new in 8.1).
- `secret: ''` for the AhaSend, Mandrill, MailerSend, Mailtrap, Sweego or Twilio parser -> the provider signing key. Since 8.1.7, these parsers throw an exception for an empty secret. The Mailgun, Mailomat, Resend and Vonage parsers also throw this exception.
