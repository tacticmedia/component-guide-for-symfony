# UX Live Component (`symfony/ux-live-component`): details

**Applies to:** Symfony UX 3.5

## Key features and concepts

- **Live component:** `#[AsLiveComponent]` replaces `#[AsTwigComponent]` and makes the component re-render through Ajax. Add `DefaultActionTrait`, which gives the default action `__invoke()`. Render `{{ attributes }}` on the single root element of the template. The component is a Symfony controller, so actions can use autowiring, `#[IsGranted]` and the `AbstractController` shortcuts. Hook attributes run code at three stages of a request: `#[PostHydrate]` after the state arrives, `#[PreDehydrate]` before the state goes back, `#[PreReRender]` before a re-render. Entry point: `Symfony\UX\LiveComponent\Attribute\AsLiveComponent`, `Symfony\UX\LiveComponent\DefaultActionTrait`.
- **LiveProps (state):** a property with `#[LiveProp]` keeps its value between re-renders. Services do not need `#[LiveProp]`, because the container injects them again for each request. The bundle signs the props with an HMAC checksum (secret: `live_component.secret`). A LiveProp is read-only by default. If the user must change it, set `writable: true`. To allow only some object properties or array keys, set `writable: ['title', 'content']`. To also allow a different entity, add `LiveProp::IDENTITY` to this list. `onUpdated: 'onQueryUpdated'` calls a method with the previous value after the browser changes the prop. `modifier: 'modifyQueryProp'` changes the prop options at runtime with the immutable `with*()` methods. Entry point: `Symfony\UX\LiveComponent\Attribute\LiveProp`.
- **Prop types and hydration:** LiveProps accept scalars, arrays of scalars, backed enums, `DateTimeInterface` objects, UIDs, Doctrine entities and DTOs without constructor arguments. A persisted entity goes to the browser as its ID, and the bundle loads it again from the database. The entity support needs a `doctrine` service in the container. For a date field, set `format: 'Y-m-d'`; without `format`, dates use RFC 3339. For an array of objects, add a `@var Product[]` docblock. This docblock needs the `phpdocumentor/reflection-docblock` package. Union and intersection types are not supported. For other types, use `hydrateWith` and `dehydrateWith`, `useSerializerForHydration: true` or a `HydrationExtensionInterface` service. Entry point: `#[LiveProp(hydrateWith: 'hydrateAddress', dehydrateWith: 'dehydrateAddress')]`, `Symfony\UX\LiveComponent\Hydration\HydrationExtensionInterface`.
- **Data binding:** `data-model="query"` binds a field to a writable LiveProp. After an `input` event and a 150 ms pause, the component re-renders. The modifiers `on(change)`, `debounce(300)`, `norender`, `min_length(3)`, `max_length(10)`, `min_value(18)` and `max_value(100)` change this behavior. In a `<form data-model="*">`, the `name` attribute of each field selects the prop. A button with `data-action="live#$render"` forces a re-render. A button with `data-model`, `data-value` and `data-action="live#update"` sets a value. Entry point: the `data-model` HTML attribute.
- **Actions:** a method with `#[LiveAction]` runs when the user clicks an element with `data-action="live#action"` and `data-live-action-param="save"`. The Twig function `live_action('save')` renders these attributes. The browser sends a POST request, and the component re-renders after the action. For each argument, add a `data-live-<name>-param` attribute and `#[LiveArg]` on the parameter. The modifier `debounce(300)|save` waits 300 ms before the call. On a `<form>`, use `data-action="live#action:prevent"` to stop the normal submit. To upload files, add the `files` modifier (`files|save` or `files(my_file)|save`). The action reads the files from `$request->files`. If the action returns a redirect and Turbo is loaded, the browser follows it with `Turbo.visit()`. If the root element, or an element that contains it, has `data-turbo="false"`, the browser loads the redirect URL without Turbo. Entry point: `Symfony\UX\LiveComponent\Attribute\LiveAction`, `Symfony\UX\LiveComponent\Attribute\LiveArg`.
- **CSRF protection:** each request sends `Accept: application/vnd.live-component+html` and `X-Requested-With: XMLHttpRequest`. The bundle handles a request on the component route only when both headers are present. Because of these headers, the same-origin and CORS rules of the browser block cross-site requests, so no CSRF token is necessary. Do not send `Access-Control-Allow-Origin: *`. In test mode (when a `test.client` service exists), the bundle skips this check. Entry point: none (automatic); for a client on another origin, allow `X-Requested-With` in `Access-Control-Allow-Headers`.
- **LiveResponse (UX 3.5):** an action can return `LiveResponse::downloadUrl($url)` or `LiveResponse::downloadFile($content, 'report.csv', 'text/csv')` to start a download, and the component still re-renders. `downloadFile()` accepts a string (always the content, never a path), an `SplFileInfo`, a stream resource or a `Closure`. It streams all types except a string. If a route can serve the file, prefer `downloadUrl()`. `LiveResponse::remove()` does one final render and then removes the component from the page. To animate the removal, style `[data-live-removing]` in CSS. Return a `LiveResponse` only from a `LiveAction` or a `LiveListener` over POST. From the default action or a GET request, it causes a `LogicException`. Entry point: `Symfony\UX\LiveComponent\LiveResponse`.
- **Forms:** `ComponentWithFormTrait` renders a Symfony form in the component. Implement `instantiateForm()`. The trait keeps the raw field values in the writable LiveProp `formValues` and submits the form on each re-render. The trait puts `data-model="on(change)|*"` on the `<form>`, so the component re-renders after each `change` event and shows the errors of the changed fields. In a save action, call `$this->submitForm()`. If the form is not valid, the component re-renders with the errors. To change a field from an action, change `$this->formValues['title']`. To reset the form to its initial state after a save, call `$this->resetForm()`. If a text field re-renders on each `input` event, set its `trim` option to `false`. Entry point: `Symfony\UX\LiveComponent\ComponentWithFormTrait`.
- **Form collections:** `LiveCollectionType` has the parent type `CollectionType`, so options such as `entry_type` work. It renders one "add" button for the collection and one "delete" button for each row. Use `LiveCollectionTrait` in the component: it includes `ComponentWithFormTrait` and the `addCollectionItem` and `removeCollectionItem` actions. `{{ form(form) }}` then renders a working collection. The options `button_add_options` and `button_delete_options` change the buttons. Entry point: `Symfony\UX\LiveComponent\Form\Type\LiveCollectionType`, `Symfony\UX\LiveComponent\LiveCollectionTrait`.
- **Validation without a form:** `ValidatableComponentTrait` validates the LiveProps with Validator constraint attributes. After each update from the browser, it validates only the fields that the user changed. `validate()` validates all fields and throws an exception if a constraint fails. The component then re-renders, and the template reads the errors from `_errors` (`_errors.has('email')`, `_errors.get('email')`). After a `validate()` call, each re-render validates all fields again. To validate the initial render, call `$this->validate(throw: false)` in a `#[PostMount]` method. `validateField()` returns `void`. To read its result, call `getError('email')`, which returns `null` for a valid field. Use `isValid()` only after `validate()`, because after a field validation it returns `false` also for valid fields. `clearValidation()` resets the validation state. Entry point: `Symfony\UX\LiveComponent\ValidatableComponentTrait`.
- **Events:** with `ComponentToolsTrait`, an action calls `$this->emit('productAdded', ['product' => $id])`. Each component on the page with a `#[LiveListener('productAdded')]` method then calls this method and re-renders. The method receives the data through `#[LiveArg]` arguments. `emitUp()` sends the event only to parent components, and `emitSelf()` only to the same component. The `componentName` argument limits the event to components with that name. `dispatchBrowserEvent('modal:close')` dispatches a DOM event on the root element, with the data in `event.detail`. Entry point: `Symfony\UX\LiveComponent\ComponentToolsTrait`, `Symfony\UX\LiveComponent\Attribute\LiveListener`.
- **Loading states:** while a request runs, `data-loading` shows or hides an element, or adds or removes classes or empty attributes. The modifiers `delay` (200 ms by default), `action(save)` and `model(email)` limit this behavior. The root element also gets `aria-busy="true"` for CSS and screen readers. Entry point: `data-loading="delay|addClass(opacity-50)"`.
- **Deferred, lazy and polled rendering:** with `loading: 'defer'`, the page shows a placeholder and loads the component through Ajax after the page loads. With `loading: 'lazy'`, the load starts when the component enters the viewport. A `placeholder` macro, a `loading-template` or a `loadingContent` block gives the placeholder content. The component is still mounted on the first request, so put slow work in methods that the template calls. `data-poll` on the root element re-renders the component every 2 seconds. `data-poll="delay(5000)|$render"` changes the interval, and `data-poll="save"` calls an action. Entry point: `<twig:Name loading="lazy" />`, `{{ component('Name', {loading: 'defer'}) }}`, `data-poll`.
- **URL binding:** `#[LiveProp(writable: true, url: true)]` reads the initial value from the query string. It writes each change back to the URL with `history.replaceState()`. `url: new UrlMapping(as: 'q')` sets the parameter name. `new UrlMapping(mapPath: true)` writes the value into the route parameter of the same name. The bundle does not validate the initial URL value. Validate it in a `#[PostMount]` method. Entry point: `Symfony\UX\LiveComponent\Metadata\UrlMapping`.
- **Nested components and morphing:** each component re-renders on its own. `#[LiveProp(updateFromParent: true)]` updates a child prop when the parent passes a new value, and the child re-renders. `dataModel: 'content'` (or `'content:value'`) binds a child model to a parent model. Give each child component in a loop a unique `key`. The browser morphs the new HTML into the page with idiomorph. Attribute changes and new elements from other JavaScript stay in place. `data-live-ignore` keeps an element unchanged, and `data-skip-morph` replaces the inner HTML of an element. Entry point: `#[LiveProp(updateFromParent: true)]`, `{{ component('Child', {key: item.id}) }}`.

## Entry points

- `#[Symfony\UX\LiveComponent\Attribute\AsLiveComponent]`: arguments `name`, `template` (a path or `new FromMethod('getTemplate')`), `defaultAction`, `exposePublicProps`, `attributesVar`, `route` (default `ux_live_component`), `method` (`post` by default, or `get`), `urlReferenceType`, `fetchCredentials`.
- `#[Symfony\UX\LiveComponent\Attribute\LiveProp]`: arguments `writable`, `hydrateWith`, `dehydrateWith`, `useSerializerForHydration`, `serializationContext`, `fieldName`, `format`, `updateFromParent`, `onUpdated`, `url`, `modifier`; constant `LiveProp::IDENTITY`; immutable `with*()` methods for a `modifier` method.
- Other attributes in `Symfony\UX\LiveComponent\Attribute`: `#[LiveAction]`, `#[LiveArg]`, `#[LiveListener('eventName')]` (repeatable), `#[PostHydrate]`, `#[PreDehydrate]`, `#[PreReRender]` (the hooks take a `priority`).
- Traits in `Symfony\UX\LiveComponent`: `DefaultActionTrait`, `ComponentToolsTrait`, `ComponentWithFormTrait`, `LiveCollectionTrait`, `ValidatableComponentTrait`.
- `Symfony\UX\LiveComponent\LiveResponse`: `remove()`, `downloadUrl()`, `downloadFile()`.
- `Symfony\UX\LiveComponent\Metadata\UrlMapping`: arguments `as` and `mapPath`.
- `Symfony\UX\LiveComponent\Form\Type\LiveCollectionType`: options `button_add_type`, `button_add_options`, `button_delete_type`, `button_delete_options`.
- `Symfony\UX\LiveComponent\Hydration\HydrationExtensionInterface`: autoconfigured; without autoconfiguration, tag the service `live_component.hydration_extension`.
- Config (in the CHANGELOG, not in the docs page): `live_component.secret` (default `%kernel.secret%`; signs the props checksum) and `live_component.fetch_credentials` (`same-origin` by default, `include`, `omit`; `#[AsLiveComponent(fetchCredentials: ...)]` overrides it).
- Route `ux_live_component` (path `/{_live_component}/{_live_action}` in `@LiveComponentBundle/config/routes.php`). The Flex recipe imports it in `config/routes/ux_live_component.yaml` with the prefix `/_components`. For localized URLs, change the prefix to `/{_locale}/_components`.
- Console: `debug:live-component [name] [--listening=<event>]` (not in the docs), `debug:twig-component` (the Type column shows `Live`), `make:twig-component --live <Name>` (MakerBundle).
- Twig: `{{ attributes }}` on the root element; `component('Name', {...})` or `<twig:Name />`; `live_action('save', {id: 1}, {debounce: 300})`; `component_url('Name', {...})` (the URL of the component route, with the props; not in the docs); the variables `this`, `form` (`ComponentWithFormTrait`) and `_errors` (`ValidatableComponentTrait`); the `placeholder(props)` macro.
- HTML attributes: `data-model`, `data-value` with `live#update`, `data-action="live#action"` with `data-live-action-param` and `data-live-<name>-param`, `live#$render`, `live#emit`, `live#emitUp` and `live#emitSelf` with `data-live-event-param`, `data-loading`, `data-poll`, `data-live-ignore`, `data-skip-morph`, `key`, `id`.
- JavaScript: `await getComponent(element)` from `@symfony/ux-live-component` gives the `Component` object (`set()`, `render()`, `action()`, `emit()`, `on()`). Hooks: `connect`, `disconnect`, `render:started`, `render:finished`, `response:error`, `loading.state:started`, `loading.state:finished`, `model:set`. Do not name an action `then` or `toJSON`.
- Tests: `Symfony\UX\LiveComponent\Test\InteractsWithLiveComponents` in a `KernelTestCase`. `createLiveComponent($name, $data, $client)` returns a `TestLiveComponent` (`render()`, `call($action, $arguments, $files)`, `set()`, `emit()`, `submitForm()`, `refresh()`, `component()`, `response()`, `actingAs($user)`). The assertions `assertComponentEmitEvent()`, `assertComponentNotEmitEvent()`, `assertComponentDispatchBrowserEvent()` and `assertComponentNotDispatchBrowserEvent()` take the `TestLiveComponent` object, not the `render()` result. `withData()` and `withPayload()` return `void`, so call them last.

## Symbiotic packages

- [UX Twig Component](../packages/ux-twig-component.md): `AsLiveComponent` extends `AsTwigComponent`, so props, `mount()` and `<twig:>` work the same, and a component that never re-renders needs only UX Twig Component.
- [StimulusBundle](../packages/stimulus-bundle.md): this bundle requires StimulusBundle, and `{{ attributes }}` adds `data-controller="live"`, the Stimulus controller that sends the requests and morphs the HTML.
- [Form](../packages/form.md): `ComponentWithFormTrait` submits a Symfony form on each re-render and shows its errors, and `LiveCollectionType` (parent type `CollectionType`) adds "add" and "delete" buttons.
- [Validator](../packages/validator.md): `ValidatableComponentTrait` and forms in live components validate with Validator constraints after each change; `#[Assert\Valid]` also validates a nested object.
- [Serializer](../packages/serializer.md): `#[LiveProp(useSerializerForHydration: true)]` sends a prop through the Serializer, with an optional `serializationContext`.
- [Uid](../packages/uid.md): a LiveProp can hold a `Uuid` or `Ulid` (any `AbstractUid`), and the bundle sends it to the browser as a string.
- [PropertyAccess](../packages/property-access.md): this bundle requires PropertyAccess to read and write DTO props and writable paths such as `post.title`.
- [PropertyInfo](../packages/property-info.md): this bundle requires PropertyInfo, which reads collection types of LiveProps, for example a `@var Product[]` docblock.
- [TypeInfo](../packages/type-info.md): this bundle requires TypeInfo, whose `TypeResolver` converts the PHP type of each LiveProp into a `Type`.
- [Symfony UX Turbo](../packages/ux-turbo.md): Turbo handles page navigation, Turbo Frames, Turbo Streams and Mercure broadcasts, while a live component keeps state and re-renders on each input.
- [UX Map](../packages/ux-map.md): `ComponentWithMapTrait` (`instantiateMap()`, `getMap()`) renders a map in a live component, and a `LiveAction` changes the map.
- [Symfony UX Pagination](../packages/ux-pagination.md): `ComponentWithPaginationTrait` adds a URL-bound `page` LiveProp and the actions `goToPage()`, `nextPage()` and `previousPage()`; UX Pagination is experimental.
- [MakerBundle](../packages/maker-bundle.md): `make:twig-component --live` generates a live component class and its template.
- [FrameworkBundle test tools](../packages/framework-bundle-testing.md): `InteractsWithLiveComponents` works only in a `KernelTestCase` and sends its requests through the `test.client` service.
- [Security](../packages/security-bundle.md): live components are controllers, so `#[IsGranted]` protects a class or an action, and `TestLiveComponent::actingAs()` logs in a user in a test.
- [Routing](../packages/routing.md): a custom route and `#[AsLiveComponent(route: 'live_component_admin')]` put a component behind a firewall, and `urlReferenceType` sets the URL type.
- [AssetMapper](../packages/asset-mapper.md): with AssetMapper, the bundle registers its JavaScript and needs no build step.
- [WebpackEncoreBundle](../packages/webpack-encore-bundle.md): with Webpack Encore, run `npm install --force` and restart Encore after you install the bundle.
- [CssSelector](../packages/css-selector.md): the `TestLiveComponent` methods `call()`, `set()`, `emit()`, `refresh()`, `submitForm()` and `component()` and the `assertComponent*()` event assertions use `Crawler::filter()`, so they need CssSelector.
- [DomCrawler](../packages/dom-crawler.md): `TestLiveComponent` needs DomCrawler to read the component props, and its `render()` method returns a `RenderedComponent` with a `crawler()` method.

## Changed in UX 2.0 to 3.5

UX packages have their own versions. UX 3.0 requires PHP 8.4 and Symfony 7.4 or 8.x.
- UX 3.5 adds `LiveResponse::downloadUrl()`, `LiveResponse::downloadFile()` and `LiveResponse::remove()` -> return them from an action instead of a temporary file plus a redirect, or JavaScript that calls `element.remove()`.
- UX 2.36 and 3.1 require the `X-Requested-With: XMLHttpRequest` header (the `live` controller sends it) -> if a client on another origin calls the component route, add `X-Requested-With` to `Access-Control-Allow-Headers`.
- UX 3.0 removes the `csrf` argument of `#[AsLiveComponent]` (UX 2.22 removed the CSRF tokens) -> remove `csrf: false`; the same-origin and CORS rules protect the actions.
- UX 2.17 deprecates the `defer` attribute, and no 3.5.1 code reads it -> `{{ component('Name', {loading: 'defer'}) }}` or `loading: 'lazy'`.
- UX 2.16 removes `data-action-name="save"` -> `data-live-action-param="save"`; `data-event` -> `data-live-event-param`; `addItem(id=1)` arguments -> `data-live-id-param="1"`; `prevent|save` -> `data-action="live#action:prevent"`.
- UX 2.15 changes `data-live-id` -> `id` (a child component gets its `id` from the `key` prop).
- UX 2.8 renames `#[LiveProp(exposed: ['email'])]` -> `#[LiveProp(writable: ['email'])]`. The 2.8 CHANGELOG names `acceptUpdatesFromParent: true`, but the 3.5.1 argument is `updateFromParent: true`.
- UX 2.1 removes `{{ init_live_component() }}` -> `{{ attributes }}`, and renames `#[BeforeReRender]` -> `#[PreReRender]`; UX 2.0 replaces `LiveComponentInterface` -> `#[AsLiveComponent]`.
