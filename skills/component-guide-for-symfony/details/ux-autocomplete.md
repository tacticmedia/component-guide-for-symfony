# UX Autocomplete (`symfony/ux-autocomplete`): details

**Applies to:** Symfony UX 3.5

## Key features and concepts

- **Local autocomplete:** `'autocomplete' => true` turns a `ChoiceType`, `EntityType`, `EnumType` or `TextType` field into a Tom Select control. A form type extension on `ChoiceType` and `TextType` adds the Stimulus controller to the field. All options stay in the page, and the browser filters them. Entry point: the `autocomplete` form option.
- **Ajax entity field:** a form type with `#[AsEntityAutocompleteField]` and a `getParent()` that returns `BaseEntityAutocompleteType` gets its own Ajax endpoint. The field renders only the selected entities, because the type wraps the choice loader in a `LazyChoiceLoader`. Put the `EntityType` options (`class`, `query_builder`, `choice_label`, `choice_value`) in `configureOptions()` of this class. The Ajax call does not use the options of the third `->add()` argument. Entry point: `Symfony\UX\Autocomplete\Form\BaseEntityAutocompleteType`.
- **Entity search:** without `searchable_fields`, the endpoint searches all fields of the entity. It uses a case-insensitive `LIKE` on text fields and an exact match on number, UUID and ULID fields. The endpoint escapes `%` and `_` in the user input. `searchable_fields` limits the fields and accepts relations with a dot (`category.name`). `filter_query` replaces the search with a callable `function (QueryBuilder $qb, string $query, EntityRepository $repository)`. It ignores `max_results`, and a `RuntimeException` occurs if you also set `searchable_fields`. The bundle does not support entities with a composite primary key. Entry point: the `searchable_fields` and `filter_query` options.
- **Ajax choice field for any data source (UX 3.5):** a form type with `#[AsAutocompleteField]` and a `getParent()` that returns `AutocompleteChoiceType` needs no Doctrine. The parent type of `AutocompleteChoiceType` is `ChoiceType`, so `choices` and the other `ChoiceType` options apply to the rendered field. Unlike `BaseEntityAutocompleteType`, the field renders all choices in the page. The endpoint uses the key of each `choices` entry as the label, and ignores `choice_label` and `group_by`. It filters the choices by a case-insensitive substring of the label and returns them page by page. For each request, it loads all choices of the field. Entry point: `Symfony\UX\Autocomplete\Form\AutocompleteChoiceType`.
- **Endpoint route and alias:** each field class gets the alias of its short class name in snake case, for example `food_autocomplete_field`. The `ux_autocomplete` route serves all aliases, at `/autocomplete/{alias}` with the Flex recipe. The `alias` and `route` arguments of the attribute change the alias and the route. If the endpoint must be behind a specific firewall, declare a route with the path `/admin/autocomplete/{alias}`. Set its controller to the service ID `ux.autocomplete.autocomplete_controller`, as the bundle route does. Then set the `route` argument to the name of this route. The docs use the class name `AutocompleteController` as the controller, but the bundle registers no service with that ID. Entry point: `#[AsEntityAutocompleteField(route: 'ux_autocomplete_admin')]`, `#[AsAutocompleteField(alias: 'country')]`.
- **Endpoint security:** the endpoint is public by default (`'security' => false`). Set `security` to a role, or to a callable that receives `Symfony\Bundle\SecurityBundle\Security` and returns a bool. If the check fails, the endpoint throws an `AccessDeniedException`. The bundle runs the check only if the application has SecurityBundle. Entry point: the `security` option of `BaseEntityAutocompleteType` and `AutocompleteChoiceType`.
- **Signed extra options:** for the Ajax call, the bundle creates the field form again with only the `extra_options` option. Use `extra_options` for values from the parent form, for example IDs to exclude. It accepts scalars, `null` and arrays of them. The bundle signs the values with an HMAC that uses `kernel.secret`, and a changed value causes an HTTP 400 response. Read the values in a lazy option closure, from `$options['extra_options']`. Entry point: the `extra_options` option.
- **Custom autocompleter without a form (UX 3.5):** implement `AutocompleterInterface`: `fetchResults(string $query, int $page): AutocompleteResults` and `isGranted(Security $security): bool`. Tag the service with `#[AutoconfigureTag('ux.autocompleter', ['alias' => 'food'])]`. The bundle does not autoconfigure the interface. Use it for an API or a search index, because `AutocompleteChoiceType` loads all choices of the field for each request. For Doctrine entities, implement `EntityAutocompleterInterface` and use the tag `ux.entity_autocompleter`. Entry point: `Symfony\UX\Autocomplete\AutocompleterInterface`.
- **Endpoint JSON:** the endpoint reads the `query` and `page` query parameters. It returns `{"results": [{"value": "1", "text": "Pizza"}], "next_page": "<URL or null>"}`. If an entity field has a `group_by` option, `results` contains `options` (each with a `group_by` list) and `optgroups`. UX 3.5 translates the optgroup labels with the `choice_translation_domain` of the field. An unknown alias gives HTTP 404. A custom endpoint for `autocomplete_url` must return `results`; `next_page` is optional. Entry point: `Symfony\UX\Autocomplete\AutocompleteResults`.
- **Paging and loading:** each response holds at most `max_results` items (default 10). When the user scrolls to the end of the list, the `virtual_scroll` plugin loads `next_page`. `min_characters` sets the query length that starts a search. If you do not set it, only the first non-empty search text needs 3 characters. With `preload` at its default `focus`, an Ajax field loads the first page when it gets focus. `max_options` (UX 3.5) caps the options that the dropdown shows; an Ajax field shows at most 50 by default. Entry point: the `max_results`, `min_characters`, `preload` and `max_options` options.
- **Tom Select options and plugins:** `tom_select_options` passes Tom Select settings as JSON, for example `create`, `createOnBlur` and `delimiter` for a tag input on a `TextType`. The control adds `clear_button` to a single select that is not disabled, `remove_button` to a multiple select or an input, and `virtual_scroll` for Ajax. To remove a default plugin, set it to `false` in `tom_select_options.plugins`. For Bootstrap 5, enable `tom-select/dist/css/tom-select.bootstrap5.css` instead of the default CSS in `assets/controllers.json`. Entry point: the `tom_select_options` option.
- **JavaScript events:** some Tom Select settings need JavaScript, for example an `onChange` callback. For these settings, write a Stimulus controller that listens to the events of the core controller. `autocomplete:pre-connect` gives `event.detail.options` before Tom Select starts, and `autocomplete:connect` gives `event.detail.tomSelect`. Add the controller with `'attr' => ['data-controller' => 'custom-autocomplete']`. Load it eagerly (remove `/* stimulusFetch: 'lazy' */`). The core controller also dispatches `autocomplete:before-reset` (not in the docs). Entry point: the `autocomplete:pre-connect` and `autocomplete:connect` DOM events.
- **Stimulus controller without a form:** `{{ stimulus_controller('symfony/ux-autocomplete/autocomplete') }}` on a `<select>` or `<input>` activates Tom Select. To load the options through Ajax, add the `url` value, for example `path('ux_autocomplete', {alias: 'food'})`. Entry point: the `symfony/ux-autocomplete/autocomplete` Stimulus controller.
- **Live Component integration (not in the docs):** the controller adds `data-skip-morph` to its `<select>`, so a Live Component re-render replaces the options instead of morphing them. If the controller has no `url` and no `optionsAsHtml` value, a `MutationObserver` rebuilds Tom Select when the options or the placeholder change. This observer also follows the `disabled` attribute. A new `url` value, for example with new extra options, also rebuilds the control. When the controller disconnects, it keeps the selected values on the `<select>`. Entry point: none; the behavior is automatic, for example in a `ComponentWithFormTrait` form.
- **Escaping and texts:** the control escapes the `text` of Ajax results. If the results contain trusted HTML, set `options_as_html` to `true`. The texts `loading_more_text`, `no_results_found_text`, `no_more_results_text` and `create_option_text` use the `AutocompleteBundle` translation domain. The bundle has translations for 33 locales. Entry point: the `options_as_html` option.

## Entry points

- `composer require symfony/ux-autocomplete`: configure StimulusBundle first. The Flex recipe enables `Symfony\UX\Autocomplete\AutocompleteBundle` and creates `config/routes/ux_autocomplete.yaml`. This file imports `@AutocompleteBundle/config/routes.php` with the prefix `/autocomplete`. With Webpack Encore, run `npm install --force` and restart Encore. AssetMapper needs no step.
- Form options on `ChoiceType` and `TextType`, so also on `EntityType` and `EnumType`: `autocomplete`, `autocomplete_url`, `tom_select_options`, `options_as_html`, `max_results` (10), `max_options` (UX 3.5), `min_characters`, `preload` (`focus`, `true` or `false`), `extra_options`, `loading_more_text`, `no_results_found_text`, `no_more_results_text`.
- Form options that the docs do not list: `reset_on_focus` (UX 2.35) and `create_option_text`. With `reset_on_focus`, an Ajax field clears and reloads its options when it gets focus with an empty search text. Do not use `allow_options_create`: the Stimulus controller does not read it. Use `tom_select_options.create` instead.
- `Symfony\UX\Autocomplete\Form\BaseEntityAutocompleteType`: parent `EntityType`. It adds `searchable_fields`, `filter_query`, `security`, `max_results` and `additional_attributes` (an array or a callable that receives the entity; not in the docs). Block prefix: `ux_entity_autocomplete`.
- `Symfony\UX\Autocomplete\Form\AutocompleteChoiceType` (UX 3.5): parent `ChoiceType`. It adds `security` and `max_results`. Block prefix: `ux_autocomplete_choice`.
- `#[Symfony\UX\Autocomplete\Form\AsEntityAutocompleteField]` and `#[Symfony\UX\Autocomplete\Form\AsAutocompleteField]` (UX 3.5): arguments `alias` (default: the short class name in snake case) and `route` (default `ux_autocomplete`). The class must also be a form type. If it is not a form type, a `LogicException` occurs when the container compiles.
- `Symfony\UX\Autocomplete\AutocompleterInterface` and `Symfony\UX\Autocomplete\OptionsAwareAutocompleterInterface` (UX 3.5; adds `setOptions(array $options)`): service tag `ux.autocompleter` with an `alias` attribute.
- `Symfony\UX\Autocomplete\EntityAutocompleterInterface`: implement `getEntityClass()`, `createFilteredQueryBuilder()`, `getLabel()`, `getValue()`, `getAttributes()`, `isGranted()` and `getGroupBy()`. `getTranslationDomain()` is optional (UX 3.5). `Symfony\UX\Autocomplete\OptionsAwareEntityAutocompleterInterface` adds `setOptions()`. Service tag: `ux.entity_autocompleter` with an `alias` attribute.
- `Symfony\UX\Autocomplete\AutocompleteResults`: constructor arguments `array $results`, `bool $hasNextPage`, `array $optgroups = []`.
- Route `ux_autocomplete` (path `/{alias}`, controller service `ux.autocomplete.autocomplete_controller`, class `Symfony\UX\Autocomplete\Controller\AutocompleteController`). The route alias `ux_entity_autocomplete` is deprecated since UX 3.5.
- Stimulus controller `symfony/ux-autocomplete/autocomplete` (HTML: `data-controller="symfony--ux-autocomplete--autocomplete"`). Values: `url`, `optionsAsHtml`, `tomSelectOptions`, `minCharacters`, `maxOptions`, `preload`, `resetOnFocus`, `loadingMoreText`, `noResultsFoundText`, `noMoreResultsText`, `createOptionText`. DOM events: `autocomplete:pre-connect`, `autocomplete:connect`, `autocomplete:before-reset`.
- Twig: `stimulus_controller()` (StimulusBundle) and `path('ux_autocomplete', {alias: 'food'})`. The bundle adds the form theme `@Autocomplete/autocomplete_form_theme.html.twig`. Form themes can read the view variable `uses_autocomplete`.
- Assets: the `autoimport` keys in `assets/controllers.json` are `tom-select/dist/css/tom-select.default.css` (on), `tom-select/dist/css/tom-select.bootstrap4.css` and `tom-select/dist/css/tom-select.bootstrap5.css` (off). The npm package `@symfony/ux-autocomplete` is for advanced setups, and its version must match the PHP package exactly. Peer dependency: `tom-select` `^2.2.2`.
- Console: `make:autocomplete-field` (MakerBundle). It asks for the Entity (Doctrine) or the Choice (any data source) mode, and Entity is the default. If the application has no Doctrine ORM, select Choice. The docs say that the command then uses Choice without a question. It asks, because MakerBundle always registers `maker.doctrine_helper`.
- Translation domain: `AutocompleteBundle`. The bundle has no configuration keys.
- Form unit tests: in a `TypeTestCase`, return `new AutocompleteChoiceTypeExtension(new ChecksumCalculator('secret'))` from `getTypeExtensions()`. The docs example omits the required `Symfony\UX\Autocomplete\Checksum\ChecksumCalculator`. `Symfony\UX\Autocomplete\Form\AutocompleteChoiceTypeExtension` and `ChecksumCalculator` are both `@internal`.

## Symbiotic packages

- [StimulusBundle](../packages/stimulus-bundle.md): the docs require StimulusBundle; with AssetMapper, it loads the controller and the CSS that `autoimport` enables in `assets/controllers.json`, and gives `stimulus_controller()`.
- [Form](../packages/form.md): the `autocomplete` option is a type extension of `ChoiceType` and `TextType`, and each Ajax field is a form type; both need `symfony/form`.
- [Doctrine Bridge](../packages/doctrine-bridge.md): the parent of `BaseEntityAutocompleteType` is `EntityType`, so the endpoint uses `class`, `query_builder`, `choice_label`, `choice_value` and `group_by`; the entity features need Doctrine ORM and DoctrineBundle.
- [Security](../packages/security-bundle.md): the `security` option and `isGranted()` receive `Symfony\Bundle\SecurityBundle\Security`; without SecurityBundle, the endpoint runs no access check.
- [UX Live Component](../packages/ux-live-component.md): an autocomplete field works in a `ComponentWithFormTrait` form, because the controller sets `data-skip-morph` and rebuilds Tom Select after a re-render changes the options.
- [MakerBundle](../packages/maker-bundle.md): `make:autocomplete-field` generates the Ajax field class in `src/Form/`.
- [AssetMapper](../packages/asset-mapper.md): the bundle adds its `assets/dist` directory to AssetMapper as `@symfony/ux-autocomplete`, so no build step is necessary.
- [WebpackEncoreBundle](../packages/webpack-encore-bundle.md): with Webpack Encore, run `npm install --force` and restart Encore after you install the bundle.
- [Translation](../packages/translation.md): the translator translates the UI texts in the `AutocompleteBundle` domain and, since UX 3.5, the optgroup labels of the endpoint.
- [TwigBundle](../packages/twig-bundle.md): if the application has TwigBundle, the bundle adds `@Autocomplete/autocomplete_form_theme.html.twig` to the form themes.
- [Routing](../packages/routing.md): the Flex recipe imports `@AutocompleteBundle/config/routes.php` with the prefix `/autocomplete`; a custom route to the `ux.autocomplete.autocomplete_controller` service puts the endpoint behind another firewall.
- [Uid](../packages/uid.md): if the application has `symfony/uid`, the entity search matches a UUID or ULID query exactly against `uuid`, `guid` and `ulid` fields.
- [PropertyAccess](../packages/property-access.md): this bundle requires PropertyAccess, which reads the `choice_label`, `choice_value` and `group_by` property paths in the endpoint.
- [Console](../packages/console.md): `Question::setAutocompleterValues()` and `setAutocompleterCallback()` autocomplete answers in a terminal prompt; use UX Autocomplete for HTML form fields.
- [UX Toolkit](../packages/ux-toolkit.md): the `Combobox` component of the shadcn kit filters a static `choices` list in the browser; use UX Autocomplete for form fields and Ajax search.

## Changed in UX 2.6 to 3.5

UX packages have their own versions. UX 3.0 requires PHP 8.4 and Symfony 7.4 or 8.x.
- UX 3.5 adds `AutocompleterInterface`, `AutocompleteChoiceType` and `#[AsAutocompleteField]` -> use them instead of a custom JSON controller for a source that is not Doctrine ORM.
- UX 3.5 deprecates the route alias `ux_entity_autocomplete` -> `path('ux_autocomplete', {alias: 'food'})`; a custom route uses the controller service `ux.autocomplete.autocomplete_controller`.
- UX 3.5 adds the `max_options` option, translated optgroup labels and the optional `EntityAutocompleterInterface::getTranslationDomain()` method.
- UX 3.0 removes `ParentEntityAutocompleteType` -> return `BaseEntityAutocompleteType::class` from `getParent()`.
- UX 3.0 removes `ExtraLazyChoiceLoader` -> `Symfony\Component\Form\ChoiceList\Loader\LazyChoiceLoader` (symfony/form 7.2 or later).
- UX 3.0 makes `getAttributes()` and `getGroupBy()` required in `EntityAutocompleterInterface` -> implement both methods; `[]` and `null` mean no attributes and no groups.
- UX 2.36 and 3.1 escape the `text` of Ajax results -> if the text contains trusted HTML, set `options_as_html` to `true`.
- UX 2.6 moves the routes file: `@AutocompleteBundle/Resources/routes.php` -> `@AutocompleteBundle/config/routes.php`.
