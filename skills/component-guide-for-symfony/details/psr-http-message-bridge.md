# PSR-7 Bridge (`symfony/psr-http-message-bridge`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **HttpFoundation to PSR-7:** `PsrHttpFactory::createRequest()` converts a Symfony `Request` into a PSR-7 `ServerRequestInterface` object. `PsrHttpFactory::createResponse()` converts a Symfony `Response` into a PSR-7 `ResponseInterface` object. The class implements `HttpMessageFactoryInterface`. If you create the `Request` with `new Request()`, set the `HTTP_HOST` server key to prevent an error. `Request::create()` sets `HTTP_HOST` to `localhost` by default. Entry point: `Symfony\Bridge\PsrHttpMessage\Factory\PsrHttpFactory`.
- **PSR-17 factories:** `PsrHttpFactory` creates the PSR-7 objects with four PSR-17 factories: a server request factory, a stream factory, an uploaded file factory and a response factory. `Nyholm\Psr7\Factory\Psr17Factory` from `nyholm/psr7` implements the four interfaces, so the docs give the same object four times. If you omit a factory argument, the constructor uses `Http\Discovery\Psr17Factory` from `php-http/discovery`, or else `Nyholm\Psr7\Factory\Psr17Factory`. `Http\Discovery\Psr17Factory` finds an installed PSR-17 implementation. If neither class exists, the constructor throws a `\LogicException`. `DiactorosFactory` does not exist. Use `PsrHttpFactory`. Entry point: `new PsrHttpFactory($psr17Factory, $psr17Factory, $psr17Factory, $psr17Factory)` or `new PsrHttpFactory()`.
- **PSR-7 to HttpFoundation:** `HttpFoundationFactory::createRequest()` converts a PSR-7 `ServerRequestInterface` object into a Symfony `Request`. `HttpFoundationFactory::createResponse()` converts a PSR-7 `ResponseInterface` object into a Symfony `Response`. This direction needs no PSR-17 factory. The class implements `HttpFoundationFactoryInterface`. Entry point: `new HttpFoundationFactory()`.
- **Streamed conversion:** the second argument `$streamed` of the two `HttpFoundationFactory` methods is `false` by default. If it is `true`, `createRequest()` gives the detached PSR-7 body resource to the `Request` instead of a string. If it is `true`, `createResponse()` returns a `StreamedResponse` that reads the PSR-7 body in chunks of up to 16372 bytes. The constructor argument `$responseBufferMaxLength` sets a different chunk size. The MCP bundle gives `true` for a `text/event-stream` response. Entry point: `$httpFoundationFactory->createResponse($psrResponse, true)`.
- **Request data:** the two request conversions copy the method, the headers, the body, the query parameters and the parsed body. They also copy the cookies, the uploaded files, the server parameters and the request attributes. `PsrHttpFactory` builds the PSR-7 URI from the scheme, the host, the base URL, the path info and the query string. `HttpFoundationFactory` sets `SERVER_NAME`, `SERVER_PORT`, `REQUEST_URI` and `QUERY_STRING` from the PSR-7 URI, and `HTTPS` for an `https` URI. If the PSR-7 parsed body is not an array, the `request` bag of the Symfony `Request` is empty. Entry point: `PsrHttpFactory::createRequest()`, `HttpFoundationFactory::createRequest()`.
- **JSON request bodies:** if `Request::getContentTypeFormat()` returns `json`, `PsrHttpFactory::createRequest()` decodes the body into the parsed body. The format is `json` for `application/json`, `application/x-json` and other `application/*+json` types without their own format. Thus, the method does not decode `application/ld+json` (format `jsonld`), `application/vnd.api+json` (format `jsonapi`), `application/hal+json` (format `hal`) or `application/problem+json` (format `problem`). If the body does not decode to a PHP array, the parsed body is `null`. For other formats, the parsed body is the form data of the `request` bag. Entry point: `$psrRequest->getParsedBody()`.
- **Uploaded files:** the factories convert uploaded files in the two directions, also in nested arrays. A file field without a file becomes a PSR-7 uploaded file with the error `UPLOAD_ERR_NO_FILE`. A PSR-7 uploaded file becomes a `Symfony\Bridge\PsrHttpMessage\Factory\UploadedFile`, which extends the HttpFoundation `UploadedFile`. If the PSR-7 stream does not point to a PHP upload, the bridge first moves the file to a temporary file. For a PHP upload, `move()` calls the PSR-7 `moveTo()` method. Entry point: `$request->files` after `HttpFoundationFactory::createRequest()`.
- **Cookies:** `HttpFoundationFactory::createResponse()` converts each PSR-7 `Set-Cookie` header line into a `Cookie` object. `PsrHttpFactory::createResponse()` converts the `Cookie` objects of a Symfony response into `Set-Cookie` header lines. Entry point: `$response->headers->getCookies()`.
- **Response status and headers:** the response conversions copy the status code, the headers and the protocol version. `PsrHttpFactory` takes the reason phrase from `Response::$statusTexts`. It ignores a request or response header that the PSR-7 implementation rejects as invalid. Entry point: `PsrHttpFactory::createResponse()`.
- **Streamed and file responses to PSR-7:** `PsrHttpFactory::createResponse()` runs the callback of a `StreamedResponse` at once and writes the output into a `php://temp` stream. Thus, the method returns only after the callback ends. For a `BinaryFileResponse`, the PSR-7 body is a stream of the file. If the `BinaryFileResponse` has a `Content-Range` header, the body contains only that range. Without a `Content-Range` header, a `BinaryFileResponse` of an `\SplTempFileObject` gives an empty body, because `createStreamFromFile('php://temp')` opens a new stream. Entry point: `PsrHttpFactory::createResponse()`.
- **PSR-7 controller arguments:** `PsrServerRequestResolver` resolves a controller argument with the type `ServerRequestInterface`, `RequestInterface` or `MessageInterface`. It converts the current request with the `HttpMessageFactoryInterface` service. The type must be one of these three interfaces, so a concrete class such as `Nyholm\Psr7\ServerRequest` does not match. No built-in value resolver of FrameworkBundle creates PSR-7 objects. Register the resolver as a service; autoconfiguration then adds the `controller.argument_value_resolver` tag. Entry point: `Symfony\Bridge\PsrHttpMessage\ArgumentValueResolver\PsrServerRequestResolver`.
- **PSR-7 controller responses:** `PsrResponseListener` listens to the `kernel.view` event. If a controller returns a PSR-7 `ResponseInterface` object, the listener sets the response that `HttpFoundationFactoryInterface::createResponse()` creates. If you give no factory to the constructor, the listener creates an `HttpFoundationFactory`. Register the listener as a service; autoconfiguration then adds the `kernel.event_subscriber` tag. If no listener converts the PSR-7 response, HttpKernel throws `ControllerDoesNotReturnResponseException`. Entry point: `Symfony\Bridge\PsrHttpMessage\EventListener\PsrResponseListener`.
- **Service setup:** FrameworkBundle registers no service of the bridge. The Flex recipe of `symfony/psr7-pack` creates `config/packages/psr_http_message_bridge.yaml`. This file registers `HttpFoundationFactory` and `PsrHttpFactory` as the services for `HttpFoundationFactoryInterface` and `HttpMessageFactoryInterface`. The file contains the resolver and the listener as comment lines. Uncomment the two lines to activate the two features. Entry point: `composer require symfony/psr7-pack`.
- **PSR-17 services:** the `php-http/discovery` recipe registers `Http\Discovery\Psr17Factory` for the six PSR-17 interfaces, for example `ResponseFactoryInterface` and `StreamFactoryInterface`. The `nyholm/psr7` recipe registers `Nyholm\Psr7\Factory\Psr17Factory` for them, but Flex skips this recipe when `php-http/discovery` 1.18 or later is installed. Thus, a controller or a service can autowire these interfaces to build PSR-7 responses. Entry point: autowire `Psr\Http\Message\ResponseFactoryInterface`.

## Entry points

- Install with `composer require symfony/psr-http-message-bridge` and a PSR-17 implementation, for example `composer require nyholm/psr7`. The bridge has the same version numbers as Symfony. The old `1.x` and `2.x` versions accept `symfony/http-foundation` 6.x at most, so they do not install with Symfony 8.
- In a Flex application, install `symfony/psr7-pack` (Flex aliases `psr-7`, `psr-17`, `psr7` and `psr17`). The pack requires the bridge, `php-http/discovery` (`^1.18`) and the virtual package `psr/http-factory-implementation`. If the project has no PSR-17 implementation, the Composer plugin of `php-http/discovery` installs one, by default `nyholm/psr7`. New projects from `symfony/skeleton` allow this plugin in the `allow-plugins` setting of `composer.json`.
- Autowire `Symfony\Bridge\PsrHttpMessage\HttpMessageFactoryInterface` to convert Symfony objects into PSR-7 objects. Autowire `Symfony\Bridge\PsrHttpMessage\HttpFoundationFactoryInterface` for the opposite direction. The recipe or your own service configuration must register the two services.
- Without FrameworkBundle: `Symfony\Bridge\PsrHttpMessage\Factory\PsrHttpFactory` and `Symfony\Bridge\PsrHttpMessage\Factory\HttpFoundationFactory`.
- Service `Symfony\Bridge\PsrHttpMessage\ArgumentValueResolver\PsrServerRequestResolver` (tag `controller.argument_value_resolver`) and service `Symfony\Bridge\PsrHttpMessage\EventListener\PsrResponseListener` (tag `kernel.event_subscriber`, event `kernel.view`). In `config/packages/psr_http_message_bridge.yaml`, uncomment the two lines with these class names.
- PSR-17 interfaces such as `Psr\Http\Message\ResponseFactoryInterface` and `Psr\Http\Message\StreamFactoryInterface`, which the `php-http/discovery` or `nyholm/psr7` recipe registers.
- Check the registration with `php bin/console debug:event-dispatcher kernel.view` and `php bin/console debug:container debug.argument_resolver.inner`. The second command needs the debug mode and the `symfony/stopwatch` package.
- The bridge has no `framework` configuration key, console command, Twig function or attribute.

## Symbiotic packages

- [HttpFoundation](../packages/http-foundation.md): the bridge converts its `Request`, `Response`, `StreamedResponse`, `BinaryFileResponse`, `UploadedFile` and `Cookie` objects, and it is the only Symfony package that the bridge requires.
- [HttpKernel](../packages/http-kernel.md): `PsrServerRequestResolver` implements its `ValueResolverInterface`, and `PsrResponseListener` converts PSR-7 controller results on its `kernel.view` event.
- [FrameworkBundle](../packages/framework-bundle.md): it registers no service of the bridge, but its autoconfiguration adds the `controller.argument_value_resolver` tag to a `PsrServerRequestResolver` service.
- [DependencyInjection](../packages/dependency-injection.md): its `ServicesBundle` autoconfigures event subscribers, so a `PsrResponseListener` service gets the `kernel.event_subscriber` tag.
- [EventDispatcher](../packages/event-dispatcher.md): `PsrResponseListener` is an `EventSubscriberInterface` subscriber for the `kernel.view` event.
- [Symfony Flex](../packages/flex.md): the recipe of `symfony/psr7-pack` registers the two factories and contains the resolver and the listener as comment lines.
- [HttpClient](../packages/http-client.md): `Psr18Client` sends PSR-7 requests to other servers, and the bridge converts the requests and responses of your own application.
- [FrameworkBundle test tools](../packages/framework-bundle-testing.md): a `WebTestCase` client tests controllers that take and return PSR-7 objects, as the functional test of the bridge shows.
- [Runtime](../packages/runtime.md): it runs the application that the front controller returns, for example a PSR-15 application with a custom runtime; the bridge only converts messages.
- [MCP Bundle](../packages/mcp-bundle.md): it requires the bridge, and its `McpController` converts requests and responses between Symfony and the PSR-7 transport of the MCP SDK.
