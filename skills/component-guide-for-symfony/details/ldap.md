# Ldap (`symfony/ldap`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **Client, adapter and service:** `Ldap` sends each call to an `AdapterInterface` object. The only adapter is `ExtLdap\Adapter`, which uses the PHP `ldap` extension. In a script, `Ldap::create('ext_ldap', $options)` creates both objects. Another adapter name throws `DriverNotFoundException`. In an application, register both classes as services. Add the `ldap` tag to the `Ldap` service. SecurityBundle puts each tagged service into the `security.ldap_locator` service locator, under its service ID. SecurityBundle also adds the `kernel.reset` tag to each tagged service, and a reset drops the connection. Thus, bind again after a reset. Entry point: `Symfony\Component\Ldap\Ldap`.
- **Connection options:** The adapter accepts `host` (default `localhost`), `port`, `version` (default 3), `encryption` (`none` by default, `ssl` or `tls`), `connection_string`, `referrals`, `debug` and `options`. With `ssl`, the default port is 636 and the default connection string is `ldaps://<host>:<port>`. With `tls`, the default port is 389 and the connection starts TLS with `ldap_start_tls()`. `options` accepts the lowercase names of the `ConnectionOptions` constants, for example `protocol_version`, `network_timeout` and `x_tls_require_cert`. An unknown option throws `UndefinedOptionsException` when the adapter creates the connection. Thus, the documented `optReferrals` option fails. To follow referrals, set `referrals` to `true`. Entry point: `Symfony\Component\Ldap\Adapter\ExtLdap\Adapter`.
- **Bind:** `bind($dn, $password)` authenticates the connection. A wrong password throws `InvalidCredentialsException`, and a timeout throws `ConnectionTimeoutException`. Other errors throw `ConnectionException` with the diagnostic message of the server. Without arguments, `bind()` does an anonymous bind. If the server allows unauthenticated binds, a blank password always succeeds. Thus, reject an empty password before the bind. `saslBind()` binds with SASL and throws `LdapException` if PHP has no SASL support. After a bind, `whoami()` returns the DN of the bound identity. If the server returns an identity without the `dn:` prefix, `whoami()` throws `LdapException`. Entry point: `Symfony\Component\Ldap\LdapInterface::bind()`.
- **Search:** `query($baseDn, $filter, $options)` returns a `QueryInterface` object, and `execute()` runs the search. Call `bind()` before `execute()`. Without a bind, `execute()` throws `NotBoundException`, also on a server that allows anonymous access. The options are `scope` (`SCOPE_SUB` by default, `SCOPE_ONE`, `SCOPE_BASE`), `filter`, `maxItems`, `pageSize`, `timeout`, `deref` and `attrsOnly`. The `filter` option is the list of attributes to return, not the LDAP filter. `pageSize` sends the paged-results control and collects all pages. `maxItems` limits the number of entries. Entry point: `Symfony\Component\Ldap\LdapInterface::query()`.
- **Entry and results:** `execute()` returns a collection of `Entry` objects that you can count, iterate and access by index. Iteration creates the entries one by one. `toArray()` and an index access such as `$results[0]` create all of them. An `Entry` holds a DN and attributes. Each attribute value is an array, because an LDAP attribute can have more than one value. `getAttribute()` and `hasAttribute()` are case-sensitive by default. To ignore the case, pass `false` as the second argument. Entry point: `Symfony\Component\Ldap\Entry`.
- **Escape values:** `query()` and the entry manager do not escape values. Before you put user input into a search filter, escape it with `escape($value, '', LdapInterface::ESCAPE_FILTER)`. For a value in a DN, use `LdapInterface::ESCAPE_DN`. `ESCAPE_DN` also encodes a leading space, a trailing space and each carriage return (RFC 4514). The docs say that the component cannot escape values, but this method exists. Entry point: `Symfony\Component\Ldap\LdapInterface::escape()`.
- **Entry manager:** `getEntryManager()` returns the object that writes to the directory: `add()`, `update()`, `remove()`, `rename()` and `move()`. `update()` sends all attributes of the `Entry`. To add or remove some values of a multi-valued attribute, use `addAttributeValues()` or `removeAttributeValues()`. The docs call them more efficient than `update()`. These two methods and `applyOperations()` are on `ExtLdap\EntryManager`, not on `EntryManagerInterface`. Each method needs a bound connection and throws `LdapException` if the server rejects the change. Entry point: `Symfony\Component\Ldap\Adapter\ExtLdap\EntryManager`.
- **Batch changes:** `applyOperations($dn, $operations)` sends a list of changes in one `ldap_modify_batch()` call. Each change is an `UpdateOperation` with an `LDAP_MODIFY_BATCH_*` type, an attribute name and an array of values. For `LDAP_MODIFY_BATCH_REMOVE_ALL`, give `null` as the values. The docs example gives a string as the values, but the constructor accepts only `?array`. Give an array, for example `['new1@example.com']`. Entry point: `Symfony\Component\Ldap\Adapter\ExtLdap\UpdateOperation`.
- **`ldap` user provider:** `security.providers.<name>.ldap` loads `LdapUser` objects from the directory. Set `service` and `base_dn`, because they have no default value. The provider binds with `search_dn` and `search_password`. If both are `null` (the default), it binds anonymously. It escapes the identifier and searches below `base_dn` with `filter` (default `({uid_key}={user_identifier})`). `uid_key` is `sAMAccountName` by default. The docs also name `userPrincipalName` and `uid`. No match, or more than one match, throws `UserNotFoundException`. Wrong search credentials throw `InvalidSearchCredentialsException`. Entry point: `Symfony\Component\Ldap\Security\LdapUserProvider`.
- **User data and password attribute:** `LdapUser::getEntry()` returns the `Entry` that the search found. `getExtraFields()` returns the `extra_fields` attributes as arrays of values. If the entry does not have one of these attributes, the provider throws an `\InvalidArgumentException` when it loads the user. If `extra_fields` is not empty, the search returns only those attributes. Thus, put each attribute that you read into `extra_fields`. `password_attribute` (not in the docs) puts the value of that attribute into `getPassword()`. Then `form_login` can check the password with the password hasher that `security.password_hashers` sets for `LdapUser`. After a successful login, if `needsRehash()` of this hasher returns `true`, `upgradePassword()` writes a new hash to the entry. This method ignores LDAP errors. If a `*_ldap` authenticator checks the password, do not set `password_attribute`. Otherwise, a successful login can write a new hash into that attribute. `refreshUser()` does not search again, so changes in the directory apply after the next login. Entry point: `Symfony\Component\Ldap\Security\LdapUser`.
- **Roles:** `default_roles` gives the same roles to each user. Without `default_roles` or `role_fetcher`, the users have no roles. `role_fetcher` takes the ID of a `RoleFetcherInterface` service and replaces `default_roles`. `MemberOfRoles` maps group names to roles. By default, it reads the `ismemberof` attribute and takes the group name from `CN=<group>,ou=...`. If a value does not match this pattern, it uses the full value as the group name. To change the attribute or the pattern, set the `$attributeName` or `$groupNameRegex` constructor argument. The attribute name is case-sensitive. Thus, write it as the server spells it, for example `memberOf`. The docs also add the attribute to `extra_fields`. Then each user must have this attribute. Otherwise, the provider throws an `\InvalidArgumentException`. Each role must start with `ROLE_`. Entry point: `Symfony\Component\Ldap\Security\MemberOfRoles`.
- **LDAP authenticators:** `form_login_ldap`, `json_login_ldap` and `http_basic_ldap` accept all options of `form_login`, `json_login` and `http_basic`. They add `service` (default `ldap`), `dn_string` (default `{user_identifier}`), `query_string`, `search_dn` and `search_password`. `service` must be the ID of a service with the `ldap` tag, not an alias. The password check is an LDAP bind, not a hash comparison. First, the user provider of the firewall loads the user, so the user must exist there. Then `{user_identifier}` in `dn_string` becomes the DN-escaped `getUserIdentifier()` of that user. `{username}` is not a placeholder. Use `{user_identifier}`. Entry point: `security.firewalls.<name>.form_login_ldap`.
- **Any user provider:** The `*_ldap` authenticators work with any user provider, for example the Doctrine `entity` provider. The user class must still implement `PasswordAuthenticatedUserInterface`, because the core password listener checks this before it skips the hash check. Its `getPassword()` method can return `null`. Entry point: `Symfony\Component\Security\Core\User\PasswordAuthenticatedUserInterface`.
- **Search before bind:** If `dn_string` cannot build the DN of each user, set `query_string`, for example `(&(uid={user_identifier})(memberOf=cn=users,ou=Services,dc=example,dc=com))`. Then the listener binds with `search_dn` and `search_password`, and searches below `dn_string` with the filter-escaped identifier. It binds with the DN of the single result and the password. If you set `query_string` but `search_dn` or `search_password` is empty, the container compilation fails with `InvalidConfigurationException`. If the search finds no entry or more than one entry, the login fails. Entry point: `security.firewalls.<name>.form_login_ldap.query_string`.
- **`LdapBadge` in a custom authenticator:** In your own authenticator, add `new LdapBadge($ldapServiceId, $dnString)` to a passport with `PasswordCredentials`. `CheckLdapCredentialsListener` (on `CheckPassportEvent`, priority 144) does the bind and resolves both badges. SecurityBundle adds this listener only to firewalls with a `*_ldap` authenticator. On another firewall, register the listener as an event subscriber with the `security.ldap_locator` service as its argument. Otherwise, the login fails because no listener resolves the badge. To add LDAP to an authenticator that you cannot change, wrap it in `LdapAuthenticator`. Entry point: `Symfony\Component\Ldap\Security\LdapBadge`.

## Entry points

- `Symfony\Component\Ldap\Ldap`: the client. Register it as a service with the `ldap` tag. Use the class name as the service ID, as the docs do. Methods: `bind()`, `saslBind()`, `whoami()`, `query()`, `getEntryManager()`, `escape()`, `reset()`, static `create()`.
- Without FrameworkBundle: `Ldap::create('ext_ldap', $options)` creates the client and its adapter, for example in a script. The `ldap` user provider and the `*_ldap` authenticators need SecurityBundle.
- `Symfony\Component\Ldap\LdapInterface`: the interface, with the constants `ESCAPE_FILTER` and `ESCAPE_DN`.
- `Symfony\Component\Ldap\Adapter\ExtLdap\Adapter`: the adapter service; its constructor argument is the options array.
- `Symfony\Component\Ldap\Adapter\QueryInterface`: the constants `SCOPE_BASE`, `SCOPE_ONE`, `SCOPE_SUB` and `DEREF_*`, and `execute()`.
- `Symfony\Component\Ldap\Entry`, `Symfony\Component\Ldap\Adapter\ExtLdap\EntryManager`, `Symfony\Component\Ldap\Adapter\ExtLdap\UpdateOperation`.
- Config: `security.providers.<name>.ldap` with `service`, `base_dn`, `search_dn`, `search_password`, `default_roles`, `role_fetcher`, `uid_key`, `filter`, `password_attribute` and `extra_fields`.
- Config: `security.firewalls.<name>.form_login_ldap`, `security.firewalls.<name>.json_login_ldap` and `security.firewalls.<name>.http_basic_ldap`, with `service`, `dn_string`, `query_string`, `search_dn` and `search_password`, plus the options of the non-LDAP variant.
- Service tag: `ldap`. Service IDs: `security.ldap_locator`, `security.user.provider.ldap` (abstract parent), `security.user.provider.concrete.<provider name>` (name in lowercase), `security.authenticator.<key>.<firewall>` and `security.listener.<key>.<firewall>`, where `<key>` is `form_login_ldap`, `json_login_ldap` or `http_basic_ldap`.
- Security classes (namespace `Symfony\Component\Ldap\Security`): `LdapUserProvider`, `LdapUser`, `RoleFetcherInterface`, `MemberOfRoles`, `AssignDefaultRoles`, `LdapBadge`, `LdapAuthenticator`, `CheckLdapCredentialsListener`.
- Exceptions (namespace `Symfony\Component\Ldap\Exception`, all implement `ExceptionInterface`): `ConnectionException`, `InvalidCredentialsException`, `InvalidSearchCredentialsException`, `ConnectionTimeoutException`, `AlreadyExistsException`, `NotBoundException`, `LdapException`, `UpdateOperationException`, `DriverNotFoundException`.
- The package has no console commands, no PHP attributes, no Twig functions and no test helpers.

## Symbiotic packages

- [Security](../packages/security-bundle.md): SecurityBundle builds the `ldap` provider and the `*_ldap` authenticators from the classes of this package, and installs symfony/security-core and symfony/security-http, which these classes need.
- [Doctrine Bridge](../packages/doctrine-bridge.md): the `entity` provider loads users from the database while `form_login_ldap` checks their passwords; a `chain` provider combines `entity` and `ldap` providers.
- [PasswordHasher](../packages/password-hasher.md): the `*_ldap` authenticators check passwords with an LDAP bind and do not hash them; PasswordHasher hashes the passwords that the application stores.
- [RateLimiter](../packages/rate-limiter.md): `login_throttling` also limits `*_ldap` logins, because its listener runs before the LDAP bind (priority 2080 against 144).
- [Security CSRF](../packages/security-csrf.md): `form_login_ldap` gets the `enable_csrf` option from `form_login`, so the LDAP login form can check a CSRF token.
- [OptionsResolver](../packages/options-resolver.md): the adapter and the query check their options with OptionsResolver, so an unknown option throws `UndefinedOptionsException`.

## Changed in 8.0/8.1

- `LdapUser::eraseCredentials()` -> removed in 8.0. `LdapUser::__serialize()` removes the password from the serialized user. Do not set `security.erase_credentials`, which 8.1 deprecates.
- The `sizeLimit` query option -> removed in 8.0 (it had no effect). A `query()` call with this option now throws `UndefinedOptionsException`. Use `maxItems` to limit the number of entries.
- A custom `LdapInterface` or `ConnectionInterface` class -> since 8.0, it must also implement `saslBind()` and `whoami()`.
- XML (`<form-login-ldap .../>`) and fluent PHP config (`->formLoginLdap()->dnString(...)`) -> removed in 8.0. Use YAML, or PHP with `App::config(['security' => [...]])` arrays.
- `form_login` and `form_login_ldap` (or another pair) on one firewall -> possible since 8.0.15 and 8.1.2. For a `form_login` or `json_login` pair, give the two authenticators different `check_path` values. For a `form_login` or `http_basic` pair, also set the firewall `entry_point`.
- Since 8.0.8, `Ldap::reset()` resets the adapter and drops the connection. Bind again after a reset. Do not bind only once in a constructor.

## Status

- The package needs the PHP `ldap` extension (`ext-ldap` in `composer.json`). PHP does not enable it by default. To enable it, build PHP with `--with-ldap`. Without the extension, `new Adapter()` throws `LdapException` ("The LDAP PHP extension is not enabled.").
- `saslBind()` needs PHP with `--with-ldap-sasl`. Otherwise, it throws `LdapException`.
- `ext_ldap` is the only adapter.
