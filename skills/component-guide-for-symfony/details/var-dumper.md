# VarDumper (`symfony/var-dumper`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **`dump()` function:** Composer loads the global `dump()` function with the package. With one value, `dump()` returns that value, so `dump($order)->getTotal()` works. With several values, it returns them in an array. A named argument, as in `dump(user: $user)`, becomes the label of the dump. Without arguments, it dumps the marker `🐛` and returns `null`. In a Symfony application, ErrorHandler requires VarDumper, so `dump()` and `dd()` also exist in `prod`. Without DebugBundle, as in `prod`, the calls write the dumps to the output. Remove the calls before you deploy. Entry point: `dump(mixed ...$vars)`.
- **`dd()` function:** `dd()` dumps the values and stops the script with the exit code 1. On a web server, it also sends the status code 500 if PHP did not send the headers yet. With DebugBundle, if `debug.dump_destination` is `null` or the dump server does not answer, `dd()` writes all dumps of the request to the output. Entry point: `dd(mixed ...$vars)`.
- **Output format:** Without DebugBundle, `dump()` writes text to `STDOUT` in the CLI and skips the output buffer. On a web server, it writes HTML when the `Accept` header contains `html` or `*/*`, or when the request has no `Accept` header. For other values, such as `application/json`, it writes plain text to the output. The environment variable `VAR_DUMPER_FORMAT` forces `html`, `cli`, `server` or a `tcp://` server address. If `VAR_DUMPER_FORMAT` is set, `VarDumper::setHandler()` has no effect, so the environment variable also overrides DebugBundle. Entry point: `VAR_DUMPER_FORMAT`.
- **Web debug toolbar:** If the application enables DebugBundle and `kernel.debug` is true, `dump()` sends the dumps to the profiler and to the web debug toolbar of WebProfilerBundle. If `debug.dump_destination` is `null` and the toolbar cannot appear, the dumps go to the output. For example, the toolbar cannot appear after a redirect, for a non-HTML response, after `exit()` or without WebProfilerBundle. For AJAX requests, requests with an `Origin` header and sub-requests, the dumps stay in the profiler and do not go to the output. For a JSON API, set `debug.dump_destination` to `php://stderr`. Entry point: `debug.dump_destination`.
- **Dump server:** The dump server shows the dumps of all requests and commands in one terminal, separate from the application output. Start it with `php bin/console server:dump`. To write an HTML file, add `--format=html > dump.html`. In an application, set `debug.dump_destination` to `tcp://%env(VAR_DUMPER_SERVER)%`. If the value does not start with `tcp://`, the command only shows a warning. The Flex recipe of DebugBundle sets this value for the `dev` environment. The profiler keeps the dumps of web requests, also when the server does not run. If the server does not run, console commands write the dumps to the terminal. `VAR_DUMPER_SERVER` defaults to `127.0.0.1:9912`. Outside an application, start `vendor/bin/var-dump-server`, which needs `symfony/console`. With `new ServerDumper($host, $fallbackDumper)`, the fallback dumper writes the dumps when the server does not run. Entry point: `server:dump`.
- **Twig `dump` function and tag:** With DebugBundle and Twig debug mode, `{{ dump(user) }}` prints an HTML dump into the page. `{% dump user %}` sends the dump to the web debug toolbar and does not change the page. Without arguments, both dump all template variables. `{% dump articles, user %}` dumps one array with the variable names as keys. The docs show named arguments in `{{ dump() }}`. They cause a `SyntaxError` ("Unknown argument"). Use positional arguments or the tag. The Flex recipe enables DebugBundle only in `dev`. Without DebugBundle, the tag causes a `SyntaxError`. Without DebugBundle but in debug mode, as in `test`, `{{ dump() }}` is the Twig core function, which prints `var_dump()` output. In `prod`, both cause a `SyntaxError`. Entry point: `{{ dump() }}`, `{% dump %}`.
- **Cloner and `Data` object:** `VarCloner::cloneVar()` turns any value into a `Data` object that you can serialize. `setMaxItems()` (default 2500), `setMaxString()` (default -1, no limit) and `setMinDepth()` (default 1) limit what the cloner copies. `Data::withMaxDepth()`, `withMaxItemsPerDepth()`, `withRefHandles(false)` and `seek($key)` change the view of a `Data` object without another `cloneVar()` call. Entry point: `Symfony\Component\VarDumper\Cloner\VarCloner`.
- **Dumpers:** `CliDumper` writes text to `php://stdout`, and `HtmlDumper` writes HTML to `php://output`. The first constructor argument sets another destination: a stream, a path or a callable that receives each line. The dumper opens a path with the mode `w`. To append to a file, give `fopen($path, 'a')`. `$dumper->dump($data, true)` returns the dump as a string. The third constructor argument takes the flags `AbstractDumper::DUMP_LIGHT_ARRAY`, `DUMP_STRING_LENGTH`, `DUMP_COMMA_SEPARATOR` and `DUMP_TRAILING_COMMA`. `DUMP_COMMA_SEPARATOR` adds commas between array items, and `DUMP_TRAILING_COMMA` adds a comma after each array item. `CliDumper` follows `NO_COLOR` and `FORCE_COLOR`, and `setColors()` overrides both. `HtmlDumper::setTheme('light')` changes the colors. Entry point: `new CliDumper()`, `new HtmlDumper()`.
- **Custom handler:** `VarDumper::setHandler()` sends all `dump()` and `dd()` calls to your own callable. The callable receives the value and the label, and it can use its own cloner and dumper. Entry point: `VarDumper::setHandler(?callable $callable)`.
- **Custom casters:** A caster is a callable that returns the array of properties that a dump shows for an object or a resource. Register it with `$cloner->addCasters([Product::class => $caster])`. The array keys can be a class, an interface, a resource type such as `':stream'`, or `'*'` for all objects. The callable receives the object, the property array, a `Stub`, the nested flag and the `Caster::EXCLUDE_*` filter. The cloner calls the `'*'` casters first, then the casters of the interfaces, the parent classes and the class. Do not change the state of the object in a caster. `new VarCloner($casters)` replaces all default casters. To keep them, call `addCasters()`. Entry point: `AbstractCloner::addCasters()`.
- **Default casters:** Without a constructor argument, each new cloner copies the static list `AbstractCloner::$defaultCasters`. The list covers, for example, `Request`, HttpClient clients and responses, `Uuid` and `Ulid`, Doctrine proxies and collections, exceptions, closures, `DateTimeInterface`, PDO, Redis and DOM nodes. Most built-in caster classes are `@internal`. Do not call them from your code. `AbstractCloner::addDefaultCasters()` adds casters to this list, or replaces the caster of a key, for the cloners that you create later. Entry point: `AbstractCloner::addDefaultCasters()`.
- **Stubs and filters:** A caster can wrap a value in a stub to change its display. `LinkStub` makes a link, `CutStub` replaces a value with an ellipsis, and `CutArrayStub` keeps only some keys of an array. `ClassStub`, `ConstStub`, `EnumStub`, `ImgStub`, `TraceStub`, `FrameStub` and `ArgsStub` show class names, constants, virtual values, images and backtraces. Prefix a computed key with `Caster::PREFIX_VIRTUAL`. `cloneVar($value, $filter)` gives the `Caster::EXCLUDE_*` flags to each caster and does not apply them itself. In your caster, apply them with `Caster::filter($array, $filter)`. Entry point: `Symfony\Component\VarDumper\Caster\Caster`, `Symfony\Component\VarDumper\Caster\LinkStub`.
- **Class names:** Since 8.1, if PHP already loaded a user class, `dump(Product::class)` shows the class like an object, with its static properties. If the dumper has a file link format, the class name links to the source file. A class name inside an array stays a string. Entry point: `dump(Product::class)`.
- **CSP nonces:** Since 8.1, `HtmlDumper::setNonce($nonce, $styleNonce)` adds CSP nonces to the inline `<script>` and `<style>` tags of the dump. Without a style nonce, the dumper uses the script nonce for both tags. The dumper calls a closure argument at each dump. With WebProfilerBundle, the toolbar forwards its CSP nonces to the dumps that DebugBundle collects. Entry point: `HtmlDumper::setNonce()`.
- **PHPUnit assertions:** `VarDumperTestTrait` adds `assertDumpEquals()` and `assertDumpMatchesFormat()`. They compare the text dump of a value without colors and without object handles such as `#123`. If the expected argument is not a string, the trait dumps it too. `assertDumpMatchesFormat()` accepts PHPUnit format placeholders such as `%d`. `setUpVarDumper($casters, $flags)` adds casters and dumper flags, and the trait resets them after each test. Entry point: `Symfony\Component\VarDumper\Test\VarDumperTestTrait`.

## Entry points

- Functions `dump()` and `dd()`. Composer loads them from `Resources/functions/dump.php`.
- Class `Symfony\Component\VarDumper\VarDumper` with the static methods `dump($var, $label)` and `setHandler(?callable $callable)`.
- Cloner `Symfony\Component\VarDumper\Cloner\VarCloner` (`cloneVar()`, `addCasters()`, `setMaxItems()`, `setMaxString()`, `setMinDepth()`, static `addDefaultCasters()`) and the result class `Symfony\Component\VarDumper\Cloner\Data`.
- Dumpers `Symfony\Component\VarDumper\Dumper\CliDumper`, `HtmlDumper`, `ServerDumper` and `ContextualizedDumper`, with the flags on `Symfony\Component\VarDumper\Dumper\AbstractDumper`. Context providers for `ServerDumper`: `CliContextProvider`, `RequestContextProvider` and `SourceContextProvider` in `Symfony\Component\VarDumper\Dumper\ContextProvider`.
- Caster helpers: `Symfony\Component\VarDumper\Caster\Caster` (`EXCLUDE_*`, `PREFIX_VIRTUAL`, `filter()`), `Symfony\Component\VarDumper\Cloner\Stub` and the stub classes in `Symfony\Component\VarDumper\Caster`.
- Test helper `Symfony\Component\VarDumper\Test\VarDumperTestTrait` with `assertDumpEquals()`, `assertDumpMatchesFormat()` and `setUpVarDumper()`.
- Console command `server:dump [--format=cli|html]`, which DebugBundle registers. Outside an application: `vendor/bin/var-dump-server [--host=127.0.0.1:9912]`.
- Environment variables `VAR_DUMPER_FORMAT` (`html`, `cli`, `server` or `tcp://host:port`) and `VAR_DUMPER_SERVER` (default `127.0.0.1:9912`); `NO_COLOR` and `FORCE_COLOR` for `CliDumper`.
- DebugBundle config keys: `debug.dump_destination` (default `null`), `debug.max_items` (2500), `debug.min_depth` (1), `debug.max_string_length` (-1) and `debug.theme` (`dark` or `light`, for `{{ dump() }}`).
- FrameworkBundle config key `framework.ide` (default `%env(default::SYMFONY_IDE)%` in debug mode) for the file links in dumps.
- Twig function `dump()` and tag `{% dump %}` from `Symfony\Bridge\Twig\Extension\DumpExtension`, which DebugBundle registers (with the Flex recipe, only in `dev`).
- No autowiring alias exists for `VarCloner`, `ClonerInterface` or the dumpers. Create them with `new`. DebugBundle defines the services `var_dumper.cloner`, `var_dumper.cli_dumper` and `var_dumper.html_dumper` only in the environments that enable it. `var_dumper.cli_dumper` is a `ContextualizedDumper`, not a `CliDumper`.
- Install: `composer require --dev symfony/debug-bundle` in an application; `composer require --dev symfony/var-dumper` for standalone use.
- Without FrameworkBundle: call `dump()` and `dd()`, or create `new VarCloner()` with `new CliDumper()` or `new HtmlDumper()`. For the dump server, start `vendor/bin/var-dump-server`, which needs `symfony/console`.

## Symbiotic packages

- [DebugBundle](../packages/debug-bundle.md): it sends `dump()` output to the toolbar or to `debug.dump_destination`, and it registers the Twig `dump` function, the tag and `server:dump`.
- [Twig Bridge](../packages/twig-bridge.md): its `DumpExtension` defines the Twig `dump()` function and the `{% dump %}` tag, which use VarDumper.
- [TwigBundle](../packages/twig-bundle.md): without DebugBundle, in debug mode, it registers only the Twig core `dump()` function, which prints `var_dump()` output.
- [WebProfilerBundle](../packages/web-profiler-bundle.md): the toolbar and the profiler show the collected dumps, `profiler_dump()` renders `Data` objects in collector templates, and the toolbar forwards CSP nonces to dumps.
- [HttpKernel](../packages/http-kernel.md): `DumpDataCollector` keeps the dumps of a request for the profiler, `DumpListener` sets the dump handler for console commands, and `DataCollector::cloneVar()` uses `VarCloner`.
- [Console](../packages/console.md): `server:dump` and `var-dump-server` need Console, and the Console `Dumper` helper formats a variable for command output with `CliDumper`.
- [FrameworkBundle](../packages/framework-bundle.md): the `framework.ide` option configures the `debug.file_link_formatter` service, which turns the file paths in dumps into links that open the files in your editor.
- [ErrorHandler](../packages/error-handler.md): ErrorHandler requires VarDumper; its CLI renderer dumps exceptions with `CliDumper`, and the debug error page shows exception properties with `HtmlDumper`.
- [Monolog Bridge](../packages/monolog-bridge.md): if the project includes VarDumper, `ConsoleHandler` formats the context and the extra data of log records with `CliDumper`.
- [Messenger](../packages/messenger.md): `messenger:failed:show <id> -vv` shows the failed message and its exception with VarDumper.
- [VarExporter](../packages/var-exporter.md): VarExporter exports a value as PHP code that recreates it, for example for a cache; VarDumper shows a value while you debug.

## Changed in 8.0/8.1

- **8.1, CSP nonces:** `HtmlDumper::setNonce()` adds CSP nonces to the inline `<script>` and `<style>` tags of HTML dumps. With WebProfilerBundle, the toolbar forwards the nonces of the page to the dumps.
- **8.1, class names:** `dump(Product::class)` shows a loaded user class like an object, with its static properties, not only the string.
- **8.0 (and 7.4), default casters:** `AbstractCloner::addDefaultCasters()` adds casters to the default list of the cloners that you create later.
- **8.0 (and 7.4), `Accept` header:** without DebugBundle, `dump()` on a web server writes HTML only for an `Accept` header with `html` or `*/*`, or without an `Accept` header. Other requests, for example with `Accept: application/json`, get plain text.
- **8.0, configuration format:** Symfony 8.0 removes the XML format and the fluent PHP format for configuration. Write the `debug` options in YAML, or return `App::config(['debug' => [...]])` from a PHP file.
