# Panther (`symfony/panther`): details

**Applies to:** Panther 2.4

## Key features and concepts

- **Test case with a web server**: `PantherTestCase` starts the application on the PHP built-in web server and opens a browser on it. The defaults are `127.0.0.1:9080` and the document root `public/`. If FrameworkBundle is installed, `PantherTestCase` extends `WebTestCase`, so the kernel and the services are also available. In one test class, later calls of `createPantherClient()` return the same browser, so cookies stay from one test to the next. If a test needs a new browser session, call `$client->restart()`. Entry point: `Symfony\Component\Panther\PantherTestCase::createPantherClient()`.
- **Three clients with one API**: In a `PantherTestCase`, `createClient()` returns the FrameworkBundle `KernelBrowser`. It sends no HTTP request, runs no JavaScript and is the fastest client. `createHttpBrowserClient()` returns the BrowserKit `HttpBrowser`, which sends real HTTP requests to the web server and runs no JavaScript. `createPantherClient()` returns a real browser. All three clients have the BrowserKit API, so you can select the client for each test. Entry point: `PantherTestCase::createHttpBrowserClient()`.
- **Panther client**: `Client` extends the BrowserKit `AbstractBrowser` and implements the php-webdriver `WebDriver` interface. Use `request('GET', '/path')`, `clickLink()`, `submitForm()`, `executeScript()` and `getWebDriver()`. `request()` accepts only GET, with no parameters, files, server values or content. The browser always follows redirects. Panther does not support nested arrays as form values. Use the full field name, for example `submitForm('Save', ['task[title]' => 'Buy milk'])`. `getResponse()`, `getRequest()` and `getHistory()` throw a `LogicException`. The client has no `loginUser()`: that method exists only on `KernelBrowser`. Entry point: `Symfony\Component\Panther\Client`.
- **Panther crawler**: The Panther `Crawler` extends the DomCrawler `Crawler`, but it contains WebDriver elements of the live page. `text()` returns only the displayed text, so `text()` on `<title>` returns an empty string. For the page title, use `$client->getTitle()`. For other hidden content, use `html()`. Use `getElement()` instead of `getNode()`. `evaluate()`, the `add*()` methods and XML documents are not supported. Entry point: `Symfony\Component\Panther\DomCrawler\Crawler`, from `Client::refreshCrawler()`.
- **Browsers and drivers**: Panther does not include the driver binaries. It finds `chromedriver` in the `PATH`, in `drivers/` or in `vendor/bin/`. It finds `geckodriver` in the `PATH` or in `drivers/`. Install them with `composer require --dev dbrekelmans/bdi` and `vendor/bin/bdi detect drivers`, or with the package manager of the operating system. Chrome is the default browser. If Panther cannot find `chromedriver`, it uses Firefox, unless the `browser` option is `PantherTestCase::CHROME`. For a Selenium Grid, set `browser` to `PantherTestCase::SELENIUM`. Then give the `host` and `capabilities` manager options. Entry point: `createPantherClient(['browser' => PantherTestCase::FIREFOX])`.
- **Wait methods**: `waitFor()`, `waitForStaleness()`, `waitForVisibility()`, `waitForInvisibility()`, `waitForElementToContain()`, `waitForElementToNotContain()`, `waitForAttributeToContain()`, `waitForAttributeToNotContain()`, `waitForEnabled()` and `waitForDisabled()` wait until their condition is true. `waitFor()` waits until the element is in the DOM, also if it is hidden. The locator is a CSS selector, or an XPath expression that starts with `/`. The default timeout is 30 seconds, and the check interval is 250 ms. The methods return a new crawler of the page. On timeout, they throw `Facebook\WebDriver\Exception\TimeoutException`. If the element was missing during the wait, the methods other than `waitFor()` and `waitForInvisibility()` throw `Facebook\WebDriver\Exception\NoSuchElementException` instead. `waitForStaleness()` and `assertSelectorWillNotExist()` look for the element first, so the element must be in the DOM when you call them. Entry point: `Client::waitFor(string $locator, int $timeoutInSecond = 30, int $intervalInMillisecond = 250)`.
- **"Will" assertions**: `assertSelectorWillExist()`, `assertSelectorWillNotExist()`, `assertSelectorWillBeVisible()`, `assertSelectorWillNotBeVisible()`, `assertSelectorWillContain()`, `assertSelectorWillNotContain()`, `assertSelectorWillBeEnabled()`, `assertSelectorWillBeDisabled()`, `assertSelectorAttributeWillContain()` and `assertSelectorAttributeWillNotContain()` call the matching wait method, then assert. They have no timeout argument, so they wait up to 30 seconds. For a different timeout, call the wait method with `$timeoutInSecond` first. Entry point: `PantherTestCase::assertSelectorWillExist()`.
- **Browser state assertions**: `assertSelectorIsVisible()`, `assertSelectorIsNotVisible()`, `assertSelectorIsEnabled()`, `assertSelectorIsDisabled()`, `assertSelectorAttributeContains()` and `assertSelectorAttributeNotContains()` check the current state in the browser. The FrameworkBundle crawler assertions also work with the Panther client, for example `assertSelectorTextContains()`, `assertSelectorCount()` and `assertPageTitleContains()`. The response and request assertions, for example `assertResponseIsSuccessful()`, do not work, because the Panther client has no response. The Panther assertions exist only if FrameworkBundle is installed. Entry point: `PantherTestCase::assertSelectorIsVisible()`.
- **Screenshots and console logs**: `takeScreenshot('var/page.png')` saves an image of the current page to the file and returns the image as a string. In headless mode, Chrome starts with `--window-size=1200,1100`. For another size in Chrome, add `--window-size=1500,4000` to `PANTHER_CHROME_ARGUMENTS`. In Firefox, call `$client->manage()->window()->setSize(new \Facebook\WebDriver\WebDriverDimension(1500, 4000))`. To read the console logs, set the `goog:loggingPrefs` capability in the manager options. Then call `$client->getWebDriver()->manage()->getLog('browser')`. Entry points: `Client::takeScreenshot($saveAs = null)`, `createPantherClient([], [], ['capabilities' => ['goog:loggingPrefs' => ['browser' => 'ALL']]])`.
- **PHPUnit extension**: `ServerExtension` keeps the web server and the browsers open for all tests and stops them after the last test. Without it, the web server stops in `tearDownAfterClass()`. If `PANTHER_ERROR_SCREENSHOT_DIR` is also set, Panther saves a screenshot of each browser when a test fails or has an error. `PANTHER_ERROR_SCREENSHOT_ATTACH` adds the screenshot paths to the test output in the JUnit attachment format. The extension also enables the interactive mode: `PANTHER_NO_HEADLESS=1 bin/phpunit --debug` shows the browser and stops after each failure or error until you press Enter. Entry point: `<bootstrap class="Symfony\Component\Panther\ServerExtension"/>` in `<extensions>` of `phpunit.dist.xml` (PHPUnit 10 or later; older versions use `<extension class="…"/>`).
- **Web server options**: The `hostname`, `port`, `webServerDir`, `router`, `readinessPath`, `env` and `external_base_uri` options of `createPantherClient()` configure the web server. Panther starts the web server once, so only the first call applies these options. To apply other options later, call `static::stopWebServer()` first. At the start, Panther waits up to 30 seconds until the web server answers a request to `readinessPath`. The web server is a separate PHP process, so services that you replace in the test container do not change its responses. Use the `env` option to give it other environment variables. If the test bootstrap loads `.env` files, also set `'SYMFONY_DOTENV_VARS' => false`. Then Dotenv does not replace your `env` values. If `external_base_uri`, `PANTHER_EXTERNAL_BASE_URI` or `SYMFONY_PROJECT_DEFAULT_ROUTE_URL` is set, Panther starts no web server and uses that URL. Entry point: `createPantherClient(['env' => ['MAILER_DSN' => 'null://null', 'SYMFONY_DOTENV_VARS' => false]])`.
- **Environment variables**: `PANTHER_NO_HEADLESS`, `PANTHER_WEB_SERVER_DIR`, `PANTHER_WEB_SERVER_PORT`, `PANTHER_WEB_SERVER_ROUTER`, `PANTHER_READINESS_PATH`, `PANTHER_EXTERNAL_BASE_URI`, `PANTHER_APP_ENV`, `PANTHER_ERROR_SCREENSHOT_DIR`, `PANTHER_ERROR_SCREENSHOT_ATTACH`, `PANTHER_DEVTOOLS`, `PANTHER_NO_REDUCED_MOTION`, `PANTHER_NO_SANDBOX`, `PANTHER_CHROME_ARGUMENTS`, `PANTHER_CHROME_BINARY`, `PANTHER_FIREFOX_ARGUMENTS` and `PANTHER_FIREFOX_BINARY` configure Panther. `PANTHER_CHROME_ARGUMENTS` and `PANTHER_FIREFOX_ARGUMENTS` add arguments to the default arguments. The `$arguments` parameter of `Client::createChromeClient()` and `Client::createFirefoxClient()` and the `browser_arguments` option replace all default arguments, also `--headless`. The web server uses `PANTHER_APP_ENV` as `APP_ENV`. The Flex recipe of FrameworkBundle 8.1 creates `src/Kernel.php`, and its `getAllowedEnvs()` method returns `prod`, `dev` and `test`. If `PANTHER_APP_ENV` has another value, add the value to `getAllowedEnvs()`. The Flex recipe sets `PANTHER_APP_ENV=test`, `PANTHER_ERROR_SCREENSHOT_DIR=./var/error-screenshots` and `PANTHER_DEVTOOLS=0` in `.env.test`, and it registers the PHPUnit extension. Entry point: `.env.test`, or `<server name="PANTHER_…" value="…"/>` in `phpunit.dist.xml`.
- **CI and Docker**: In a container, set `PANTHER_NO_SANDBOX=1`. The docs also recommend `PANTHER_CHROME_ARGUMENTS='--disable-dev-shm-usage'`. Install Chromium and ChromeDriver in the container image. If Flex Docker support is on (`extra.symfony.docker`), the recipe adds both settings and the Chromium installation to the `Dockerfile`. The `Dockerfile` needs a `###> recipes ###` line. The docs have examples for Docker, GitHub Actions, Travis CI, GitLab CI and AppVeyor. The GitHub Actions example on `ubuntu-latest` installs no browser and no driver. The Travis CI, GitLab CI and AppVeyor examples use PHP 8.0 or 8.1, but Symfony 8.1 needs PHP 8.4.1 or later. Entry point: `ENV PANTHER_NO_SANDBOX=1` in the `Dockerfile`.
- **Additional browsers**: `createAdditionalPantherClient()` opens one more isolated browser on the same web server, with its own cookies. Use it for a second user, for example in a chat that uses Mercure or WebSocket. The assertions always use the primary browser. Entry point: `PantherTestCase::createAdditionalPantherClient()`.
- **Standalone client for a scraper**: Outside a test, create the client with `Client::createChromeClient()`, `Client::createFirefoxClient()` or `Client::createSeleniumClient()`. These factories start no web server. Use absolute URLs, or give a `$baseUri`. Entry point: `Client::createChromeClient(?string $chromeDriverBinary = null, ?array $arguments = null, array $options = [], ?string $baseUri = null)`.

## Entry points

- Installation: `composer require --dev symfony/panther`. The Flex recipe adds `PANTHER_APP_ENV`, `PANTHER_ERROR_SCREENSHOT_DIR` and `PANTHER_DEVTOOLS` to `.env.test` and registers the PHPUnit extension.
- Without FrameworkBundle: create the client with `Client::createChromeClient()`, `Client::createFirefoxClient()` or `Client::createSeleniumClient()`, for example in a scraper. The Panther assertions exist only if FrameworkBundle is installed.
- `Symfony\Component\Panther\PantherTestCase`: the base test class, with the constants `CHROME`, `FIREFOX` and `SELENIUM`.
- `Symfony\Component\Panther\PantherTestCaseTrait`: the Panther methods for another base class (for example a LiipFunctionalTestBundle `WebTestCase`), without the Panther assertions.
- Test case methods: `createPantherClient(array $options = [], array $kernelOptions = [], array $managerOptions = [])`, `createAdditionalPantherClient()`, `createHttpBrowserClient(array $options = [], array $kernelOptions = [])`, `createClient()`, `startWebServer(array $options = [])`, `stopWebServer()`, `isWebServerStarted()`.
- Browser options of `createPantherClient()`: `browser`, `browser_arguments`. Web server options of `createPantherClient()`, `createHttpBrowserClient()` and `startWebServer()`: `hostname`, `port`, `webServerDir`, `router`, `readinessPath`, `env`, `external_base_uri`. Option of `createHttpBrowserClient()`: `http_client_options`.
- Manager options (third argument of `createPantherClient()`, `createChromeClient()` and `createFirefoxClient()`): `capabilities`, `port`, `chromedriver_arguments` (Chrome only), `connection_timeout_in_ms`, `request_timeout_in_ms`. With `PantherTestCase::SELENIUM`: `host` and `capabilities`.
- `Symfony\Component\Panther\Client`: `createChromeClient()`, `createFirefoxClient()`, `createSeleniumClient()`, `request()`, the `waitFor*()` methods, `takeScreenshot()`, `executeScript()`, `executeAsyncScript()`, `getWebDriver()`, `manage()`, `wait()`, `getMouse()`, `getKeyboard()`, `refreshCrawler()`, `getTitle()`, `ping()`, `restart()`, `quit()`.
- `Symfony\Component\Panther\DomCrawler\Crawler`: the crawler that `request()` and the wait methods return.
- `Symfony\Component\Panther\ServerExtension`: the PHPUnit extension.
- `Symfony\Component\Panther\ProcessManager\WebServerManager`: starts the web server for a custom client.
- `Symfony\Component\Panther\Exception\ExceptionInterface`: the Panther exception classes implement it. The wait methods throw php-webdriver exceptions, which do not implement it.
- Assertions in `PantherTestCase`: `assertSelectorWillExist()`, `assertSelectorWillNotExist()`, `assertSelectorWillBeVisible()`, `assertSelectorWillNotBeVisible()`, `assertSelectorWillContain()`, `assertSelectorWillNotContain()`, `assertSelectorWillBeEnabled()`, `assertSelectorWillBeDisabled()`, `assertSelectorAttributeWillContain()`, `assertSelectorAttributeWillNotContain()`, `assertSelectorIsVisible()`, `assertSelectorIsNotVisible()`, `assertSelectorIsEnabled()`, `assertSelectorIsDisabled()`, `assertSelectorAttributeContains()`, `assertSelectorAttributeNotContains()`.
- Environment variables: the `PANTHER_*` list in "Key features and concepts".
- MakerBundle: `make:test PantherTestCase <ClassName>` generates a Panther test class.
- Panther has no bundle, no configuration keys, no services, no attributes and no Twig functions.

## Symbiotic packages

- [BrowserKit](../packages/browser-kit.md): The Panther `Client` extends `AbstractBrowser`, so `request()`, `clickLink()` and `submitForm()` work as in `HttpBrowser`; if the page needs no JavaScript, use `HttpBrowser`.
- [DomCrawler](../packages/dom-crawler.md): The Panther `Crawler` extends the DomCrawler `Crawler` with WebDriver elements, so `filter()`, `text()`, `attr()`, `link()` and `form()` work on the live page.
- [CssSelector](../packages/css-selector.md): The Panther crawler methods `matches()`, `closest()` and `children($selector)` need it, but `filter()` uses the CSS engine of the browser.
- [FrameworkBundle test tools](../packages/framework-bundle-testing.md): `PantherTestCase` extends `WebTestCase`, and the Panther assertions need FrameworkBundle; if a test needs no JavaScript, use `KernelBrowser` and its `loginUser()`.
- [HttpClient](../packages/http-client.md): `createHttpBrowserClient()` sends real HTTP requests through HttpClient, with the `http_client_options` option.
- [Process](../packages/process.md): Panther starts ChromeDriver, geckodriver and the PHP built-in web server as subprocesses, and an `env` value of `false` removes that variable.
- [Dotenv](../packages/dotenv.md): The application in the web server loads the `.env` files again and can replace your `env` values. To keep them, add `'SYMFONY_DOTENV_VARS' => false` to the `env` option.
- [Mercure](../packages/mercure.md): `createAdditionalPantherClient()` opens a second isolated browser, so a test can check that one user receives the Mercure update of another user.
- [Symfony UX Turbo](../packages/ux-turbo.md): Turbo changes the page with JavaScript, so its docs test Turbo Frames with `PantherTestCase` and `assertSelectorWillContain()`.
- [AssetMapper](../packages/asset-mapper.md): The PHP built-in web server returns 404 for assets that AssetMapper serves in `dev`; run `asset-map:compile` before the tests, or set `PANTHER_WEB_SERVER_ROUTER`.
- [MakerBundle](../packages/maker-bundle.md): `make:test` with the type `PantherTestCase` generates a test class that calls `createPantherClient()`.

## Changed in 1.0 to 2.4

- 2.4.0: Panther allows `symfony/http-client` 8 and matches the BrowserKit 8 and DomCrawler 8 method signatures. With Symfony 8, use Panther 2.4 or later. The CI of Panther 2.4.0 also tests PHPUnit 11.5.
- 2.3.0: The browser dev tools are off by default. To open them, set `PANTHER_DEVTOOLS=1`.
- 2.2.0: By default, the browser asks the pages to reduce motion (`prefers-reduced-motion: reduce`). To get the normal animations, set `PANTHER_NO_REDUCED_MOTION=1`.
- 2.2.0: Selenium works with the built-in web server. Set the `browser` option to `PantherTestCase::SELENIUM`. Then give the `host` and `capabilities` manager options.
- 2.2.0: `createHttpBrowserClient()` accepts the `http_client_options` option. Panther has its own exception classes, which implement `Symfony\Component\Panther\Exception\ExceptionInterface`. The docs moved from the README to symfony.com.
- 2.1.0: Panther supports PHPUnit 10. With PHPUnit 10 or later, register `<bootstrap class="Symfony\Component\Panther\ServerExtension"/>`, not `<extension class="…"/>`.
- 1.0.0: Removed the PHPUnit listener; use the `ServerExtension` PHPUnit extension. Removed the Goutte support; use `createHttpBrowserClient()`. Removed `PANTHER_CHROME_DRIVER_BINARY` and `PANTHER_GECKO_DRIVER_BINARY`; put the drivers in the `PATH` or in `drivers/`.

## Status

Panther is a library with its own version line (2.x), not a bundle. It needs the PHP extensions `dom` and `libxml`, a Chrome or Firefox browser, and the matching driver binary. Install it as a dev dependency.
