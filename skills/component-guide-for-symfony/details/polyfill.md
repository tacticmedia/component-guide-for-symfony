# Symfony Polyfill (`symfony/polyfill-*`): details

**Applies to:** Symfony Polyfill 1.43, Symfony 8.1

## Key features and concepts

- **One package for each PHP version or extension:** Each `symfony/polyfill-*` package covers one PHP version or one extension. Require only the packages that your code needs. Do not require the all-in-one `symfony/polyfill` package, because Composer then cannot share the polyfills correctly in the dependency graph. Entry point: `composer require symfony/polyfill-php85`.
- **Native code first:** Most packages list a `bootstrap.php` file in `autoload.files`, so `vendor/autoload.php` loads it. A version polyfill stops immediately when `\PHP_VERSION_ID` is equal to or higher than its PHP version. Most extension polyfills stop when PHP loads the extension. Each bootstrap file defines a function only when `function_exists()` returns `false`. The mbstring and grapheme polyfills also define newer functions, such as `mb_trim()`, when PHP loads an older version of the extension. Entry point: the global function, for example `str_contains()`.
- **Classes from stubs:** Most packages declare the global classes, interfaces, enums and attributes in `Resources/stubs`, and the Composer classmap loads them. The autoloader loads a stub only for a class that PHP does not define, and most stubs also check `\PHP_VERSION_ID`. The implementation classes, such as `Symfony\Polyfill\Php80\Php80`, are `@internal`. Use the global names in your code. Entry point: for example `new \ReflectionConstant('PHP_VERSION')`.
- **Same contract as the native function:** The bootstrap files declare the native signature of the running PHP version. Some functions always throw a `\ValueError` for invalid input, for example `json_validate()` and `grapheme_str_split()`. Their polyfills also throw it on PHP 7, where the polyfill declares the missing `ValueError` class. If a native function returns `false` for invalid input on PHP 7, its polyfill also returns `false` on PHP 7, for example `grapheme_extract()`. The polyfill accepts and ignores new arguments that it cannot implement, for example the `$locale` argument of the `grapheme_*()` functions. Entry point: `\ValueError`.
- **Version polyfills that need an extension:** The version polyfills define some functions only when PHP loads the related extension. For example, `bcround()` needs bcmath, `mb_trim()` needs mbstring, and `grapheme_str_split()` needs intl. Without mbstring, require `symfony/polyfill-mbstring`, which defines the same `mb_*()` functions. Without intl, require `symfony/polyfill-intl-grapheme`, which defines the same `grapheme_*()` functions. Entry point: `mb_trim()`, `grapheme_str_split()`.
- **Attributes as markers:** `#[\Override]`, `#[\Deprecated]`, `#[\NoDiscard]`, `#[\SensitiveParameter]`, `#[\AllowDynamicProperties]`, `#[\ReturnTypeWillChange]` and `#[\DelayedTargetValidation]` exist on older PHP versions, so reflection can read them. On an older PHP version, they have no runtime effect, because the effect needs engine support. Entry point: `#[\Override]`.
- **Exception classes for `catch` blocks:** Before PHP 8.3, the `Date*Exception`, `Date*Error` and `\SQLite3Exception` classes exist only for `catch` blocks and `instanceof` checks. No polyfill code throws them. Before PHP 8.5, the same applies to `Filter\FilterException` and `Filter\FilterFailedException`. The polyfills do not define `FILTER_THROW_ON_FAILURE`, so its absence stays usable for feature detection. Entry point: `catch (\DateMalformedStringException $e)`.
- **Partial mbstring:** `symfony/polyfill-mbstring` is a partial, UTF-8 based implementation on top of iconv, and it requires `ext-iconv`. It does not define `mb_strimwidth()`, `mb_strcut()`, `mb_split()`, the `mb_ereg*()` and `mb_regex_*()` functions, `mb_convert_kana()`, `mb_preferred_mime_name()` or `mb_send_mail()`. `mb_list_encodings()` returns only `UTF-8`. `mb_encode_mimeheader()` does not encode: it triggers a warning that recommends `iconv_mime_encode()`, and on PHP 8 it then throws a `TypeError`. Entry point: `mb_strlen()`, `mb_substr()`, `mb_convert_case()`.
- **English-only intl:** In `symfony/polyfill-intl-icu`, the `Collator`, `NumberFormatter` and `IntlDateFormatter` constructors accept only the `en` locale or `null`. Other locales, for example `en_US`, throw a `MethodArgumentValueNotImplementedException`. `IntlListFormatter` accepts all locales that start with `en`. A method that the polyfill does not implement throws a `MethodNotImplementedException`, and the message tells you to install the intl extension. These exceptions are in the `Symfony\Polyfill\Intl\Icu\Exception` namespace. `NumberFormatter::format()` throws an exception for the `CURRENCY` style. For currencies, use `NumberFormatter::formatCurrency()`. `symfony/polyfill-intl-messageformatter` uses English rules for `plural` and `selectordinal` with all locales, and it supports `select` and simple arguments. It formats the `number` type only without a style or with the `integer` style. For other types, such as `date`, `format()` returns `false`. Entry point: `\MessageFormatter::formatMessage('en', $pattern, $values)`.
- **IDN, normalization and graphemes:** `symfony/polyfill-intl-idn` converts domain names with UTS #46, and it requires `symfony/polyfill-intl-normalizer`. `symfony/polyfill-intl-normalizer` gives the `Normalizer` class and the `normalizer_*()` functions. `symfony/polyfill-intl-grapheme` gives 12 `grapheme_*()` functions. `idn_to_ascii()` calls `mb_chr()`, and some `grapheme_*()` functions call `mb_*()` or `iconv_strlen()`, but these packages do not require mbstring or iconv. Without the mbstring extension, also require `symfony/polyfill-mbstring`. Entry point: `idn_to_ascii()`, `\Normalizer::normalize()`, `grapheme_strlen()`.
- **UUID functions:** `symfony/polyfill-uuid` gives `uuid_create()`, 11 other `uuid_*()` functions and the `UUID_TYPE_*` and `UUID_VARIANT_*` constants. `uuid_create()` creates v1, v4, v6 or v7 UUIDs. On PHP 8, an unknown type throws a `\ValueError`. When APCu is enabled on 64-bit PHP, v1 and v6 UUIDs share the last timestamp and the node across processes. Entry point: `uuid_create(\UUID_TYPE_TIME_V7)`.
- **deepclone functions:** `symfony/polyfill-deepclone` needs PHP 8.1. It gives `deepclone_to_array()`, `deepclone_from_array()`, `deepclone_hydrate()`, three `DEEPCLONE_HYDRATE_*` flags and two exception classes. Its README says that the extension gives the same functions 4 to 5 times faster. To get this speed, install the extension with `pie install symfony/deepclone`. The extension needs PHP 8.2, so on PHP 8.1 only the polyfill is available. Do not pass untrusted input to `deepclone_from_array()`. Entry point: `deepclone_hydrate(Foo::class, ['name' => $name])`.
- **PHP 8.6 APIs on PHP 8.1 or later:** `symfony/polyfill-io-poll` gives `Io\Poll\Context`, `Io\Poll\Watcher`, `\StreamPollHandle` and the `Backend` and `Event` enums. It uses `stream_select()`, so only the `Poll` backend works, and it does not support edge-triggered events. `Context::wait()` takes a `Time\Duration` timeout, but the package does not require `symfony/polyfill-time`. If you give a timeout on PHP 8.5 or older, also require `symfony/polyfill-time`. Entry point: `new \Io\Poll\Context()`, `Context::add()`, `Context::wait(\Time\Duration::fromMilliseconds(100))`.
- **APCu on top of APC:** `symfony/polyfill-apcu` defines the `apcu_*()` functions only when PHP loads the legacy `apc` extension or the `apcu` extension. It maps them to the `apc_*()` functions. Without one of these extensions, it defines nothing, so it is not a cache. Entry point: `apcu_fetch()`.
- **When an application needs a polyfill, and when it does not:** Composer installs the polyfills that your dependencies require. If your code calls a function that your minimum PHP version or server does not have, require its polyfill. If your minimum PHP version or a required `ext-*` package gives the functions, add the polyfill to `replace`. Then Composer does not install it. Symfony 8 requires PHP 8.4, so `symfony/polyfill-php73` to `symfony/polyfill-php84` define nothing in a Symfony 8 application. The `symfony/skeleton` project replaces `symfony/polyfill-php72` to `symfony/polyfill-php84`, `symfony/polyfill-ctype` and `symfony/polyfill-iconv`, because it requires PHP 8.4, `ext-ctype` and `ext-iconv`. Symfony 8.1 requires `symfony/polyfill-php85` for `array_first()` and `get_error_handler()` on PHP 8.4. On PHP 8.4, do not replace `symfony/polyfill-php85`. Entry point: the `replace` section of `composer.json`.

## Entry points

Each line gives the package, the PHP version or extension that it replaces, its latest release on Packagist, and what it defines. Except for the legacy metapackages, all packages need PHP 7.2 or later, or PHP 8.1 or later when the line says so.

- `symfony/polyfill-php73` (PHP 7.3; v1.37.0): `array_key_first()`, `array_key_last()`, `hrtime()`, `is_countable()`, `\JsonException`.
- `symfony/polyfill-php74` (PHP 7.4; v1.43.0): `get_mangled_object_vars()`, `password_algos()`, and `mb_str_split()` with the mbstring extension.
- `symfony/polyfill-php80` (PHP 8.0; v1.43.0): `str_contains()`, `str_starts_with()`, `str_ends_with()`, `get_debug_type()`, `get_resource_id()`, `fdiv()`, `preg_last_error_msg()`, `FILTER_VALIDATE_BOOL`, `\Attribute`, `\Stringable`, `\ValueError`, `\UnhandledMatchError`, and `\PhpToken` with the tokenizer extension.
- `symfony/polyfill-php81` (PHP 8.1; v1.38.1): `array_is_list()`, `enum_exists()` (always returns `false`) and `#[\ReturnTypeWillChange]`. With mysqli: `MYSQLI_REFRESH_REPLICA`. With curl: `\CURLStringFile` (PHP 7.4 or later) and `CURLOPT_ISSUERCERT_BLOB` (libcurl 7.71.0 or later).
- `symfony/polyfill-php82` (PHP 8.2; v1.43.0): `ini_parse_quantity()`, `#[\AllowDynamicProperties]`, `#[\SensitiveParameter]`, `\SensitiveParameterValue`, `Random\Engine`, `Random\CryptoSafeEngine` and `Random\Engine\Secure`. Also `Random\RandomError`, `Random\BrokenRandomEngineError` and `Random\RandomException`. With odbc: `odbc_connection_string_is_quoted()`, `odbc_connection_string_should_quote()` and `odbc_connection_string_quote()`. With curl: `CURLOPT_SSH_HOST_PUBLIC_KEY_SHA256` (libcurl 7.80.0 or later).
- `symfony/polyfill-php83` (PHP 8.3; v1.43.0): `json_validate()`, `str_increment()`, `str_decrement()`, `stream_context_set_options()`, `#[\Override]`, `\DateError`, `\DateException` and their seven subclasses, and `\SQLite3Exception`. With mbstring: `mb_str_pad()`. With ldap: `ldap_exop_sync()` and `ldap_connect_wallet()`.
- `symfony/polyfill-php84` (PHP 8.4; v1.43.0): `array_find()`, `array_find_key()`, `array_any()`, `array_all()`, `fpow()`, `#[\Deprecated]`, `\RoundingMode` and `\ReflectionConstant`. With mbstring: `mb_ucfirst()`, `mb_lcfirst()`, `mb_trim()`, `mb_ltrim()` and `mb_rtrim()`. With bcmath: `bcceil()`, `bcfloor()`, `bcround()` and `bcdivmod()`. With intl: `grapheme_str_split()`. With the matching PDO driver: `Pdo\Mysql`, `Pdo\Pgsql`, `Pdo\Sqlite`, `Pdo\Odbc`, `Pdo\Firebird` and `Pdo\Dblib`. With curl: `CURL_HTTP_VERSION_3` (libcurl 7.66.0 or later) and `CURL_HTTP_VERSION_3ONLY` (libcurl 7.88.0 or later).
- `symfony/polyfill-php85` (PHP 8.5; v1.43.0): `array_first()`, `array_last()`, `get_error_handler()`, `get_exception_handler()`, `#[\NoDiscard]`, `#[\DelayedTargetValidation]`, `Filter\FilterException` and `Filter\FilterFailedException`. With intl: `locale_is_right_to_left()` and `grapheme_levenshtein()`.
- `symfony/polyfill-php86` (PHP 8.6; v1.43.0): `clamp()`, `ARRAY_FILTER_USE_VALUE`, `grapheme_strrev()` (with intl), and `\SortDirection` (on PHP 8.1 or later).
- `symfony/polyfill-io-poll` (PHP 8.6 `Io\Poll` API; needs PHP 8.1; v1.43.0): `Io\Poll\Context`, `Io\Poll\Watcher`, `Io\Poll\Handle`, `\StreamPollHandle`, the `Io\Poll\Backend` and `Io\Poll\Event` enums, `Io\IoException` and the `Io\Poll\*Exception` classes.
- `symfony/polyfill-time` (PHP 8.6 `Time` API; needs PHP 8.1; v1.42.0, the only release): `Time\Duration`, `Time\TimeException`.
- `symfony/polyfill-ctype` (ctype extension; v1.37.0; declares `provide: ext-ctype`): the 11 `ctype_*()` functions, with ASCII character classes.
- `symfony/polyfill-iconv` (iconv extension; v1.43.0; declares `provide: ext-iconv`): `iconv()`, `iconv_strlen()`, `iconv_strpos()`, `iconv_strrpos()`, `iconv_substr()`, `iconv_mime_encode()`, `iconv_mime_decode()`, `iconv_mime_decode_headers()`, `iconv_get_encoding()`, `iconv_set_encoding()` and the `ICONV_*` constants. It does not define `ob_iconv_handler()`.
- `symfony/polyfill-mbstring` (mbstring extension; v1.43.0; requires `ext-iconv`; declares `provide: ext-mbstring`): 44 `mb_*()` functions and the `MB_CASE_UPPER`, `MB_CASE_LOWER` and `MB_CASE_TITLE` constants.
- `symfony/polyfill-intl-grapheme` (grapheme functions of the intl extension; v1.43.0): `grapheme_extract()`, `grapheme_strlen()`, `grapheme_substr()`, `grapheme_strpos()`, `grapheme_stripos()`, `grapheme_strrpos()`, `grapheme_strripos()`, `grapheme_strstr()`, `grapheme_stristr()`, `grapheme_str_split()`, `grapheme_levenshtein()`, `grapheme_strrev()` and the `GRAPHEME_EXTR_*` constants.
- `symfony/polyfill-intl-icu` (intl extension, `en` locale only; v1.43.0): `\Collator`, `\NumberFormatter`, `\Locale`, `\IntlDateFormatter`, `\IntlListFormatter`, `intl_get_error_code()`, `intl_get_error_message()`, `intl_is_failure()`, `intl_error_name()`.
- `symfony/polyfill-intl-idn` (IDN functions of the intl extension; v1.43.0; requires `symfony/polyfill-intl-normalizer`): `idn_to_ascii()`, `idn_to_utf8()`, the `IDNA_*` constants and `INTL_IDNA_VARIANT_UTS46`.
- `symfony/polyfill-intl-messageformatter` (`MessageFormatter` of the intl extension; v1.43.0): `\MessageFormatter`, `msgfmt_format_message()`, `\IntlException`.
- `symfony/polyfill-intl-normalizer` (`Normalizer` of the intl extension; v1.43.0): `\Normalizer`, `normalizer_normalize()`, `normalizer_is_normalized()`, `normalizer_get_raw_decomposition()`.
- `symfony/polyfill-uuid` (uuid extension; v1.43.0; declares `provide: ext-uuid`): `uuid_create()`, `uuid_generate_md5()`, `uuid_generate_sha1()`, `uuid_is_valid()`, `uuid_compare()`, `uuid_is_null()`, `uuid_type()`, `uuid_variant()`, `uuid_time()`, `uuid_mac()`, `uuid_parse()`, `uuid_unparse()`, and the `UUID_TYPE_*` and `UUID_VARIANT_*` constants.
- `symfony/polyfill-deepclone` (deepclone extension; needs PHP 8.1; v1.43.1; declares `provide: ext-deepclone`): `deepclone_to_array()`, `deepclone_from_array()`, `deepclone_hydrate()`, `DEEPCLONE_HYDRATE_CALL_HOOKS`, `DEEPCLONE_HYDRATE_NO_LAZY_INIT`, `DEEPCLONE_HYDRATE_PRESERVE_REFS`, `DeepClone\ClassNotFoundException`, `DeepClone\NotInstantiableException`.
- `symfony/polyfill-apcu` (apcu extension, on top of the legacy apc extension; v1.37.0): 11 `apcu_*()` functions, for example `apcu_fetch()` and `apcu_store()`, and `\APCuIterator`.
- `symfony/polyfill-util` (no PHP feature; v1.43.0): `Symfony\Polyfill\Util\Binary` for byte-safe string functions with `mbstring.func_overload`, and the PHPUnit test listener of the polyfill test suite.
- `symfony/polyfill` (all-in-one package; v1.43.1): it contains and replaces the 23 packages above. Do not require it.
- Legacy metapackages: `symfony/polyfill-php54`, `symfony/polyfill-php55`, `symfony/polyfill-php56`, `symfony/polyfill-php70` and `symfony/polyfill-php71` (last release v1.20.0, 2020-10-23), and `symfony/polyfill-php72` (last release v1.31.0, 2024-09-09). Each last release is an empty `metapackage`, and the monorepo does not contain them. Do not add them to `require`.
- The `replace` section of `composer.json`, for example `"replace": {"symfony/polyfill-php84": "*"}`: it removes a polyfill that your PHP version or your required extensions make unnecessary.
- Without FrameworkBundle: require the polyfill package with Composer. `vendor/autoload.php` loads its bootstrap file and its stubs, so the global functions and classes work in any PHP code.

## Symbiotic packages

- [String](../packages/string.md): String requires the mbstring, grapheme, normalizer and ctype polyfills; for UTF-8 text, use `u()` instead of `mb_*()` calls.
- [Uid](../packages/uid.md): Uid requires `symfony/polyfill-uuid` and calls `uuid_create()` in `UuidV1`; in an application, use `Uuid::v7()` instead of the `uuid_*()` functions.
- [VarExporter](../packages/var-exporter.md): VarExporter requires `symfony/polyfill-deepclone`; in application code, use `DeepCloner::deepClone()`, which calls the `deepclone_*()` functions.
- [Cache](../packages/cache.md): `PhpFilesAdapter` and `PhpArrayAdapter` restore cached objects with the `deepclone_*()` functions, which the deepclone extension runs several times faster than the polyfill.
- [DependencyInjection](../packages/dependency-injection.md): The loaders and compiler passes copy service definitions with `DeepCloner`, so the deepclone extension also makes the container compilation faster.
- [Translation](../packages/translation.md): Translation requires `symfony/polyfill-mbstring`, and without intl its `IntlFormatter` needs `symfony/polyfill-intl-messageformatter`, which supports only English.
- [Intl](../packages/intl.md): Intl and `symfony/polyfill-intl-icu` are different: Intl gives locale data, such as country and currency names, and the polyfill gives English-only `NumberFormatter` and `IntlDateFormatter` classes.
- [Form](../packages/form.md): Form requires `symfony/polyfill-intl-icu`, so its localized number and date transformers work without intl, but only for the `en` locale.
- [Mime](../packages/mime.md): Mime requires `symfony/polyfill-intl-idn` and `symfony/polyfill-mbstring`, and `IdnAddressEncoder` converts the domain of an email address with `idn_to_ascii()`.
- [HttpClient](../packages/http-client.md): HttpClient does not require `symfony/polyfill-intl-idn`, so for a non-ASCII URL host without intl, require the polyfill to prevent an `InvalidArgumentException`.
- [Console](../packages/console.md): Console requires `symfony/polyfill-mbstring` and `symfony/polyfill-php85`, and `CombinedOutput` calls `array_first()`.
- [ErrorHandler](../packages/error-handler.md): ErrorHandler requires `symfony/polyfill-php85` and calls `get_error_handler()` to find the previous error handler.
- [FrameworkBundle](../packages/framework-bundle.md): FrameworkBundle requires `symfony/polyfill-mbstring` and `symfony/polyfill-php85`, and `FrameworkBundle::boot()` calls `get_error_handler()`.
- [Tui](../packages/tui.md): Tui requires `symfony/polyfill-intl-grapheme` 1.42.1 or later, because `TextWrapper` and `CellBuffer` split terminal text with `grapheme_*()` functions.
- [Clock](../packages/clock.md): The Clock docs say that Clock requires `symfony/polyfill-php83`. Clock 8.1 does not require it, because PHP 8.4 defines `\DateInvalidTimeZoneException`.
- [PHPUnit Bridge](../packages/phpunit-bridge.md): The bridge polyfills PHPUnit methods, not PHP functions: on PHPUnit 9 or older, its `simple-phpunit` script adds `PolyfillAssertTrait` to the `Assert` class.
- [Symfony Requirements Checker](../packages/requirements-checker.md): When it runs from `vendor/bin`, the checker loads `vendor/autoload.php`, so the polyfills pass its `iconv()`, `ctype_alpha()` and `mb_strlen()` checks, but not its intl extension check.

## Changed in 1.31 to 1.43 (and Symfony 8.1)

- 1.31.0 and 1.32.0: The minimum PHP version is 7.2, and the monorepo no longer contains `symfony/polyfill-php72`. Remove `symfony/polyfill-php72` from `require`, because its last release is an empty metapackage.
- 1.33.0: `array_first()`, `array_last()`, `bcdivmod()`, `grapheme_str_split()` and `\ReflectionConstant` are new. Use `array_first()` and `array_last()` instead of `reset()` and `end()`.
- 1.34.0 and 1.35.0: `symfony/polyfill-deepclone` and `symfony/polyfill-php86` are new packages. Version 1.35.0 adds `deepclone_hydrate()`, `ARRAY_FILTER_USE_VALUE` and `\SortDirection`.
- 1.38.0: On PHP 8.5 or later, `UUID_TYPE_DCE` and `UUID_TYPE_NAME` are deprecated. Use `UUID_TYPE_RANDOM` and `UUID_TYPE_TIME` instead.
- 1.38.1: This release fixes CVE-2026-46644 in `idn_to_ascii()` and `idn_to_utf8()`. Keep the polyfills at the latest 1.x release, because only that release gets security fixes.
- 1.41.0 and 1.42.0: `symfony/polyfill-io-poll` and `symfony/polyfill-time` are new packages. Since 1.42.0, `Io\Poll\Context::wait()` takes its timeout as a `Time\Duration`.
- 1.43.0: `uuid_create()` creates v6 and v7 UUIDs with the new `UUID_TYPE_TIME_V6` and `UUID_TYPE_TIME_V7` constants.
- Symfony 8.1: VarExporter deprecates `Hydrator` and `Instantiator`. Use `deepclone_hydrate()` instead.

## Status

- The legacy metapackages `symfony/polyfill-php54` to `symfony/polyfill-php72` get no new releases. Packagist does not mark them as abandoned.
- `symfony/polyfill-apcu` needs the `apc` or `apcu` extension. Some functions of other packages also need an extension, as the Entry points section shows.
- `symfony/polyfill-apcu` v1.37.0 (2024-09-10) does not contain one later monorepo change: the `mixed` return type of `apcu_fetch()` in the Zend Data Cache branch. The `1.x` branch of `symfony/polyfill-apcu` contains the change, but no tag points to it. The other 22 split packages have the same content as v1.43.1, also when their latest tag is older.
- Some packages are partial: mbstring, the intl packages (English only) and `Io\Poll` (one backend). The README recommends a newer PHP version or the missing extension when possible.
