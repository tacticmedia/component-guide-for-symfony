# EventDispatcher (`symfony/event-dispatcher`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **Synchronous dispatch.** `dispatch()` calls the listeners one after the other in the same process, and returns after the last listener. If the work is slow, needs a background worker or needs retries, dispatch a Messenger message instead. A `kernel.terminate` listener runs after Symfony sends the response. Outside debug mode, the client gets the response before the listener ends only with PHP-FPM, FrankenPHP or LiteSpeed. Entry point: `Symfony\Contracts\EventDispatcher\EventDispatcherInterface::dispatch()`.
- **Event classes.** An event class extends `Symfony\Contracts\EventDispatcher\Event` and carries the data for the listeners. If you do not give an event name, `dispatch()` uses the fully qualified class name (FQCN) of the event as the name. `dispatch()` returns the same event object, so the caller can read the values that the listeners changed. The dispatcher calls each listener with the event, the event name and the dispatcher. Entry point: `Symfony\Contracts\EventDispatcher\Event`.
- **`#[AsEventListener]`.** This attribute registers a class or a method as a listener. Its arguments are `event`, `method`, `priority` and `dispatcher`, and you can repeat it. If you do not set `event`, Symfony reads the event class from the first parameter type of the listener method (`__invoke()` by default). With a union type, Symfony registers the listener for each class. If you set `event` but not `method` on a class, Symfony calls the `on` + PascalCased event name method, for example `onKernelException()`. If that method does not exist, Symfony calls `__invoke()`. If you put the attribute on a method, do not set `method`: Symfony throws a `LogicException`. Symfony creates the listener service only when the dispatcher needs it. Entry point: `Symfony\Component\EventDispatcher\Attribute\AsEventListener`.
- **Event subscribers.** A class that implements `EventSubscriberInterface` returns its events, methods and priorities from the static `getSubscribedEvents()` method. Each value is a method name, a `[method, priority]` array, or a list of these arrays. Symfony calls `getSubscribedEvents()` when it compiles the container, so the result must not depend on runtime state. The main docs page presents listeners and subscribers as equal choices. A subscriber keeps the event list in the class, and a bundle can enable or disable a listener with a configuration value. Entry point: `Symfony\Component\EventDispatcher\EventSubscriberInterface`.
- **Priorities.** A listener with a higher priority runs earlier. The default priority is `0`, and you can also use negative values. Listeners with the same priority run in the order in which you add them. Symfony's own listeners usually use priorities from `-256` to `256`. For example, a `kernel.exception` listener with priority `2` runs before the Security `ExceptionListener`, which has priority `1`. Entry points: the `priority` argument of `#[AsEventListener]` and of the `kernel.event_listener` tag, and the third argument of `addListener()`.
- **Stop propagation.** A listener calls `$event->stopPropagation()`, and the dispatcher does not call the listeners that follow. After `dispatch()`, the caller can check `$event->isPropagationStopped()`. These framework methods also stop propagation: `RequestEvent::setResponse()` (also on `ExceptionEvent` and `ViewEvent`) and the Mailer `MessageEvent::reject()`. Entry point: `Symfony\Contracts\EventDispatcher\Event::stopPropagation()`.
- **Event aliases.** You can use the FQCN of a core event class as the event name, for example `RequestEvent::class` for `kernel.request`. FrameworkBundle, ConsoleBundle and SecurityBundle register these aliases for the kernel, form, workflow, console and security events. To add aliases for your own events, register `AddEventAliasesPass` in `Kernel::build()`. If you alias a custom event class, dispatch the event with the alias name. A dispatch without a name uses the FQCN, and the listeners from the container do not get the event. The aliases apply only to listeners and subscribers from the container, not to `addListener()` or `addSubscriber()` calls. Entry point: `Symfony\Component\EventDispatcher\DependencyInjection\AddEventAliasesPass`.
- **Several dispatchers.** The `dispatcher` argument of `#[AsEventListener]`, `kernel.event_listener` and `kernel.event_subscriber` adds the listener to another dispatcher service. Each security firewall has its own dispatcher, `security.event_dispatcher.<firewall>`. A listener on the global dispatcher also gets the security events of each firewall. To listen to one firewall only, add the listener to the dispatcher of that firewall. Entry point: the `dispatcher` argument, for example `#[AsEventListener(dispatcher: 'security.event_dispatcher.main')]`.
- **Debug command.** `debug:event-dispatcher` shows each event with its listeners in call order, with their priorities. To filter the list, give an event name or a part of it, for example `kernel` or `Security`. Use `--dispatcher` to show another dispatcher. Use `--format` to get `txt`, `xml`, `json` or `md` output. Entry point: `php bin/console debug:event-dispatcher`.
- **Traceable dispatcher.** `TraceableEventDispatcher` wraps another dispatcher, times each listener with a `Stopwatch`, and records the listeners that ran. `getCalledListeners()`, `getNotCalledListeners()` and `getOrphanedEvents()` return the records. An orphaned event is a dispatched event without listeners. In debug mode, FrameworkBundle decorates `event_dispatcher` with the HttpKernel subclass of this class (service `debug.event_dispatcher`). The profiler shows the records in its events panel. Entry point: `Symfony\Component\EventDispatcher\Debug\TraceableEventDispatcher`.
- **Immutable dispatcher.** `ImmutableEventDispatcher` wraps a dispatcher that you configured before. `dispatch()` and the read methods work. `addListener()`, `addSubscriber()`, `removeListener()` and `removeSubscriber()` throw a `BadMethodCallException`. The Form component uses it to lock the dispatcher of each form after the build. Entry point: `Symfony\Component\EventDispatcher\ImmutableEventDispatcher`.
- **Before and after filters.** A `kernel.controller` listener runs before each controller, and a `kernel.response` listener runs after the controller returns a response. In the docs example, controllers implement an empty `TokenAuthenticatedController` interface. `onKernelController()` checks the token and stores it in the request attributes. `onKernelResponse()` reads the token and adds an `X-CONTENT-HASH` header. If the controller is an `[object, 'method']` array, check `$controller[0]`. The kernel also dispatches these events for sub-requests. If the code is for the main request only, check `$event->isMainRequest()` first. To act on a controller attribute, listen to the `<kernel event>.<attribute FQCN>` event. Its listener gets a `ControllerAttributeEvent`. Entry points: `KernelEvents::CONTROLLER`, `KernelEvents::RESPONSE`.
- **Method hooks without inheritance.** To let other code change a method without a subclass, dispatch events at its start and end. In the docs example, `CustomMailer::send()` dispatches a `BeforeSendMailEvent` as `mailer.pre_send` and an `AfterSendMailEvent` as `mailer.post_send`. Listeners change the subject, the message or the return value through setters on the event. Entry point: `EventDispatcherInterface::dispatch($event, 'mailer.pre_send')`.
- **GenericEvent.** `GenericEvent` carries a subject and an array of arguments, so you do not need a custom event class. `getArgument()` throws an `InvalidArgumentException` for a missing key. The docs example `$event['counter']++` has no effect, because `offsetGet()` returns a value, not a reference. Use `setArgument()` or `$event['counter'] = $event['counter'] + 1`. Entry point: `Symfony\Component\EventDispatcher\GenericEvent`.
- **Runtime listener management.** The component `EventDispatcherInterface` adds, lists and removes listeners at runtime. `addListener()` takes any PHP callable, a closure included, and an optional priority. `getListeners()` returns the listeners in call order. `getListenerPriority()` returns `null` if the event has no such listener. Without the framework, create a `new EventDispatcher()`, or register `RegisterListenersPass` on a standalone `ContainerBuilder`. Entry point: `Symfony\Component\EventDispatcher\EventDispatcherInterface`.

## Entry points

- Autowire `Symfony\Contracts\EventDispatcher\EventDispatcherInterface` to dispatch events. The service ID is `event_dispatcher`.
- Autowire `Symfony\Component\EventDispatcher\EventDispatcherInterface` to also add, list or remove listeners.
- Autowire `Psr\EventDispatcher\EventDispatcherInterface` (from the third-party `psr/event-dispatcher` package) for a library that expects a PSR-14 dispatcher.
- Base class `Symfony\Contracts\EventDispatcher\Event` (`stopPropagation()`, `isPropagationStopped()`), and the ready-made `Symfony\Component\EventDispatcher\GenericEvent`.
- Attribute `Symfony\Component\EventDispatcher\Attribute\AsEventListener` (arguments `event`, `method`, `priority`, `dispatcher`).
- Interface `Symfony\Component\EventDispatcher\EventSubscriberInterface` (static `getSubscribedEvents()`).
- Service tags `kernel.event_listener` (attributes `event`, `method`, `priority`, `dispatcher`) and `kernel.event_subscriber` (attribute `dispatcher`). Autoconfiguration adds them for `#[AsEventListener]` and `EventSubscriberInterface`.
- Service tag `event_dispatcher.dispatcher` (attribute `name`). Autoconfiguration adds it to each service that implements the component `EventDispatcherInterface`. `debug:event-dispatcher --dispatcher` and the profiler find the dispatchers through this tag.
- Event name constants: `Symfony\Component\HttpKernel\KernelEvents`, `Symfony\Component\Console\ConsoleEvents`.
- Classes: `Symfony\Component\EventDispatcher\EventDispatcher`, `Symfony\Component\EventDispatcher\ImmutableEventDispatcher`, `Symfony\Component\EventDispatcher\Debug\TraceableEventDispatcher`.
- Compiler passes: `Symfony\Component\EventDispatcher\DependencyInjection\AddEventAliasesPass` (event aliases, hot-path events, no-preload events) and `Symfony\Component\EventDispatcher\DependencyInjection\RegisterListenersPass`. The framework registers `RegisterListenersPass`. Add it yourself only on a standalone `ContainerBuilder`.
- Without FrameworkBundle: create a `new EventDispatcher()` and call `addListener()`, `addSubscriber()` and `dispatch()`, or register `RegisterListenersPass` on a standalone `ContainerBuilder`. In a console application without FrameworkBundle, the DependencyInjection `ServicesBundle` defines `event_dispatcher`.
- Container parameter `event_dispatcher.event_aliases` (the alias map).
- Services: `event_dispatcher`, `debug.event_dispatcher` (debug mode only), `security.event_dispatcher.<firewall>` (SecurityBundle).
- Config key: none. FrameworkBundle has no `framework.event_dispatcher` key.
- Console commands: `debug:event-dispatcher [event] [--dispatcher=<service ID>] [--format=txt|xml|json|md] [--raw]`, and `debug:container --tag=kernel.event_listener`.
- Profiler: the events panel, with the called listeners, the not called listeners and the orphaned events.
- Twig: none.
- Test helpers: FrameworkBundle has no event assertions. In a unit test, use a `new EventDispatcher()` and check the event that `dispatch()` returns.

## Symbiotic packages

- [Messenger](../packages/messenger.md): Dispatch a Messenger message instead of an event for slow, queued or retried work; the Messenger worker also dispatches events such as `WorkerMessageFailedEvent`.
- [HttpKernel](../packages/http-kernel.md): The kernel dispatches the `KernelEvents`, from `kernel.request` to `kernel.terminate`, and controller attribute events named `<kernel event>.<attribute FQCN>`.
- [FrameworkBundle](../packages/framework-bundle.md): FrameworkBundle adds `debug:event-dispatcher`, the kernel, form and workflow event aliases, and the traceable dispatcher in debug mode.
- [DependencyInjection](../packages/dependency-injection.md): The `ServicesBundle` of DependencyInjection defines the `event_dispatcher` service and autoconfigures listeners and subscribers, also in a console application without FrameworkBundle.
- [Console](../packages/console.md): The console `Application` dispatches `console.command`, `console.error`, `console.terminate` and `console.signal`, and ConsoleBundle maps their event classes to these names.
- [Security](../packages/security-bundle.md): Each firewall dispatches `CheckPassportEvent`, `LoginSuccessEvent`, `LogoutEvent` and other events on its own dispatcher, which also calls the global listeners of these events.
- [Form](../packages/form.md): Each form dispatches its events on its own dispatcher, so add form listeners in `buildForm()` and mark form subscriber classes with `#[Exclude]`.
- [Workflow](../packages/workflow.md): The workflow dispatches guard, transition, enter and other events, and `#[AsGuardListener]`, `#[AsTransitionListener]` and the other workflow attributes extend `#[AsEventListener]`.
- [Mailer](../packages/mailer.md): A `MessageEvent` listener can change an email before Mailer sends it, and `MessageEvent::reject()` cancels the email and stops propagation.
- [Scheduler](../packages/scheduler.md): Scheduler dispatches `PreRunEvent`, `PostRunEvent` and `FailureEvent`, and `Schedule::before()`, `after()` and `onFailure()` add listeners for them.
- [Doctrine Bridge](../packages/doctrine-bridge.md): Doctrine has its own event system for entity changes, with `#[AsDoctrineListener]` and `#[AsEntityListener]` from DoctrineBundle; for domain logic, the docs advise Symfony events.
- [Stopwatch](../packages/stopwatch.md): `TraceableEventDispatcher` measures each listener with a `Stopwatch`, and FrameworkBundle enables it only in debug mode when Stopwatch is installed.
- [WebProfilerBundle](../packages/web-profiler-bundle.md): The events panel of the profiler shows the called listeners, the not called listeners and the orphaned events of each request.
- [Symfony Contracts](../packages/contracts.md): `symfony/event-dispatcher-contracts` holds the base `Event` class and the dispatch-only `EventDispatcherInterface`; type-hint them to depend on an abstraction, not on the component.
- [Tui](../packages/tui.md): The experimental Tui component sends all widget events through one EventDispatcher; register listeners with widget methods such as `onSubmit()` or with `$tui->addListener()`.
- [RemoteEvent](../packages/remote-event.md): RemoteEvent handles events that an external service sends to a webhook, with an `#[AsRemoteEventConsumer]` consumer; for events inside your own code, use the EventDispatcher.
- [Webhook](../packages/webhook.md): Webhook receives and sends HTTP webhook calls between systems; use the EventDispatcher for events inside one application.
- [MakerBundle](../packages/maker-bundle.md): `make:listener` generates an `#[AsEventListener]` listener or an `EventSubscriberInterface` subscriber.

## Changed in 8.0/8.1

- 8.1 deprecates `RegisterListenersPass::setHotPathEvents()` and `setNoPreloadEvents()`. Old: `(new RegisterListenersPass())->setHotPathEvents(['app.event'])`. New: `new AddEventAliasesPass([], ['app.event'])`; the third argument takes the no-preload events.
- 8.1 adds controller attribute events. Old: a `kernel.controller_arguments` listener that looks for an attribute on each controller. New: `#[AsEventListener(event: KernelEvents::CONTROLLER_ARGUMENTS.'.'.MyAttribute::class)]`. The listener gets a `ControllerAttributeEvent` with `$event->attribute` and `$event->kernelEvent`. All kernel events except `kernel.request` and `kernel.terminate` support this.
- 8.1 defines the `event_dispatcher` service and the autoconfiguration of `#[AsEventListener]` and `EventSubscriberInterface` in the new `Symfony\Component\DependencyInjection\Kernel\ServicesBundle`. If a test calls `FrameworkExtension::load()` on a hand-made `ContainerBuilder`, first call `new ServicesBundle()->getContainerExtension()->load([], $container)`.
- 8.0 removes the XML configuration format, so `<tag name="kernel.event_listener" .../>` in a `services.xml` file no longer works. Use `#[AsEventListener]`, or the tag in YAML or PHP configuration.
