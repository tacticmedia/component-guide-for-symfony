# BrowserKit (`symfony/browser-kit`): details

**Applies to:** Symfony 8.1

## Key features and concepts

- **Browser base class**: `AbstractBrowser` keeps the server parameters, the `History` and the `CookieJar`, and it handles redirects. A subclass implements `doRequest()`, which sends a request and returns a response. To use other request and response objects, override `filterRequest()` and `filterResponse()`. The `Client` class does not exist. Use `AbstractBrowser`. Entry point: `Symfony\Component\BrowserKit\AbstractBrowser`.
- **HTTP browser**: `HttpBrowser` sends real HTTP requests with an `HttpClientInterface` (`HttpClient::create()` by default). For 4xx and 5xx responses, it does not throw an exception. Check the status code of each response. To set HttpClient options such as `auth_basic` or `ciphers`, give them to `HttpClient::create()`. The `base_uri` and `query` options have no effect, because the browser sends each request to an absolute URI. For a GET request, `HttpBrowser` does not add `$parameters` to the URI. Put the query string in the URI. Without `symfony/mime`, `HttpBrowser` throws a `LogicException` for each request except a GET or HEAD request without a `Content-Type`. Entry point: `new HttpBrowser(HttpClient::create($defaultOptions))`.
- **Requests**: `request($method, $uri, $parameters, $files, $server, $content)` sends a request and returns a DomCrawler `Crawler` for the response. For a relative URI, the browser uses the current page as the base. Without history, the base is `http://localhost/`. If you set the `HTTP_HOST` and `HTTPS` server parameters, they replace the host and the scheme of a relative URI. The browser adds a `Referer` header from the history and the `User-Agent` value `Symfony BrowserKit`. Entry point: `AbstractBrowser::request()`.
- **JSON and AJAX requests**: `jsonRequest($method, $uri, $parameters, $server)` sends the parameters as a JSON body, with `Content-Type` and `Accept` set to `application/json`. Its fourth argument is `$server`, not `$files` as in `request()`. `xmlHttpRequest()` takes the arguments of `request()` and adds the header `X-Requested-With: XMLHttpRequest`. Entry points: `AbstractBrowser::jsonRequest()`, `AbstractBrowser::xmlHttpRequest()`.
- **Server parameters and headers**: The browser takes HTTP headers as `$_SERVER` keys: uppercase, `_` instead of `-`, and the `HTTP_` prefix (for example `HTTP_X_API_KEY`). `CONTENT_TYPE` and `CONTENT_LENGTH` have no prefix. A key without the `HTTP_` prefix, such as `X-Api-Key`, does not become a header. Set a default value with `setServerParameter()`, or give the `$server` array to one request. The constructor of `HttpBrowser` has no `$server` argument. To send a header name with an underscore, override `HttpBrowser::getHeaders()` in a subclass. Entry point: `AbstractBrowser::setServerParameter()`.
- **Links**: `clickLink($text)` clicks the first link whose text contains `$text` as whole words, or the first link with an image whose `alt` text contains it. `click($link)` clicks a DomCrawler `Link`, for example `$crawler->selectLink('Next')->link()`. If no link matches, DomCrawler throws the PHP `\InvalidArgumentException`. Entry points: `AbstractBrowser::clickLink()`, `AbstractBrowser::click()`.
- **Forms**: `submitForm($button, $fieldValues)` finds the form of a button by its text, `id`, `value` or `name`. It keeps the default and hidden values of the form and replaces only the given fields. The third argument is the HTTP method, and its default is `POST`, also for a form with `method="get"`. To keep the method of the form, call `submit($crawler->selectButton('Search')->form(), $values)`. For a file field, give the absolute path of the file. `HttpBrowser` then sends a `multipart/form-data` body. Entry points: `AbstractBrowser::submitForm()`, `AbstractBrowser::submit()`.
- **Redirects**: `AbstractBrowser` and `HttpBrowser` follow a 3xx response with a `Location` header automatically, with no limit. The Symfony test client does not follow redirects by default. Call `followRedirects(false)` to stop, then `followRedirect()` to follow one redirect. After a 301, 302 or 303 response, the next request uses `GET` without a body. A 307 or 308 response keeps the method and the body. After `setMaxRedirects($max)`, the browser follows a maximum of `$max + 1` redirects in a chain, and it throws a `LogicException` at the next redirect. `setMaxRedirects()` with a negative value stops automatic redirects. A value of 0 or more starts automatic redirects, also after `followRedirects(false)`. `followMetaRefresh()` also follows a `<meta http-equiv="refresh" content="0; url=...">` tag in `<head>`. Entry point: `AbstractBrowser::followRedirects()`.
- **Cookies**: The `CookieJar` stores the `Set-Cookie` values of each response, also of each redirect. It sends the cookies that match the domain, the path and the scheme of a request, and it removes expired cookies. To add a cookie before a request, call `getCookieJar()->set(new Cookie('name', 'value'))`. Do not send cookies in the `HTTP_COOKIE` server parameter. The test client does not put that value into `$request->cookies`. If the jar has a cookie for the URI, `HttpBrowser` replaces that header. `get($name, $path, $domain)` returns the most specific matching cookie. Entry points: `AbstractBrowser::getCookieJar()`, `Cookie`, `CookieJar`.
- **History**: Each request goes into the `History`. `back()`, `forward()` and `reload()` send a stored request again, with its method, parameters, files and content. `back()` and `forward()` skip each request whose redirect the browser followed automatically. They do not skip a request whose redirect you followed with `followRedirect()`. On the first page, `back()` throws a `LogicException`. Before you call `back()`, check `getHistory()->isFirstPage()`. After an automatic redirect of the first request, `isFirstPage()` returns false, but `back()` throws. `restart()` clears the history and the cookies. Entry points: `AbstractBrowser::back()`, `AbstractBrowser::getHistory()`.
- **Responses**: `getResponse()` returns the response object of the transport: a BrowserKit `Response` for `HttpBrowser`, and an HttpFoundation `Response` for the test client. `getInternalResponse()` always returns a BrowserKit `Response` with `getStatusCode()`, `getHeader()`, `getContent()` and `toArray()`. `toArray()` decodes a JSON body. If the body is not a JSON object or array, it throws a `JsonException`. Entry point: `AbstractBrowser::getInternalResponse()`.
- **HTML fragments**: The HTML5 parser can drop elements of a fragment such as `<tr><td>...</td></tr>`. `wrapContent('<table>%s</table>')` wraps each response body before the browser parses it. The response itself does not change. `wrapContent(false)` removes the pattern. Entry point: `AbstractBrowser::wrapContent()`.
- **Insulation**: `insulate()` runs each request in a new PHP process, so global state of one client cannot affect another client. It needs `symfony/process` and an implementation of `getScript()`. `HttpKernelBrowser` and the test client implement it; `HttpBrowser` does not. Entry point: `AbstractBrowser::insulate()`.
- **PHPUnit constraints**: `BrowserHasCookie`, `BrowserCookieValueSame`, `BrowserHistoryIsOnFirstPage` and `BrowserHistoryIsOnLastPage` check a browser object. Use them in any PHPUnit test, for example `self::assertThat($browser, new BrowserHasCookie('session_id'))`. `WebTestCase` wraps them as `assertBrowserHasCookie()` and the other browser assertions. Entry point: `Symfony\Component\BrowserKit\Test\Constraint`.
- **Symfony test client**: `HttpKernelBrowser` extends `AbstractBrowser` and sends each request to an `HttpKernelInterface` in the same PHP process. `KernelBrowser` (service `test.client`, from `WebTestCase::createClient()`) extends it, so the features of `AbstractBrowser` work in functional tests. `catchExceptions(false)` lets a kernel exception reach the test. If `framework.test` is true and you install `symfony/browser-kit`, the container has the `test.client` service. Entry point: `Symfony\Component\HttpKernel\HttpKernelBrowser`.

## Entry points

- `Symfony\Component\BrowserKit\HttpBrowser`: `new HttpBrowser(?HttpClientInterface $client = null, ?History $history = null, ?CookieJar $cookieJar = null)` for real HTTP requests.
- Without FrameworkBundle: `new HttpBrowser(HttpClient::create())` sends real HTTP requests, for example in a scraper. It needs `symfony/http-client` and `symfony/mime`. `HttpKernelBrowser` sends requests to any `HttpKernelInterface`, and the PHPUnit constraints work in any PHPUnit test.
- `Symfony\Component\BrowserKit\AbstractBrowser`: extend it and implement `doRequest(object $request): object`. If necessary, override `filterRequest()`, `filterResponse()` and `getScript()`.
- Browser methods for requests and navigation: `request()`, `jsonRequest()`, `xmlHttpRequest()`, `clickLink()`, `click()`, `submitForm()`, `submit()`, `followRedirect()`, `back()`, `forward()`, `reload()`, `restart()`.
- Browser methods for settings and state: `followRedirects()`, `setMaxRedirects()`, `followMetaRefresh()`, `insulate()`, `wrapContent()`, `setServerParameter()`, `setServerParameters()`, `getServerParameter()`, `getCookieJar()`, `getHistory()`, `getCrawler()`, `getResponse()`, `getInternalResponse()`, `getRequest()`, `getInternalRequest()`.
- `Symfony\Component\BrowserKit\CookieJar` (`set()`, `get()`, `all()`, `allValues()`, `allRawValues()`, `expire()`, `clear()`, `updateFromSetCookie()`) and `Symfony\Component\BrowserKit\Cookie` (`new Cookie($name, $value, $expires, $path, $domain, $secure, $httponly)`, `Cookie::fromString()`).
- `Symfony\Component\BrowserKit\History`: `isFirstPage()`, `isLastPage()`, `current()`, `isEmpty()`, `clear()`.
- `Symfony\Component\BrowserKit\Request` and `Symfony\Component\BrowserKit\Response` (`getStatusCode()`, `getHeader()`, `getHeaders()`, `getContent()`, `toArray()`).
- PHPUnit constraints: `Symfony\Component\BrowserKit\Test\Constraint\BrowserHasCookie`, `BrowserCookieValueSame`, `BrowserHistoryIsOnFirstPage`, `BrowserHistoryIsOnLastPage`.
- Exceptions: each BrowserKit exception implements `Symfony\Component\BrowserKit\Exception\ExceptionInterface`. Examples: `LogicException` (redirect limit, history bounds), `InvalidArgumentException` (`submitForm()` finds no button), `JsonException` (`toArray()`), `BadMethodCallException` (a call before the first request).
- In a Symfony application: `Symfony\Component\HttpKernel\HttpKernelBrowser` (any `HttpKernelInterface`, `catchExceptions()`), `Symfony\Bundle\FrameworkBundle\KernelBrowser` (service `test.client`, from `WebTestCase::createClient()`), config key `framework.test`.
- Installation: `composer require symfony/browser-kit` (it installs `symfony/dom-crawler`). For `HttpBrowser`, also install `symfony/http-client` and `symfony/mime`. For `Crawler::filter()`, also install `symfony/css-selector`.

## Symbiotic packages

- [DomCrawler](../packages/dom-crawler.md): BrowserKit requires DomCrawler, each request returns a `Crawler`, and `click()` and `submit()` take its `Link` and `Form` objects.
- [CssSelector](../packages/css-selector.md): `Crawler::filter()` on the returned crawler and `followMetaRefresh()` need it, but `clickLink()` and `submitForm()` work without it.
- [HttpClient](../packages/http-client.md): `HttpBrowser` sends its requests through an `HttpClientInterface`; HttpClient alone is for stateless API calls, and `HttpBrowser` adds cookies, links and forms.
- [Mime](../packages/mime.md): `HttpBrowser` needs Mime for all requests except GET and HEAD requests without a `Content-Type`, and it sends a form with files as a `FormDataPart`.
- [HttpKernel](../packages/http-kernel.md): `HttpKernelBrowser` is the BrowserKit browser for an `HttpKernelInterface` and handles each request in the same PHP process, without a web server.
- [HttpFoundation](../packages/http-foundation.md): `HttpKernelBrowser` converts each BrowserKit `Request` to an HttpFoundation `Request`, and it converts the HttpFoundation `Response` back to a BrowserKit `Response`.
- [FrameworkBundle test tools](../packages/framework-bundle-testing.md): `WebTestCase::createClient()` returns `KernelBrowser`, a BrowserKit browser with `loginUser()` and `getSession()`, and `BrowserKitAssertionsTrait` wraps the BrowserKit constraints.
- [Panther](../packages/panther.md): Panther is for pages that need JavaScript: its `Client` extends `AbstractBrowser` but controls a real browser, and its `request()` accepts only GET.
- [Process](../packages/process.md): `insulate()` runs each request in a new PHP process with `PhpProcess`, so it needs `symfony/process`.

## Changed in 8.0/8.1

- Removed in 8.0: `AbstractBrowser::useHtml5Parser()`. BrowserKit always uses the native HTML5 parser. Old: `$browser->useHtml5Parser(false)`. New: remove the call. If an HTML fragment loses elements, call `$browser->wrapContent('<table>%s</table>')`.
- New in 7.4/8.0: `$browser->getHistory()->isFirstPage()` and `isLastPage()`. Old: `try { $browser->back(); } catch (LogicException $e) { ... }`. New: `if (!$browser->getHistory()->isFirstPage()) { $browser->back(); }`. If the browser followed a redirect of the first request automatically, keep the `catch`.
- New in 7.4/8.0: the PHPUnit constraints `BrowserHistoryIsOnFirstPage` and `BrowserHistoryIsOnLastPage`.
- New in 7.4 and in 8.0.4: `AbstractBrowser::wrapContent()` for HTML fragments.
