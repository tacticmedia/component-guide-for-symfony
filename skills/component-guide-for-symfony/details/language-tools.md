# Symfony Language Tools (`symfony/lsp`): details

**Applies to:** symfony/lsp 0.23, Symfony CLI 5.22

## Key features and concepts

- **One executable, two modes.** Without arguments, `symfony-lsp` is a language server on standard input and output. `symfony-lsp check` runs the same analysis on the saved files and writes a report. On Windows, start the server with `--socket=<port>`, so that it connects to the client on a local port. The server raises the PHP memory limit to 2 GB. To change it, set `SYMFONY_LSP_MEMORY_LIMIT`, for example to `4G` or `-1`. Keep a general PHP language server enabled, because this server answers Symfony questions only. Entry points: `symfony-lsp`, `symfony-lsp --socket=<port>`, `symfony-lsp check`.
- **Installation.** `symfony/lsp` is not on Packagist, so do not run `composer require`. Download an archive from GitHub Releases (`linux-x64`, `linux-arm64`, `macos-arm64` or `windows-x64`). Verify the archive against `SHA256SUMS`. The executable contains a static PHP runtime and the Tree-sitter parser, so the tool itself needs no PHP installation. The Linux executables are static, so they also run on musl systems such as Alpine. The macOS executables are not signed. To upgrade, replace the executable while the editor is stopped. On Intel macOS, build from source with PHP 8.4.1 or later, `composer install` and `composer tree-sitter:build`. Entry point: `symfony-lsp --version`.
- **Runtime analysis and trust.** The tool runs the application with `phpCommand` (default `["php"]`) in debug mode to read routes, services, templates and bundle configuration. This step executes application code. An editor runs it only after the user trusts the workspace, and `.symfony-lsp.json` never grants trust. `symfony-lsp check` does not ask and runs the application. `--source-only` and `"runtimeIndexing": false` turn off the runtime analysis, and then only the file-based features remain. For code that you do not trust, use `symfony-lsp check --source-only`, because command-line options override `.symfony-lsp.json`. If `releaseMetadata` is `true` (the default), the tool reads the maintained branches from `symfony.com/releases.json`. If it gets this list, it boots only the branches from the oldest maintained branch to the next development branch. Hovers, diagnostics, caches and logs never show parameter values, secrets or `.env` values. Entry points: `--source-only`, `runtimeIndexing`, `workspaceTrust`.
- **Integrations.** The analysis covers routes, services and parameters, translations, environment variables, bundle configuration, and Console arguments and options. It also covers Messenger, events, Security, forms, validation, serializer groups, Doctrine, assets and importmap, Stimulus and Twig components. In Twig, it also covers template names, the Twig functions and filters of the project, and PHP constants and enums. Rename works only for routes, services, parameters and translation keys. Messenger, events, Doctrine, Stimulus and Twig components also have code lenses. Entry point: the `symfony-lsp` server in an LSP client.
- **Environments and kernels.** The tool boots one environment at a time, `dev` by default, and one kernel at a time. It reports an unknown name only in the files that the selected environment loads. Configuration keys and values are the exception: the tool checks them in every `when@` block. The `kernel` setting takes a kernel class or a project-relative entry point that returns the application closure. Entry points: `environment`, `kernel`, `--environment=`, `--kernel=`, `symfony.switchEnvironment`, `symfony.switchKernel`.
- **Diagnostic codes.** Each diagnostic has a code, for example `route.not_found`, `route.missing_parameters`, `template.not_found`, `parameter.not_found`, `form.unknown_option` or `messenger.unknown_transport`. `symfony-lsp check --list-codes` lists the 31 codes. `translation.not_found` and `translation.domain_not_found` stay off until you enable `translationDiagnostics` or pass `--translation-diagnostics`. The tool never reports an unknown service ID, although `service.not_found` is in the list. Some codes work without the running application: `env.malformed_chain`, `event.invalid_listener_method`, `translation.placeholders` and `twig_callable.unknown_argument`. `config.malformed_structure` also works without it, for YAML indented with tabs and for malformed XML. Entry point: `symfony-lsp check --list-codes`.
- **Blocking rules and exit codes.** By default, each error blocks the check, and warnings do not block. With `--fail-on=code,...`, only the named codes block, at any severity. An empty `--fail-on=` reports the diagnostics but never blocks. `config.unknown_key`, `config.invalid_type`, `config.deprecated_key` and `env.incompatible_type` are always warnings. Exit code `0` means no blocking diagnostic, and `10` means blocking diagnostics. Exit code `11` means an invalid invocation, configuration, selection or baseline. Exit code `12` means an incomplete analysis, and it has priority over `10`. The run stops after 600 seconds, and each application boot stops after 300 seconds. Entry points: `--fail-on=`, `--timeout=`, `--bridge-timeout=`.
- **Report formats.** `--format=` selects one format: `human` (the default), `json`, `github`, `gitlab` or `sarif`. The report goes to standard output, and failures and `--profile` timings go to standard error. `github` writes workflow commands, so the diagnostics show as annotations on a pull request. `gitlab` writes a Code Quality report without the baseline matches. `sarif` writes SARIF 2.1.0 and keeps the baseline matches as suppressions. If the run exits with `12`, do not upload the SARIF report. Entry point: `symfony-lsp check --format=github`.
- **Baseline.** `--generate-baseline` writes the current findings to `.symfony-lsp-baseline.json` and does not overwrite an existing file. The check reads a baseline only when you pass `--baseline=PATH`. A baseline entry matches one occurrence, not a line number, so it survives moved code. Matched diagnostics stay in the report, but they do not block. `--strict-baseline` makes stale entries fail the run. `--refresh-baseline` replaces an existing baseline. Entry points: `--generate-baseline`, `--baseline=`, `--strict-baseline`, `--refresh-baseline`.
- **Suppression comments.** A `@symfony-lsp-ignore` directive in a PHP, Twig, YAML or XML comment hides one diagnostic of each named code on one line. On its own line, the directive applies to the next line. After code, it applies to the same line. An unknown code or a directive without a code gives `suppression.invalid`. The editor and the check both obey the directive. Entry point: `/* @symfony-lsp-ignore template.not_found (checked at runtime) */`.
- **Project configuration.** `.symfony-lsp.json` in the workspace root holds the settings for each editor and for the check. The file must contain `"version": 1`, and unknown keys or invalid values are errors. The keys are `projectRoots`, `phpCommand` (`["php"]`), `containerProjectRoot`, `environment` (`dev`), `kernel`, `debug` (`true`), `runtimeIndexing` (`true`), `releaseMetadata` (`true`), `bridgeTimeout` (300), `translationDiagnostics` (`false`), `excludePaths` and `projects`. Per-project entries override top-level values, editor settings override the file, and command-line options override both. A list replaces the list of a lower level, and the tool does not merge lists. The tool finds an application when its `composer.json` requires `symfony/framework-bundle`, directly or through `composer.lock`, and it has the type `project` or a `bin/console` file. For another layout, set `projectRoots`. Entry points: `.symfony-lsp.json`, `--config=PATH`.
- **Docker.** If PHP runs only in a container, set `phpCommand` to a non-interactive command that runs PHP in the container. Set `containerProjectRoot` to the project path in the container. For a Compose service `php` that mounts the project at `/app`, use `["docker", "compose", "exec", "-T", "php", "php"]` and `"/app"`. The tool translates the paths between the host and the container with this path prefix. Start the container before you open the project. Entry point: `containerProjectRoot`.
- **VS Code extension.** The `symfony.language-tools` extension bundles the server for Linux x64 and ARM64, musl Linux, macOS ARM64 and Windows x64. It needs VS Code 1.91 or later and a trusted workspace. Each setting of `.symfony-lsp.json` also exists as `symfonyLsp.<name>`, and it overrides the file only when you set it. `symfonyLsp.serverPath`, `symfonyLsp.memoryLimit` and `symfonyLsp.trace` have no key in `.symfony-lsp.json`. After you change one of them or `symfonyLsp.projectRoots`, run `Developer: Reload Window`. The extension gives no Twig syntax highlighting. Entry point: `code --install-extension symfony.language-tools`.
- **Neovim, Zed and OpenCode.** In Neovim, install the server with `:MasonInstall symfony-lsp` or from a release. Then call `vim.lsp.enable('symfony_lsp')`, which needs nvim-lspconfig. The `symfony_lsp` config of nvim-lspconfig sends values for `phpCommand`, `containerProjectRoot`, `environment`, `debug`, `runtimeIndexing` and `translationDiagnostics`. These editor values override `.symfony-lsp.json`. If the file sets one of these keys, set the same value under `settings.symfonyLsp` in `vim.lsp.config('symfony_lsp', {...})`. In Zed, install `editor/zed/` of the repository as a dev extension. It finds `symfony-lsp` on `PATH` or downloads the latest stable release. In OpenCode, declare `symfony-lsp` as a custom server under `lsp.symfony` in `opencode.json`. OpenCode shows no trust prompt, so set `"workspaceTrust": true` only for a project that you trust. Entry points: `vim.lsp.enable('symfony_lsp')`, `lsp.symfony-language-tools` (Zed), `lsp.symfony` (OpenCode).
- **Symfony CLI.** `symfony lsp:check` downloads the latest stable release, verifies it against `SHA256SUMS` and runs `symfony-lsp check` with your arguments. It looks for a new release at most once in 24 hours and needs version 0.17.0 or later. It loads the `.env` variables of the project and makes `symfony php` the default `phpCommand`. Thus the application runs with the PHP version of the project. Entry points: `symfony lsp:check`, `symfony lsp:cache-dir`.

## Entry points

- Executable: `symfony-lsp` (language server on standard input and output), `symfony-lsp --socket=<port>`, `symfony-lsp --version` (`-V`), `symfony-lsp --help` (`-h`).
- Check: `symfony-lsp check [options] [files, directories or patterns]`. Report options: `--format=human|json|github|gitlab|sarif`, `--fail-on=CODE,...`, `--list-codes`, `--baseline=PATH`, `--generate-baseline`, `--refresh-baseline`, `--strict-baseline`, `--translation-diagnostics`, `--no-translation-diagnostics`.
- Check options for the analysis: `--source-only`, `--environment=NAME`, `--kernel=CLASS|PATH`, `--project-root=PATH` (repeatable), `--workspace=PATH`, `--config=PATH`, `--php-command=JSON`, `--container-project-root=PATH`, `--no-container-project-root`, `--debug`, `--no-debug`, `--runtime-indexing`, `--no-runtime-indexing`, `--timeout=SECONDS`, `--bridge-timeout=SECONDS`, `--verbose` (`-v`, `-vv`, `-vvv`), `--profile`, `--help` (`-h`). An option takes its value only with `=`, so `--environment prod` does not work.
- Symfony CLI: `symfony lsp:check [options]`, `symfony lsp:cache-dir`.
- Files: `.symfony-lsp.json` (project configuration), `.symfony-lsp-baseline.json` (the default baseline path), `var/symfony-lsp/` (the cache in each application). In CI, cache `var/symfony-lsp/` by revision, platform and tool version. Do not publish it as a build artifact.
- Comment directive: `@symfony-lsp-ignore code[,code] (reason)`.
- Environment variable: `SYMFONY_LSP_MEMORY_LIMIT`.
- LSP commands: `symfony.refreshIndex`, `symfony.indexStatus`, `symfony.switchEnvironment`, `symfony.switchKernel`. Initialization options: `workspaceTrust`, `projectRoots`, `trace`, and the analysis settings of `.symfony-lsp.json`, such as `environment`. Settings section: `symfonyLsp`.
- VS Code: the extension `symfony.language-tools`, the settings `symfonyLsp.*`, and the palette commands `Symfony Language Tools: Refresh Index`, `Show Index Status`, `Switch Environment` and `Switch Kernel`.
- Neovim: `:MasonInstall symfony-lsp`, `vim.lsp.enable('symfony_lsp')`, `vim.lsp.config('symfony_lsp', {...})`.
- Zed: the dev extension in `editor/zed/` of the repository, with the settings `lsp.symfony-language-tools` (`initialization_options`, `settings`, `binary.path`, `binary.env`).
- OpenCode: `lsp.symfony` in `opencode.json` (`command`, `extensions`, `initialization`, `env`).
- The tool adds no bundle, PHP class, attribute, service, Twig function or `framework.*` configuration key to the application. Do not add it to `composer.json`.

## Symbiotic packages

- [FrameworkBundle](../packages/framework-bundle.md): The tool finds an application through `symfony/framework-bundle` and reads its metadata with the `debug:router`, `debug:container`, `debug:config` and `debug:form` commands of FrameworkBundle.
- [Runtime](../packages/runtime.md): The tool gets the kernel from a Runtime front controller, such as `bin/console`, if it finds no kernel class or if `kernel` names that file.
- [Routing](../packages/routing.md): The tool checks route names and required parameters in `path()`, `url()`, `generateUrl()`, `redirectToRoute()` and `UrlGeneratorInterface::generate()` against the routes of the selected environment.
- [DependencyInjection](../packages/dependency-injection.md): The tool completes service IDs and `%parameter%` names in YAML and in `#[Autowire]`, and it reports `parameter.not_found`, but never an unknown service ID.
- [Config](../packages/config.md): The tool reads the configuration tree of each registered bundle extension to complete and check the keys and values in `config/` files.
- [Translation](../packages/translation.md): The tool compares the parameters of `trans()`, `TranslatableMessage`, `t()` and the Twig `trans` filter with the message placeholders; with `--translation-diagnostics`, it also reports unknown keys and domains; `lint:translations` checks the catalog syntax instead.
- [Dotenv](../packages/dotenv.md): The tool reads only the variable names from `.env` files, for completion and navigation in `%env()%` expressions, and never shows the values.
- [Console](../packages/console.md): The tool checks the names in `$input->getArgument()` and `$input->getOption()` against the `addArgument()`, `addOption()`, `#[Argument]` and `#[Option]` declarations of the command.
- [Messenger](../packages/messenger.md): The tool checks the bus and transport names in `#[AsMessageHandler]`, `BusNameStamp` and `framework.messenger`, checks handler signatures, and links messages to handlers.
- [EventDispatcher](../packages/event-dispatcher.md): The tool reports an `#[AsEventListener]` method that does not exist, and it links event classes to their listeners with hover and code lenses.
- [Security](../packages/security-bundle.md): The tool checks firewall and user provider names, and it completes roles in `#[IsGranted]`, `is_granted()` and `security.yaml`.
- [Form](../packages/form.md): The tool reports `form.unknown_option` for an option in `createForm()` or `$builder->add()` that the form type and its parent types do not accept.
- [Validator](../packages/validator.md): The tool reports `validation.unknown_constraint_option` for a named argument that a Symfony constraint attribute, such as `#[Assert\Length]`, does not accept.
- [Serializer](../packages/serializer.md): The tool finds the references of serializer group names in `#[Groups]`, `#[Context]` and YAML mapping, but it reports no diagnostics for them.
- [Doctrine Bridge](../packages/doctrine-bridge.md): The tool completes entity fields in the `choice_label`, `choice_value` and `group_by` options of an `EntityType` field.
- [AssetMapper](../packages/asset-mapper.md): The tool completes logical asset paths in `asset()` and reports `importmap.unknown_entrypoint` for an `importmap()` entrypoint that `importmap.php` does not declare.
- [Asset](../packages/asset.md): Without AssetMapper, the tool completes `asset()` paths from the files in `public/`, and it never reports an unknown asset path.
- [StimulusBundle](../packages/stimulus-bundle.md): The tool completes controller names in `data-controller` and `stimulus_controller()`, and `stimulus.unknown_controller` needs StimulusBundle and the running application.
- [TwigBundle](../packages/twig-bundle.md): The tool reads the Twig loader paths with the `debug:twig` command that TwigBundle registers, and it reports `template.not_found`; for Twig syntax errors, use `lint:twig`.
- [Twig Bridge](../packages/twig-bridge.md): The tool reads the arguments of the Twig Bridge functions `path()`, `url()`, `asset()`, `importmap()`, `is_granted()`, `logout_path()` and `t()`, and of the `trans` filter.
- [UX Twig Component](../packages/ux-twig-component.md): The tool completes component names and properties in `<twig:Name>` tags and reports `twig_component.not_found` when this package is installed.
- [UX Live Component](../packages/ux-live-component.md): The tool completes Live Component event names in `emit()` and makes live actions navigable from templates.
- [Yaml](../packages/yaml.md): `lint:yaml` checks YAML syntax, and Symfony Language Tools checks the keys and values in `config/` against the bundle schemas.

## Changed in 0.8 to 0.23

- 0.23.0: The tool no longer reads a Twig `trans()` function call, because Symfony defines only the `trans` filter. In Twig, use the `|trans` filter or the `t()` function.
- 0.23.0: An application root outside the workspace is an error, also when an editor sends it in the initialization options.
- 0.22.0: The tool checks YAML configuration keys and values in every `when@` block. The new docs pages are `docs/check.rst` and `docs/configuration.rst`. Version 0.23.0 removed the old pages `docs/features/headless-diagnostics.rst` and `docs/project-configuration.rst`.
- 0.20.2: The `kernel` setting, the `--kernel=` option and the `symfony.switchKernel` command select one kernel in an application with several kernels.
- 0.20.0: Releases have no Intel macOS build. On Intel macOS, build from source.
- 0.17.0 and 0.18.0: Version 0.17.0 added `symfony-lsp check` with CI reports, baselines, SARIF output and `excludePaths`. Version 0.18.0 added `--format=gitlab`, `@symfony-lsp-ignore` comments and `releaseMetadata`.
- 0.13.0: The `consolePath` setting is gone. `.symfony-lsp.json` rejects it as an unknown key, and editor settings ignore it.
- 0.8.0 to 0.8.6: The name changed from Symfony LSP to Symfony Language Tools. The executable stays `symfony-lsp`, the settings section stays `symfonyLsp`, and the VS Code extension ID is `symfony.language-tools`.

## Status

- 0.x and experimental. The announcement of 2026-08-17 says: "A word of caution: this is a beta, and an experimental one." The post of 2026-08-23 says: "Version 0.16 is a large step, but Symfony Language Tools is still a beta." Settings, options and docs paths changed between 0.x versions.
- Not a Composer dependency. `symfony/lsp` is not on Packagist, and its `composer.json` has the type `project`.
- The application must use a maintained Symfony version and must have its Composer dependencies installed. The PHP command must be compatible with the application, and it can run in a container.
- No Intel macOS build exists since 0.20.0, and the macOS executables are not signed. Zed and OpenCode work only on Linux and Apple Silicon macOS. The Zed extension is not in the Zed registry yet.
- Third-party copies lag behind. On 2026-10-09, the Mason package pins v0.19.0. Symfony CLI expects a `macos-x64` archive, so `symfony lsp:check` cannot install current releases on Intel macOS. The Symfony CLI README links to the removed page `docs/features/headless-diagnostics.rst`.
- The repository accepts issues, not external pull requests. CONTRIBUTING.md calls this "an experiment in issue-first open source development".
