# UX Map (`symfony/ux-map`): details

**Applies to:** Symfony UX 3.5

## Key features and concepts

- Map and coordinates: a `Map` holds the center, the zoom, the optional `minZoom()` and `maxZoom()`, the options and the elements. The setters and the `add*()` and `remove*()` methods return the map, so you can chain the calls. A `Point` takes a latitude from -90 to 90 and a longitude from -180 to 180. Other values throw an `InvalidArgumentException`. If you do not call `fitBoundsToMarkers()`, set `center()` and `zoom()`. Without them, the renderer throws an `InvalidArgumentException`. A zoom value below 0, a `minZoom` above `maxZoom`, or a zoom outside the `minZoom` to `maxZoom` range throws an `InvalidArgumentException`. The constructor and the `zoom()`, `minZoom()` and `maxZoom()` methods throw it when you call them. `Symfony\UX\Map\Map`, `Symfony\UX\Map\Point`
- Markers and info windows: a `Marker` takes a `position`, and optionally a `title`, an `infoWindow`, an `icon`, `extra` data and an `id`. An `InfoWindow` takes `headerContent`, `content`, `opened` (default `false`) and `autoClose` (default `true`). With `autoClose`, other info windows close when this one opens. The first positional argument of `InfoWindow` is `headerContent`, not `content`. The content is HTML, and the bridges do not escape it. If the content holds user input, escape it first. The JavaScript controllers ignore the `position` argument of `InfoWindow`. `Symfony\UX\Map\Marker`, `Symfony\UX\Map\InfoWindow`
- Marker icons: `Icon::url()`, `Icon::svg()` and `Icon::ux()` create the value for the `icon` argument of `Marker`. The default width and height are 24. Change them with `width()` and `height()`. On an SVG icon, these two methods throw a `\LogicException`, so set the size in the SVG markup. `Icon::ux('fa:map-marker')` needs `symfony/ux-icons`. Without it, the renderer throws a `\LogicException`. `Symfony\UX\Map\Icon\Icon`
- Shapes: a `Polygon` draws an area from a list of `Point` objects. A list of point lists draws a polygon with holes, and the first list is the outer boundary. A `Polyline` draws a path. A `Circle` draws a `radius` in meters around a `center`. A radius of 0 or less throws an `InvalidArgumentException`. A `Rectangle` takes a `southWest` corner and a `northEast` corner. Each shape also takes an `infoWindow`, `extra` data and an `id`. `Symfony\UX\Map\Polygon`, `Polyline`, `Circle`, `Rectangle`
- Element removal: `removeMarker()`, `removePolygon()`, `removePolyline()`, `removeCircle()` and `removeRectangle()` take the element object or its `id` string. `removeAllMarkers()` and the other `removeAll*()` methods remove all elements of one type. Use these methods in Live Component actions to change the map. `Map::removeMarker(Marker|string $markerOrId)`
- Twig function: `ux_map(map, attributes)` renders a `<div>` with the Stimulus controller of the configured bridge. To make the map visible, give it a height, for example `{style: 'height: 300px'}`. Without a `Map` object, use the named arguments `center`, `zoom`, `minZoom`, `maxZoom`, `fitBoundsToMarkers`, `markers`, `polygons`, `polylines`, `circles`, `rectangles` and `attributes`. These arguments cannot set the map options, the map `extra` data or a renderer. In inline polygons, write each point as `{lat: …, lng: …}`. If you pass a `Map` and other map arguments together, the function throws an `\InvalidArgumentException`. `ux_map()`
- Twig component: `<twig:ux:map>` takes the same props as the named arguments of `ux_map()`, or a `Map` object as `:map="map"`. The other attributes go to the `<div>`. The component needs `symfony/ux-twig-component` 2.21 or later. `<twig:ux:map />`
- HTML attributes: since 3.5, the attribute values follow the `html_attr()` rules of `twig/html-extra`. A `null` value omits the attribute. A `true` value renders `name=""`, a `data-*` attribute renders `"true"`, and an `aria-*` attribute renders `"true"` or `"false"`. If you add a `data-controller` attribute, the renderer puts your controller before the map controller. `ux_map(map, {'data-controller': 'mymap'})`
- Renderer configuration: a bridge package, `symfony/ux-leaflet-map` or `symfony/ux-google-map`, supplies the renderer. The `ux_map.renderer` option takes its DSN, and the Flex recipe sets the option to `%env(resolve:default::UX_MAP_DSN)%`. If you configure no renderer, the bundle uses `null://null`, and `ux_map()` throws a `LogicException` that names the bridge packages. If the bridge for the DSN scheme is missing, an `UnsupportedSchemeException` gives the `composer require` command. Set the bridge options with `Map::options()`. If the options class does not match the renderer, the renderer uses its default options and gives no error. `ux_map.renderer`
- Google Maps bridge: the DSN needs the API key as the user part, for example `google://%env(GOOGLE_MAPS_API_KEY)%@default`. The query options are `v` (default `weekly`), `language`, `region`, `libraries[]`, `authReferrerPolicy`, `mapIds[]`, `channel` and `solutionChannel`. The `maps` and `marker` libraries always load. `GoogleOptions` sets the map ID, the gesture handling, the background color and the double-click zoom. It also shows, hides or moves the zoom, map type, Street View and fullscreen controls. The `ux_map.google_maps.default_map_id` option sets the map ID of each map that has no map ID. The page HTML contains the API key in the `provider-options` value. `Symfony\UX\Map\Bridge\Google\GoogleOptions`
- Leaflet bridge: the DSN is `leaflet://default`, and the bridge needs no API key. By default, the map shows OpenStreetMap tiles with an attribution. `LeafletOptions` sets the tile layer (a `TileLayer` with a URL, an attribution and options), the attribution control and the zoom control. If your tile engine does not work with `L.tileLayer()`, set `tileLayer: false`. If Webpack Encore cannot find `leaflet/dist/leaflet.min.css`, add the alias `'leaflet/dist/leaflet.min.css': 'leaflet/dist/leaflet.css'` with `Encore.addAliases()`. `Symfony\UX\Map\Bridge\Leaflet\LeafletOptions`
- JavaScript events: the map controller dispatches events with the `ux:map:` prefix. Listen to them on the map element, in your own Stimulus controller. `ux:map:pre-connect` occurs before the map exists, and you can change `event.detail.center`, `zoom` and `options` there. `ux:map:connect` gives `map`, `markers`, `polygons`, `polylines`, `circles`, `rectangles`, `infoWindows` and `extra`. Each element type (`marker`, `polygon`, `polyline`, `circle`, `rectangle`, `info-window`) has a `:before-create` event (`event.detail.definition`) and an `:after-create` event (the new object and `definition`). The `info-window` events also give the `element` that owns the info window. Each event detail also holds the library object: `L` (Leaflet) or `google`. The `extra` data is in `event.detail.extra` (map events) or `event.detail.definition.extra` (element events). `ux:map:connect`
- Low-level options: in a `:before-create` listener, set `event.detail.definition.bridgeOptions`. The bridge gives these options to the library constructor, for example `{gmpDraggable: true}` for a Google marker or `{color: 'red'}` for a Leaflet polygon. In `ux:map:pre-connect`, set `event.detail.bridgeOptions` for the map constructor. Google markers are `google.maps.marker.AdvancedMarkerElement` objects. If a marker has an `Icon`, the bridge ignores `bridgeOptions.content` (Google) or `bridgeOptions.icon` (Leaflet) and logs a warning. `bridgeOptions`
- Live Component: in a `#[AsLiveComponent]` class, use `DefaultActionTrait` and `ComponentWithMapTrait`. Implement the `instantiateMap(): Map` method. Put `{{ ux_map(map, {style: 'height: 300px'}) }}` in the component template. In a `#[LiveAction]` method, change the map through `$this->getMap()`. The trait keeps the map in the `map` LiveProp, which is not writable. To start from a prepared `Map`, pass it as the `map` prop when you render the component. After a re-render, the controller adds and removes only the changed elements, because it compares a hash of each element. If `fitBoundsToMarkers` is on, the map fits the markers again after each marker change. `Symfony\UX\Map\Live\ComponentWithMapTrait`
- Geo helpers: `GridClusteringAlgorithm` and `MortonClusteringAlgorithm` group `Point` objects into `Cluster` objects for one zoom level. Each cluster gives `getCenter()`, `getPoints()` and `count()`, and you add one marker for each cluster. `DistanceCalculator` returns the distance between two points, by default with the Vincenty formula, in meters. To change the formula or the unit, pass a `HaversineDistanceCalculator` or a `SphericalCosineDistanceCalculator`, and a `DistanceUnit`. The result is in the unit of the `DistanceUnit`, for example in kilometers with `DistanceUnit::Kilometer`. `CoordinateUtils::decimalToDMS()` and `CoordinateUtils::DMSToDecimal()` convert coordinates. The docs page describes only the clusters. `Symfony\UX\Map\Cluster\GridClusteringAlgorithm`, `Symfony\UX\Map\Distance\DistanceCalculator`, `Symfony\UX\Map\Utils\CoordinateUtils`

## Entry points

- Installation: `composer require symfony/ux-map`, then `composer require symfony/ux-leaflet-map` or `composer require symfony/ux-google-map`. With Webpack Encore, also run `npm install --force` and `npm run watch`.
- Map classes: `Symfony\UX\Map\Map`, `Symfony\UX\Map\Point`, `Symfony\UX\Map\Marker`, `Symfony\UX\Map\InfoWindow`, `Symfony\UX\Map\Polygon`, `Symfony\UX\Map\Polyline`, `Symfony\UX\Map\Circle`, `Symfony\UX\Map\Rectangle`, `Symfony\UX\Map\Icon\Icon`.
- Leaflet options: `Symfony\UX\Map\Bridge\Leaflet\LeafletOptions`, with `Option\TileLayer`, `Option\AttributionControlOptions`, `Option\ZoomControlOptions` and `Option\ControlPosition` in the same namespace.
- Google Maps options: `Symfony\UX\Map\Bridge\Google\GoogleOptions`, with `Option\ControlPosition`, `Option\GestureHandling`, `Option\ZoomControlOptions`, `Option\MapTypeControlOptions`, `Option\MapTypeControlStyle`, `Option\StreetViewControlOptions` and `Option\FullscreenControlOptions` in the same namespace.
- Live Component trait: `Symfony\UX\Map\Live\ComponentWithMapTrait`, with the abstract method `instantiateMap(): Map` and the method `getMap(): Map`.
- Twig function `ux_map(map, attributes = {})`, or `ux_map(center: …, zoom: …, markers: […], attributes: {…})`. Twig component `<twig:ux:map />`.
- Configuration keys: `ux_map.renderer` (default `null`, which means `null://null`) and `ux_map.google_maps.default_map_id` (default `null`). Environment variables from the Flex recipes: `UX_MAP_DSN`, and `GOOGLE_MAPS_API_KEY` for Google Maps.
- Stimulus controllers: `@symfony/ux-leaflet-map/map` (HTML name `symfony--ux-leaflet-map--map`) and `@symfony/ux-google-map/map` (HTML name `symfony--ux-google-map--map`). Both are lazy (`"fetch": "lazy"`) in `assets/controllers.json`. The JavaScript libraries are `leaflet` `^1.9.4` and `@googlemaps/js-api-loader` `^2.0.0`.
- JavaScript events: `ux:map:pre-connect`, `ux:map:connect`, and `ux:map:<type>:before-create` and `ux:map:<type>:after-create` for `marker`, `polygon`, `polyline`, `circle`, `rectangle` and `info-window`.
- Helpers: `Symfony\UX\Map\Cluster\GridClusteringAlgorithm` and `MortonClusteringAlgorithm` (interface `ClusteringAlgorithmInterface`, result `Cluster`); `Symfony\UX\Map\Distance\DistanceCalculator`, `DistanceUnit`, `HaversineDistanceCalculator`, `SphericalCosineDistanceCalculator` and `VincentyDistanceCalculator` (interface `DistanceCalculatorInterface`); `Symfony\UX\Map\Utils\CoordinateUtils`.
- Exceptions: most errors use `Symfony\UX\Map\Exception\InvalidArgumentException`, `LogicException` or `UnsupportedSchemeException`, which implement `Symfony\UX\Map\Exception\Exception`. Some errors use the global `\InvalidArgumentException` or `\LogicException`.
- Services: the bundle `Symfony\UX\Map\UXMapBundle` (configuration alias `ux_map`) registers no autowiring alias. Create maps with `new Map()`. The renderer service `ux_map.renderers` uses the `@internal` class `Renderers`.
- Test helpers: `Symfony\UX\Map\Test\RendererTestCase` tests a renderer with snapshots and needs `spatie/phpunit-snapshot-assertions`. `Symfony\UX\Map\Test\RendererFactoryTestCase` tests a renderer factory. The two bridges use them. The package has no assertions for application tests.

## Symbiotic packages

- [StimulusBundle](../packages/stimulus-bundle.md): UX Map requires it; the renderer builds the `<div>` attributes with `StimulusHelper`, and StimulusBundle loads the lazy bridge controller from `assets/controllers.json`.
- [UX Twig Component](../packages/ux-twig-component.md): it supplies the `<twig:ux:map />` tag; UX Map conflicts with UX Twig Component versions before 2.21.
- [UX Live Component](../packages/ux-live-component.md): `ComponentWithMapTrait` keeps the map in a LiveProp, and a live action changes the map without a page reload.
- [UX Icons](../packages/ux-icons.md): `Icon::ux('fa:map-marker')` renders a marker icon through UX Icons, so install `symfony/ux-icons` for this icon type.
- [AssetMapper](../packages/asset-mapper.md): the bundle adds its asset paths and the bridge asset paths, and Flex adds `leaflet` or `@googlemaps/js-api-loader` to `importmap.php`.
- [WebpackEncoreBundle](../packages/webpack-encore-bundle.md): with Webpack Encore, run `npm install --force`; if the Leaflet build cannot find `leaflet/dist/leaflet.min.css`, add an alias with `Encore.addAliases()`.
- [Symfony Flex](../packages/flex.md): the recipes register `UXMapBundle`, create `config/packages/ux_map.yaml` and add `UX_MAP_DSN` (and `GOOGLE_MAPS_API_KEY` for Google Maps) to `.env`.
- [TwigBundle](../packages/twig-bundle.md): TwigBundle collects the `twig.extension` and `twig.runtime` services that supply the `ux_map()` function.
- [ObjectMapper](../packages/object-mapper.md): its `#[Map]` attribute copies data between PHP objects; it does not draw geographic maps.

## Changed in UX 2.27 to 3.5

- 3.0 removed the `render_map()` Twig function. Use `ux_map()` or `<twig:ux:map />`.
- 3.0 removed the `title` argument of `Polygon`, `Polyline`, `Rectangle` and `Circle`. Use `infoWindow: new InfoWindow(content: '…')`.
- 3.0 removed the `rawOptions` property of the `ux:map:*:before-create` events. Use `bridgeOptions`.
- 3.0 (Google Maps bridge): the bridge uses `@googlemaps/js-api-loader` `^2.0`. The DSN option `version` is now `v`. 3.0 removed the DSN options `id`, `nonce`, `retries` and `url`, and added `authReferrerPolicy`, `mapIds`, `channel` and `solutionChannel`. If you use AssetMapper without Flex, run `bin/console importmap:require @googlemaps/js-api-loader@^2.0`.
- 3.0: the minimum versions are PHP 8.4 and Symfony 7.4.
- 3.5: `ux_map()` and `<twig:ux:map>` resolve attribute values with the `html_attr()` rules, and UX Map supports Twig 4. If your tests compare the map HTML, generate the expected HTML again.
- 2.27: in a Live Component, the `fitBoundsToMarkers` value that you set stays active. If the map must not fit the markers again after a change, call `$this->getMap()->fitBoundsToMarkers(false)` in the live action. The map then needs a `center()` and a `zoom()`.
- New since 2.27: `Circle` and `Rectangle` (2.27), `minZoom()` and `maxZoom()` (2.28), clusters (2.29), the `fitBoundsToMarkers` argument of `ux_map()` (2.31) and the `removeAll*()` methods (2.32).

## Status

- Stable. The docs state no experimental status. They say that the bundle aims to follow the Backward Compatibility promise of Symfony.
- The Google Maps renderer needs a Google Maps API key. The Leaflet renderer needs no key and loads OpenStreetMap tiles by default.
